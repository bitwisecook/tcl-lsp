# v2.1.16

**2.x alpha — pre-release channel.**

Another pre-release on the **2.x** line, where the ongoing Python → Rust
rewrite of tcl-lsp ships its alphas. It is opt-in: install it from the VS Code
Marketplace **pre-release** channel or the JetBrains Marketplace **eap**
channel, or download the pre-release VSIX / plugin / native binaries from this
GitHub release. The stable **1.x** line stays the default for everyone who has
not opted into pre-releases, and a `2.1.x` build never becomes the "latest"
GitHub release or the default Marketplace download.

This is a large release — 43 merged pull requests closing just over 100 issues.
Its dominant theme is **making the command registry the single source of truth**:
where the formatter, minifier, semantic tokens, folding, inlay hints, navigation
and the optimiser each used to match command *names* by hand, they now ask the
registry what a command actually *is*. That change is what makes a whole family
of long-standing bugs fall out at once — `::format` finally classifies like
`format`, a `rename`d or `interp alias`ed command formats and folds under the
grammar it really has, and a user `proc` that shadows a builtin correctly stops
inheriting one. On top of that sits a new head-identity resolver that follows
`namespace import`, static `rename` and `interp alias` chains across nine
separate consumers.

The second thread is **TclOO**. `oo::objdefine`, snit and itcl method bodies are
now analysed at all — previously they never became method units, so no CFG, no
SSA, no instance variables and no diagnostics of any kind ran inside them.
Cross-file metaclass-manufactured classes (`::tk::Megawidget create IconList …`)
are now modelled workspace-wide, list-slot definition words (`filter`,
`superclass`, `mixin`, `variable`) follow real `oo::Slot` append/replace
semantics rather than last-writer-wins, and per-object `oo::objdefine` state
finally has a home.

The third is **precision work on the read-before-set family**. A long run of
W210 false positives — braced data words, `foreach` value lists, opaque `switch`
arms, `dict update` pair locals, three-frame `uplevel` chains, out-parameters
filled by a helper in another file — is fixed by classifying *how* a use is
consumed instead of merely whether a `$name` appears in the text.

Rounding it out: namespace rename is now supported end to end, `package require`
sequencing now derives cross-file run order (704 provable edges over tcllib 2.0),
registry lifecycle metadata is unified behind `introduced`/`deprecated`/`retired`
with two new diagnostics, the BIG-IP report generator gained an offline security
posture tab, BPF-Tcl gained a kernel-loadable XDP/socket-filter target, and
diagnostics on large flat dispatch chains got roughly an order of magnitude
faster.

## Breaking Changes

- The four version-pinned dialect language ids were renamed from `tcl8.4`/`tcl8.5`/`tcl9.0`/`tcl9.1` to `tcl84`/`tcl85`/`tcl90`/`tcl91` (display names unchanged), because VS Code cannot carry configuration defaults for a dotted language id at all — it splits the id while building the defaults tree, throws, and drops every remaining override, ours and other extensions' alike. Dialect *names* are a separate namespace and keep their dots, and the server accepts both spellings as a `languageId`, so the other editor integrations are unaffected. These ids are picker-only — no file extension binds to them — so the only impact is a hand-pinned language mode, which falls back to plain `tcl` with dialect resolution intact. (#1122)
- **Formatting output changes by default.** Unique keyword abbreviations are expanded to their canonical spellings (`string le` → `string length`) and boolean-consuming words are normalised to `true`/`false`. Opt out with `tclLsp.format.expandAbbreviations: false`, or change the target pair with `tclLsp.format.booleanForm`. (#1232, #1233)
- `tclLsp.formatting.lineEnding` now defaults to `auto`, resolving the terminator from the document's own first line break rather than always emitting LF.
- `tclLsp.features.folding` now defaults to on and no longer inherits the editor's own `editor.folding` setting; only an explicit `false` disables the server's folding ranges. VS Code's sticky-scroll provider queries folding-range providers unconditionally and never reads `editor.folding`, so the old inheritance starved sticky scroll for users who simply had the folding UI switched off. (#1122)
- **Registry lifecycle metadata is no longer a boolean.** `min_version` / `max_version` / boolean-`deprecated` are replaced by `introduced` / `deprecated` / `retired` across every serialisation surface — CLI, MCP, snapshots, editor catalogues, and the Spec Studio draft/schema/render — with `null` meaning "never reached that state". There is no generic maximum version any more; an upper bound exists only as retirement metadata, and retirement is exclusive (`retired: 10.0.0` means already gone in 10.0.0). W139's message and semantics are corrected from the old inclusive "removed after". (#1210)
- **Two version-requirement verdicts changed**, now that requirements are decided exactly over a whole release line rather than against its first release: `9.0.1` against 8.6 was inert and is now a definite No (no 8.6.x reaches a 9.0 bound), and `8.6-8.6` — the range `package require -exact 8.6` builds — was Yes and is now inert, since 8.6 satisfies it but 8.6.14 does not. (#1126)
- **The minifier's compact tier no longer compacts array member keys**, and the default tier no longer performs `[subst $alias]` template deduplication. Both were semantics-destroying (see Bug Fixes). Output from those tiers is slightly larger than before; the default tier is now frame-transparent by contract, while the aggressive tier is documented as explicitly not. (#1192, #1194)
- **"Fix All Safe Issues" applies a narrower set of fixes**: only those individually classified as bulk-applicable. Notably W100 brace-wrapping and W110's `eq` rewrite are no longer applied unattended where they would change the number of substitution rounds or comparison semantics. (#1195)
- **The VS Code client no longer registers its own `synchronize.fileEvents` watchers**; file watching is entirely server-registered. This removes duplicate change notifications and fixes the client watchers' drift — they were missing `.exp` and `.apl`. (#1215)

## New Features

### Language and analysis

- **Namespace rename.** `prepare_rename` now offers a namespace's final segment instead of declining, and only that byte range is rewritten — which makes rooted and relative spellings fall out together: `namespace eval ::app::old`, a nested `namespace eval old`, and a call `old::p` from inside `::app` all move, while a bare `p` inside the namespace correctly gets no edit. Qualified variable occurrences, resolved call sites, `proc` and class declaration name words, and `namespace import`/`forget` patterns are rewritten; `namespace export` patterns are correctly left alone, since a `::`-qualified export is a hard Tcl error. The rename runs across every indexed document rather than an index-derived candidate set, because an unattributed embedded name puts nothing in any index table. Where coverage cannot be guaranteed it refuses with a specific reason: a computed namespace word that could spell this namespace, a rooted name sitting in an unattributed data word (a callback string, a dispatch-table literal), or a collision with an existing namespace. (#1114)
- **Cross-file metaclass-manufactured classes are modelled.** A `::tk::Megawidget create IconList FocusableWidget {…}` in a file that never mentions the metaclass's own definition previously recorded nothing at all — no class, no members, no navigation, an empty outline — because the class-factory walk was per-file and the call is shape-identical to `interp create`. Class factories are now derived once at the metaclass's own declaration (manufacturer word layout plus the prologue it splices, as a template over the creation call's arguments) and published workspace-wide through a salsa-backed factory index, so document symbols, go-to-definition, hover (full signature, methods and MRO), W123 and method go-to-definition behave identically to a literal `oo::class create` in another file. (#1276)
- **Cross-file run order is derived from `package require` sequencing**, not just from `source`. A `package require NAME` that returns proves the providing document's statements have all run — the only ordering fact available on package-structured code, where the sequencing `source [file join $dir x.tcl]` calls live inside a `pkgIndex.tcl` and fold to nothing. Measured over tcllib 2.0 and Tcl 9.0.4 this yields 704 provable package edges. The edge is deliberately one-sided (the provider has run *from the require onwards*, never "it has not run yet"), and the server abstains in three cases: a package two indexed documents provide (only `auto_path` order decides the winner), a package this workspace registers a `package ifneeded` script for (the script is what actually runs), and conditional or non-literal requires. (#1279)
- **Namespaces created only as implicit parents are navigable.** `namespace eval ::p::q::r {}` really creates `::p::q`; that is now answered with the covering prefix of the deepest written name — the sub-range spelling exactly that namespace, never the whole word — and hover words it "implicitly created by" rather than "declared by". This works across documents too, where the cross-document tier previously matched exact qualified names only and answered nothing when the sole creating block lived in a sibling file. Containment is segment-wise, so `::pq::r` correctly does not create `::p`. (#1113, #1246)
- **Head identity resolution across nine consumers.** A new resolver answers, per command head, what a command *is* rather than what it is spelled: `namespace import`, static `interp alias`, static `rename`, and a top-level `proc` that shadows a builtin are all resolved, and a head whose binding was provably taken over is marked rebound and gets no registry grammar at all. Chained bindings compose — `interp alias {} a {} format; rename a b` leaves `b` naming `format`, matching tclsh 8.6.16 and 9.0.4, while `proc format …; rename format myfmt` correctly leaves `myfmt` rebound rather than inheriting the builtin's grammar. `textDocument/declaration`, folding, the formatter, the minifier, inlay hints, the call-graph scan, parameter-trait inference and the iRules object-reference walker all consume it. (#1185, #1275)
- `callback`, `mymethod` and `classvariable` are now modelled as version-gated `::oo::Helpers` members. The registry carried only five of the seven members tclsh 9.0.4 lists, so a bare `callback` inside a TclOO method body drew `W123 Unknown command 'callback'` on every dialect. All three are now 9.0+ core commands, with `mymethod` and `classvariable` additionally available on 8.6/8.7 behind `package require ooutil`. (#1019)
- snit's `installhull ?using TYPE?` is modelled, binding the widget's implicit `hull` component — the one binding shape the handle descriptor could not express, since the bound name appears nowhere in the call. It is declared on the snit *widget* grammars only, because a plain `snit::type` has no hull. (#1185)
- A literal `foreach` member installer — `foreach m {alpha beta gamma} { method $m {args} {…} }` — now records its per-iteration member names, so those methods appear in the outline, hover, go-to-definition and completion. Their signatures are honestly marked computed, so arity checking abstains rather than inventing a parameter list. (#1277)
- Hovering a `method`, `classmethod` or `property` **at its own declaration** now renders. Previously only call sites, `link`-exposed barewords and the `constructor`/`destructor` keywords hovered, so hovering a method in a reopening `oo::define` block returned nothing — and so did hovering one in the class's own creation block. Hover reuses the same declaration disambiguation find-references uses, so the two cannot disagree about which declaration the cursor is on. (#1019)

### New diagnostics

- **W144** — a command, subcommand, option, iRules event or profile that is *deprecated* in the target release but still available is now reported distinctly, instead of being lumped in with "not introduced yet" (W135/W136) or "removed" (W139). (#1210)
- **W145** (ambiguous keyword abbreviation) — `string l` is a guaranteed runtime error because `l` prefixes both `last` and `length`. It previously fell into the generic unknown-subcommand path (W001), which guessed at an intended spelling; W145 now names the actual colliding candidates for both subcommand words and `-option` words, and offers one `RequiresReview` quick fix per candidate (never auto-applied by Fix All, because the tool cannot know which was meant). It abstains on strict tables, dynamic and `{*}`-expanded words, and ensembles the file configured with `namespace ensemble … -prefixes 0`. (#1234, #1231)
- **W315** ("this object definition cannot run") now covers `oo::objdefine` bodies, not just `oo::define`. Per-object member state is folded across every block for a receiver binding, so a retraction in a second block of what a first block declared no longer false-positives; retract-of-missing only reports when the name is per-object-declared nowhere in the document and the receiver's construction is in view, rename-onto-existing needs unconditional presence evidence, and rename-to-itself is an error against any table state. (#1170)
- **E001** now fires for a bare object-producing command substitution head invoked with no method word — `[Dog new]`, `[Dog create rex]`, `[make]`, rename/alias-reached constructors, and factory procs — matching tclsh 9.0.4, which fails all of these with `wrong # args: should be "::oo::ObjN method ?arg ...?"`. snit/itcl, external classes, dynamic heads and deleted classes abstain, and both E001 forms abstain inside a child interpreter's evaluation body where the class command does not exist in that interpreter's command table. (#1143, #1200)

### Formatter, minifier and refactorings

- The formatter **expands unique keyword abbreviations** to canonical spellings: `string le $s` → `string length $s`, `lsearch -noc` → `lsearch -nocase`. The rewrite goes through the same registry abbreviation resolver the analyser uses to understand the word, so the two can never disagree. Idempotent, and honoured by whole-document, range and on-save formatting. Ambiguous words (`string l`), unknown words, strict tables, `-prefixes 0` ensembles, dynamic and `{*}`-expanded words, braced/quoted data words, and command names are left byte-for-byte alone. (#1232, #1233)
- The formatter **normalises boolean word forms** — `yes`/`on`/`1`-style spellings — to one configured pair, but only at positions the registry proves are consumed through `Tcl_GetBooleanFromObj`. A value-definition site such as `set flag yes` keeps its bytes, because `$flag` may later be compared with `eq "yes"` or matched by a `switch` arm; a numeric-or-boolean position abstains, since `0`/`1` are also integers. (#1232, #1233, #1256, #1268, #1269)
- The formatter gained an **`auto` line-ending mode** (`tclLsp.formatting.lineEnding`), now the default, resolving the terminator from the document's own first line break. The CLI and MCP formatters resolve it identically, and code-action-inserted text (docstrings, extracted procs, `package require`, noqa comments) carries the document's terminator too.
- The minifier gained an aggressive-tier phase that **emits unique-prefix keyword abbreviations** — `string equal -nocase` → `string e -n` — computed from the registry rather than pattern-matched by hand. Two safety rules keep the rewrite observationally invisible: the emitted prefix must resolve to the same keyword in the target dialect's table *and* in every later core-Tcl table, and only dispatch-consumed subcommand and option words are abbreviated (boolean *values* deliberately are not, since `set flag true` is a value-definition site whose bytes may be observed). `tcl minify --aggressive --no-abbreviations` turns it off for eyeball-diffable output. A mixed corpus minified with the phase on runs byte-identical (stdout, stderr, exit status) under tclsh 8.6.16. (#1230)
- Refactorings that cannot preserve behaviour are now **greyed out with their reason** via LSP's `CodeAction.disabled.reason`, instead of silently vanishing from the menu — a missing entry could not previously be told apart from a broken feature. (#1199, #1201)

### Editor integration

- **Sticky scroll** now works for scripts whose top level is control flow and therefore have no outline symbol to pin: the folding model carries them, and per-arm `switch` folds mean a viewport inside an arm pins the arm rather than the `switch` header. (#1122, #1216)
- New `tcl-lsp.setSessionDialectOverride` command gives the chat commands' dialect pin its own server-side slot. Previously they pinned a dialect by pushing `didChangeConfiguration`, which the next config pull re-applied away — the pin's lifetime was "until anything touches settings". The override now survives every config pull, is reported by `getEffectiveConfig`, and clearing it needs no saved previous value. Precedence is unchanged: same tier as the configured default, below a language id, a BIG-IP basename and a folder override. (#1217)
- Added a `tcl86` version-pinned language id ("Tcl 8.6") so Tcl 8.6 can be hand-picked from the language mode picker like its siblings, with grammar, semantic-token bindings, sticky-scroll defaults and dialect mapping all mirrored. Previously every version *except* 8.6 could be pinned per file, which broke down the moment a workspace's default dialect was something other than 8.6.
- New `tclLsp.packages.preferLatest` setting (`[packages] preferLatest` in the INI layers) declares the interpreter's *starting* `package prefer` mode, instead of the resolver hard-coding `stable`. That is the honest carrier: `TCL_PKG_PREFER_LATEST`, and on 9.0+ an unstable build of Tcl itself, belong to the interpreter the user runs, not to the source tree or the language server's own environment. (#1253)
- Completion now offers the boolean keyword vocabulary at a boolean-valued option position, where it previously offered nothing, and hover names the accepted vocabulary. Driven by new first-class `ArgRole::Boolean` / `ArgRole::NumericOrBoolean` registry facts, populated across 41 option declarations including `fconfigure -blocking`, `clock -gmt` and `socket -reuseaddr`. (#1256)
- The compiler explorer toolbar gained a Compile button (plus Ctrl/Cmd+Enter) that forces a recompile of unchanged source. (#1183)

### BIG-IP and BPF-Tcl

- Added a **Security tab** to the BIG-IP HTML report generator with six offline, high-confidence posture checks: BIGIP-SEC-001 (factory `root/default` and `admin/admin` credentials, verified against the stored password hash — SHA-512/SHA-256-crypt and MD5-crypt implemented in-process, with unsupported schemes failing closed as "could not inspect" rather than guessed), BIGIP-SEC-002 (default/weak SNMP community strings, severity raised for read-write), BIGIP-SEC-003 (disabled or weak password-policy enforcement), BIGIP-SEC-004 (plaintext credential-bearing fields), BIGIP-SEC-005 (unprotected private-key material in a UCS filestore), and BIGIP-SEC-006 (non-administrative accounts with full bash shell access). Findings carry a stable id, severity and a four-way status (confirmed / clear / not applicable / could not inspect) and never include a password, hash, salt, master key or other decrypted secret. Available in both the native CLI and the in-browser WASM generator. (#1211)
- Added **BIG-IP 21.1 support**: the iRules command registry, report defaults and lifecycle data now cover 21.1, and the selected BIG-IP version propagates through incremental analysis. (#1206)
- Added a **kernel-loadable BPF-Tcl XDP target**. BPF-Tcl programs compile to real Linux-kernel eBPF objects for `xdp_md` (XDP) and `__sk_buff` (socket filter) contexts, via `--target kernel-socket`. Every packet load emits a dominating `data + off + width <= data_end` proof using the shared-id direct-packet-access idiom, short packets take the program type's drop verdict, and the ELF writer emits BTF-defined `.maps`, `.BTF` and `.rel<prog>` sections so `readelf`, `llvm-objdump` and `bpftool` all accept the object. The rbpf userspace simulator remains the deterministic default. (#1203, #1205)
- BPF-Tcl gained a **registry-described typed core language**: every BPF command carries a `BpfOpSpec` descriptor (core op or framework declaration, scalar width, packet-load width, map role, verdict family, effect classification), the `when EVENT` event space is registry data, and lowering dispatches on descriptors rather than command names. `Inst::Load` carries a constant range, width, byte order and an explicit out-of-bounds action; maps carry a typed schema (kind, key/value size, capacity, concurrency) with `map_has` distinguishing a missing key from a stored zero; full 64-bit constants materialise via `lddw`; and liveness-based slot allocation re-colours disjoint live ranges and reports stack pressure with source context. (#1202)
- BPF-Tcl gained **typed event schemas and a handler/loader layer**. `BpfEventSpec` carries a typed context struct, permitted-capability set, verdict algebra with a default verdict, attach parameter schema, kernel/BTF/`bpf_link` requirements and codegen readiness. `TC_INGRESS`, `TC_EGRESS`, `CGROUP_CONNECT4` and `CGROUP_BIND4` are schema-described (a handler for one gets a precise "codegen pending" diagnostic rather than "unknown event"), a non-terminal `next` verdict allows explicit continuation, handler composition runs lower priority first with terminal verdicts stopping the chain, and a versioned ring-buffer record ABI with loss accounting feeds a structured JSON/text consumer. New `bpf-tcl plan` dry-run subcommand; `check` prints resolved event contracts and composition chains. (#1204)

## Improvements

### Registry-driven grammar

- **Semantic tokens and format-specifier inlay hints read registry grammar** instead of hard-coded command spellings, so the `::`-qualified forms `::format {%08x} 42`, `::foreach {a b} {1 2} {…}`, `::upvar 1 s l`, `::oo::define C method m …`, `::scan`, `::clock`, `::binary` and `::regsub` classify identically to their bare forms — previously all of them silently lost their richer classification. `regsub` gained a proper pattern role so the regex pass stops re-parsing its switches, and correctly declares no replacement template under `-command`, where that word is a callback prefix. A same-named user proc (`ns::format`) does not inherit the grammar, and a `{*}`-expanded dynamic head gets none. (#1185)
- Loop-variable-list and snit typemethod classification is likewise registry-driven: `dict for`/`dict map`/`array for`/`foreach`/`lmap` variable and collection layouts come from declared roles and the collection's declared dict type hint rather than a keyword test, and snit's built-in typemethods come from the definer grammar (with `create` correctly excluded, since `Type create inst` is a construction). (#1185)
- **Registry-driven formatting for `if`/`for`/`try`.** Layout previously keyed on literal command names and scanned every argument's *text* for `then`/`elseif`/`else` and `on`/`trap`/`finally`, with two visible consequences: the explicitly global spellings `::if`, `::for` and `::try` formatted differently from their bare forms even though C Tcl resolves them to the same command, and keywords were matched by value rather than position, so `if {1} {a} else then` retyped the trailing `then` (which is really the else-branch body) as a keyword. Keywords now come from the registry's structural `Keyword` role, and block-vs-inline layout is a new registry fact so `for`'s `start` and `next` scripts format inline. A namespaced user proc such as `ns::if` correctly does not inherit the grammar. (#1186)
- **Formatting lays a command out under the grammar of the command it *is*.** A document doing `rename format origfmt` or `interp alias {} myfmt {} format` previously had its calls formatted under a grammar they no longer had; body-argument, expression-argument, keyword-rewrite, traits and clause-list decisions all read the resolved identity now. Range formatting builds the identity map from the whole document rather than the selected slice, so a `rename` above the selection still governs it. (#1275)
- Folding no longer loses folds on an aliased or renamed body-bearing command, and no longer folds a builtin that a user `proc` has shadowed under a grammar it no longer has. A member sub-keyword such as `method` inside a class body deliberately keeps its written spelling, because that is lexical rather than a command binding. (#1275)
- `rename` and `interp alias` are followed by the interprocedural call-graph scan, so a `catch`-bodied call reached through a proven alias contributes its reachability edge (which previously made a live procedure look dead to O124), and a `puts` reached through one no longer counts as an unknown call permanently sinking the caller's purity. Parameter-trait inference resolves through the same map, so a proc body calling `eval` through a proven alias records the `Eval` trait, and one calling an `eval` that a top-level `proc eval` has taken over no longer records a trait it should not. (#1275)
- **The registry models keyword abbreviations**, so every consumer reads prefix spellings the way `Tcl_GetIndexFromObj` does. The prefix map is derived from the table rather than hand-authored, exposed through one three-valued resolver (unique / ambiguous / unknown), and honours a per-table `prefix_matching` flag, per-subcommand minimum abbreviations, and a call site the analyser saw configured with `namespace ensemble … -prefixes 0`. Resolution over a version range only calls a word unique when every release agrees — `string c` was `compare` in 8.5 but is ambiguous once 8.6.2 added `cat`. Booleans are a built-in table reproducing `Tcl_GetBoolean` exactly, including `o` being the one ambiguous boolean prefix. (#1231)
- The formatter knows the document's dialect and target version range, so abbreviation expansion only fires where the prefix resolves to the same keyword in the document's own release *and* every later release in range. `info e` is `info exists` in 8.4 but ambiguous once `info errorstack` lands in 9.0, and `trace vd` names a subcommand 9.0 removes outright — both are now left alone rather than expanded into something a newer interpreter would reject. (#1257)
- **Registry lifecycle metadata is unified** into one `introduced`/`deprecated`/`retired` model carried by commands, subcommands, options, versioned argument values, iRules events and profiles. Completion omits retired iRules events and labels deprecated ones; IRULE1002 reports an exclusive range and IRULE1003 names the deprecating release. Real lifecycle data was seeded: the classic pre-10.0 XML parser events (9.0.3, deprecated and retired at 10.0.0), `XML_CONTENT_BASED_ROUTING` (10.2.0, not retired), the `AUTH_*` family (9.0.0, deprecated 9.4.0, still present), `QOE_PARSE_DONE` (11.5.0, deprecated 15.0.0), `ASM_REQUEST_VIOLATION`, `HTTP_CLASS_*`, and the AIMCP profile (21.1.0). (#1210)
- `configure`/`cget` resolution is decided by a registry trait (`CONFIGURES_BY_PROPERTY`, declared on `oo::configurable` alone) rather than by comparing the metaclass name to the string `oo::configurable`. A metaclass the registry does not model answers false, so an unknown factory is never treated as configurable — verified on tclsh 9.0.4, where an `oo::configurable` instance answers `[$pt configure]` with its property dict while an `oo::class` instance answers `unknown method "configure"`. (#1275)
- Collection element-class inference reads `ReturnElements::ElementOf` through the registry instead of matching `dict get`/`lindex` by name, so the fully-qualified spellings resolve too. (#1185)
- A registry sweep now asserts that no repeated-tail position declared with `conditional_binding: true` — a local bound only when a runtime data condition holds, such as `dict update`'s pair locals — ever carries `ArgRole::VarWrite`, the role every generic write-detection site queries when deciding a position defines a variable unconditionally. This is the general guard against the `dict update` value-variable W210 false-positive family. (#1278, #1247)
- The Spec Studio's field coverage is gated at compile time: each covered type has an exhaustive destructuring with no rest pattern, so a newly added `CommandSpec` field fails the build naming itself rather than silently going missing from the web UI (21 types covered). The plain-data descriptors now genuinely round-trip as full struct literals instead of seeding a `TODO` for the author to retype. (#1185)

### TclOO and the object model

- **`oo::objdefine`, snit and itcl method bodies are now analysed.** Lowering's OO extraction literal-matched only `oo::class create` and `oo::define`, so those bodies never became method units: no per-method CFG or SSA, no instance variables, and no diagnostics of any kind inside them — whole method bodies were invisible to every analysis. Definer calls are now classified from registry specs covering metaclasses, `oo::objdefine`, and the shared `DEFINER TARGET {body}` shape used by `oo::define`, `snit::type`/`widget`/`widgetadaptor` and `itcl::class`, including wrapper prefixes (itcl's `public`/`protected`/`private`, TclOO's `self`/`private`) and wrapper block forms. snit and itcl method units carry the grammar's implicit member-body variables (`self`, `selfns`, `type`, `options`, `win`/`hull` for widgets, itcl's `this`) so the newly-running W-family does not flood false positives. (#1172)
- **TclOO list-slot definition words follow real `oo::Slot` semantics.** `filter`, `superclass`, `mixin` and `variable` were modelled as last-writer-wins assignment; they are now slot operations, so incremental `filter a; filter b` declarations show both and `superclass -append` idioms work. Explicit `-set`/`-append`/`-appendifnew`/`-prepend`/`-remove`/`-clear` operations fold, with per-slot defaults and dedup rules pinned against C Tcl (identical in 9.0.4 and 8.6.16): `filter` and `variable` append, `variable` dedups, `superclass` and `mixin` replace. (#1169)
- **Per-object `oo::objdefine` export/unexport reaches every consumer**, matching real dispatch order: go-to-definition and hover suppress masked names (including at the server's cross-file tier, where an in-document definitive empty was previously indistinguishable from "no local answer") and resolve per-object-exported ones, and completion offers per-object members first, masks unexported names, and revives per-object-exported class members. (#1170, #1119)
- **Class-side dispatch suppression reaches the declaring document.** A cross-file `self unexport Cm` or `self deletemethod Cm` suppressed `C Cm` for every document *except* the one declaring the class, because definition and hover answer from the in-document provider before the workspace chain runs. Both tiers now share one decision function; it abstains for a class the index holds no record of and for a hierarchy the shared linearisation declines, and instance-side dispatches are deliberately not gated so per-object override layering is preserved. (#1168)
- **Cross-file `renamemethod` inside an `oo::define` stub is treated as a move, not a deletion.** The stub owns no method definition to move (params, body and visibility live in the defining file), so the member previously vanished from the workspace tier entirely instead of reappearing under its new name. The arrival name and span are now recorded and joined in the shared dispatch-chain fold, with visibility travelling with the body rather than the new name's leading-capital default, so rename and find-references seed from the new name. A plain `deletemethod` and a computed destination (`renamemethod old $new`) correctly record no arrival. (#1167)
- `workspace/symbol` no longer offers the pre-rename member name after a cross-file `renamemethod`: enumeration reads the same effective member set the dispatch chain resolves through, with the arrived member located at the arrival word in the retracting document — the same site go-to-definition on the new name answers with. The retraction lookup is built once per query rather than rescanned per declared member, because the naive fold is quadratic in the workspace's class count on a path that runs per keystroke. (#1263)
- **Cross-file method rename covers documents that merely *receive* an instance** — through a global another file fills in, a dict entry, a callback registered elsewhere, or a proc parameter fed from another file. Both legs previously required a document to invoke a family constructor in its own text, so such a consumer appeared in no index table and was neither rewritten (a missed edit, giving a runtime `unknown method` after the rename) nor scanned by the safety gate. The rename leg now covers every indexed document, so the gate either refuses on the untracked receiver or the collector types it through the workspace class oracle and rewrites it. Find All References keeps the narrower constructor-site set on purpose — it is an interactive query whose worst outcome is a missing result, and widening it would re-analyse the whole workspace on every invocation. (#1099)
- **Find References, Rename, code lens, go-to-definition, go-to-type-definition, hover and completion all consult the compiler's interprocedural object-type lattice** through one accessor pair, rather than the weaker `instance_classes` map alone, so a receiver typed only through the lattice's scope-keyed bindings now resolves for navigation, reference counting and rename edits. Multi-class bindings deliberately abstain — every one of these consumers edits or navigates, so a guess would be a wrong edit rather than a missed one — and a genuinely untracked receiver still refuses the rename. (#994)
- The object-type lattice gained a **method-return VTA edge**: `set b [$a make]` now types `b` when the receiver's classes are tracked and the declared `::Class::make`'s own inferred return type names an object class. As a consequence a factory-returned handle carries its class, so an unknown method call on it is now reported as W308 where it was previously silent, and a dispatch that hover/definition can resolve no longer draws the W307 abstention warning. (#1143, #1200)
- **The SCCP method-dispatch propagation barrier is per-method rather than a module-wide switch.** Previously a single `upvar`-reaching or redefined method — the ubiquitous classvar helper idiom — disabled method-local optimisation for every method in the module. Classes now group into hierarchy components derived from `superclass`/`mixin` relations, each method's dispatch surface is classified from its statements (including transitively through the proc call graph), and a method is barred only if a tainted component is actually reachable. A method that never dispatches is never barred. (#1164)
- **Redefined TclOO method bodies are retained rather than discarded**, so a redefinition whose bodies are all caller-frame-clean no longer disables method-local propagation module-wide, and O126 method purity joins over every retained body (pure only when all bodies are, constant-return only when every body's exits agree) instead of forcing impure. Members with dynamic names or dynamic bodies, and dynamic class words on `oo::class`/`oo::define`, correctly widen the barrier, since a body that was never readable cannot be scanned. (#1166)

### Navigation, references and rename

- **Every provider resolves a call with the same whole-program view of `namespace export`.** A whole-program export oracle is threaded through inlay hints, signature help, all four call-hierarchy passes, code actions, the inline-proc refactor, document highlights, the code-lens reference count, find-references and rename — each of which previously resolved with a document-only view. The in-document `namespace import -force` shadow gate becomes three-valued, so a call a live `-force` import shadows resolves the same way on every surface, instead of go-to-definition refusing an answer the neighbouring surfaces still gave. (#1116)
- **Import lifecycle events are ordered across files** through a source-graph run order: each event's position is lifted to its root-ward path of source-statement offsets, and two events reduce to positions in their deepest common document, so the ordering gate and the conflict rule are answered by one projection and cannot drift apart. (#1272, #1104)
- **Go-to-definition and hover agree with the analyser about what a span names.** The "otherwise it is a call" fallback previously handed whatever word a pure text scan returned straight to proc resolution; it is now gated on the cursor's word actually occupying its enclosing command's head position, asked of the analyser's recorded invocation set, so an ordinary argument that happens to share a proc's name abstains instead of resolving onto it. An already-resolved *indirect* head (`set ns ::tc; ${ns}::setdef`) is preferred over the bareword lookup, since the span carries no written command name and the bareword path could only ever reach a same-named decoy. (#1137, #1133)
- Hover, go-to-definition and find-references answer for **caller-frame names the call site never spells**: each proc's literal `upvar 1 name name` targets are recorded and answered with the creating *call* as the binding site, and a literal binding never claims the bareword command head so that keeps navigating as the command. (#1139)
- Cross-file navigation reaches `::oo::Helpers` procs declared in another file: a TclOO member body's implicit `namespace path` is registry data folded into each invocation's resolution candidates ahead of the unspellable object namespace. (#1137)
- **Find References reports variable reads through registry `ArgRole::VarRead` name words**, not just `$name` and the bare `set name` form. A cursor on the name word in `puts [set m]` or `info exists m` previously resolved nothing, and every such site was under-reported. A braced word keeps its literal-name meaning: `[set {$n}]` reads the cell actually called `$n`, never `n`. (#1108)
- `${...}` variable parsing follows C Tcl 9's `Tcl_ParseVarName` — matching brace, with a backslash consuming the next byte — instead of stopping at the first `}`. (#1109)
- **List-built script arguments navigate and highlight.** `uplevel #0 [list upvar #0 ::tk::Priv.$disp ::tk::Priv]` and `namespace eval :: [list source [file join $::tk_library $file.tcl]]` each evaluate exactly one deterministic command, but every pass keyed on a literal `{...}` body used to skip them; a shared predicate now drives body analysis, `uplevel` handling and semantic-token overrides together, so `::tk::Priv` gets the same token classification as a plain `variable ::tk::Priv` declaration. The predicate abstains on a dynamic head, a multi-command substitution, or a non-`list` builder. (#1138)
- **Navigation resolves through constant command substitutions**: `set ns [namespace qualifiers ::tc::X]` followed by `${ns}::setdef …` resolves, as does the `[self class]` variant inside instance-side TclOO methods, with foldability decided entirely from registry `const_fold`/`const_fold_versioned`/`oo_context_facts` data rather than a command-name list. Trust comes from a whole-module command-mutation scan, so a `rename` appearing later in the file correctly disables the fold. SCCP's value lattice consults the same fold engine, so multi-statement chains such as `set base [self class]; set ns [namespace qualifiers $base]` close under the ordinary monotone fixpoint. (#1132, #1134)
- Literal `namespace path {…}` entries are rewritten by the namespace rename tier instead of triggering a blanket refusal; only a path word built from a run-time value (`namespace path $paths`, `namespace path "$ns ::a"`) still refuses, and that abstention is now an explicit recorded fact rather than a silent absence. (#1261)
- `documentSymbol` no longer contradicts hover: a qualified `proc pix::svg::parse` written outside any `namespace eval` block landed at top level in the outline while hover said `::pix::svg::parse`; namespace-level procs are now homed under the namespace their qualified name spells. A namespace the document never opens leaves the symbol where it was written, and a proc nested in another proc's body is never re-homed. (#1140)
- Picking a `namespace eval` in the outline no longer selects the entire block: namespace symbols report the name word as their `selectionRange`, with `range` widened to cover name plus body so the LSP containment invariant still holds. (#1218)

### Packages and imports

- The package resolver **tracks `package prefer latest`**. A raise is recorded and derived at each `package require`'s own offset through the shared in-effect order rule, so a top-level raise reaches a require in any body of the file while a raise written *below* a top-level require does not. `package prefer stable` needs no event log — it is a no-op from the default and silently ineffective after a raise (8.6.14 returns `latest` with no error) — so the presence of a raise is the whole state. Conditional raises abstain toward the interpreter default. (#1126)
- The `package prefer latest` latch **crosses the `source` graph**: `source CHILD` loads the whole child at that statement, so everything the parent already ran is in force for it and nothing it runs afterwards is. Unconditional raises are indexed and the crossing is answered over the same graph the W120 requires-inheritance walk uses. (#1253)
- When two `package ifneeded` registrations compare equal, the resolver returns the **union** of their files instead of one arbitrary set. Which registration survives is `glob` order — i.e. filesystem order — and therefore unpinnable, so naming every file that may hold the package's definitions beats betting on it. (#1126)
- W123's cross-file rules now have three tiers rather than two, and the `tcl::mathfunc` tier is **on by default**. `expr {Pi()}` in one file no longer draws "Unknown command 'Pi'; did you mean 'ni'?" when `::tcl::mathfunc::Pi` is injected by a sibling file — `::tcl::mathfunc::X` is one interpreter-wide slot the language owns, so a workspace that defines it defines the one `X` every `expr` in it can call. The broader bare-tail match over the whole workspace stays behind `crossFileResolution`: measured over tcllib 2.0 (790 files, 450 W123s) it silences 396, of which 197 are justified by no resolution candidate at the call site, so it is not defensible as a default. The workspace name set is only built when it can change a verdict, so a document with neither an `expr` math-function call site nor the project toggle pays exactly what it did before. (#1019)

### Performance

- **Diagnostics on large flat dispatch chains are dramatically faster.** Shimmer loop detection replaced a per-block forward BFS (plus a predecessor-rebuilding back-BFS per cycle block, run once per function by four separate passes) with a single iterative Tarjan SCC pass shared between the sub-passes. On a proc of N flat `if {$kind eq "kN"} { return … }` branches, debug `tcl diag` went from 2.0 s to 0.7 s at N=250, 6.0 s to 1.4 s at N=500, 21.3 s to 3.1 s at N=1000, and 81.6 s to 8.3 s at N=2000. (#1240)
- GVN loop-invariant detection no longer walks the immediate-dominator chain per query: `dominates(a, b)` is an O(1) interval-nesting test against a dense dominator-tree pre-order numbering, removing the quadratic term — per-doubling growth on the flat-branch benchmark fell from ~2.5× to ~1.95× (4.27 s to 2.65 s at 2000 branches). (#1250)
- Taint propagation builds its CFG-derived predecessor map and reverse-postorder block order once per function instead of on every call. Summary inference propagates once for the baseline plus once per (parameter, basis) scenario across 15 bases, and re-infers whenever a callee's summary moves, so those O(V+E) maps were previously rebuilt dozens of times per function under randomised `BlockId` hashing. Combined with the dominator work, the 2000-branch case went from 4.27 s to 2.15 s. (#1251)
- Interprocedural taint summarisation prunes dataflow solves whose results are provably already known — a procedure whose executable returns are all value-less or substitution-free returns clean for any map (0 solves instead of 1 + 15P), and seeding a parameter the body never reads leaves the map bit-identical to the base run. Measured on `practcl.tcl` (8,463 lines, 116 functions): the taint solve fell from 211.5 ms to 143.4 ms and total `run_all_checks` from 260.1 ms to 155.9 ms. Every summary stays bit-identical to the unpruned one, verified by a differential test across the TP/FP/TN/FN matrix. The solver's two prunes, lost during an earlier rebase, are also restored — the mainline had reverted to 1 + 15P whole-CFG solves per procedure. (#1187)
- **Document snapshots are shared rather than deep-copied per request.** `DocumentState::text` is an `Arc<str>` and the line index's backing store an `Arc<[u32]>`, so each of the ~55 snapshot sites is two reference-count bumps instead of a full copy of the document plus four bytes per line. On a 1.3 MB / 85,040-line file a snapshot previously copied ~1.58 MiB and now copies nothing, turning `O(R × (B + 4L))` live bytes under `R` concurrent requests into `O(B + 4L + R)`. (#1184)
- **Typing in a document containing the words `package`, `require` and `Tk` anywhere** — including in comments, strings and generated data — no longer forces a whole-file re-analysis on every keystroke. Tk activation is decided from the `tk` dialect (short-circuited at entry) and from a `package require Tk` recorded by the registry's own PackageRequire hook, so `-exact`, version constraints, line continuations, and a require nested in a `namespace eval`/`if`/proc body all fall out of the ordinary walk. Measured on tcllib 2.0 (882 documents, 460,103 lines): documents claimed as Tk-active fell from 33 files / 127,247 lines / 4,908 ms to 9 / 4,160 / 343 ms. A new 256 KiB oversized-body guard hands generated single-body files back to the whole-file walk, where isolated-body analysis is a large pessimisation. (#1188)
- **Rapid settings changes no longer stall the server.** Every `workspace/didChangeConfiguration` previously ran a full config pull (one unscoped `workspace/configuration` request plus one scoped batch per folder) followed by a full re-analysis of every open buffer, with no coalescing — a settings-editor burst of 16 notifications produced 32 pull batches and 16 re-analyses. Reloads are now leader-and-dirty-flag coalesced behind a 150 ms window, with the leader looping so a notification arriving mid-run still gets its own complete pass. One-shot events (`initialized`, the `.tcl-lsp.ini` watcher, workspace-folder changes) keep the undebounced path. (#1213)
- The per-call import walk in the run-order machinery allocates nothing, and an order with no package edge costs a single `is_empty` test. (#1279)

### Server and editor integration

- **Server-constructed and client-sent URIs share one canonical form**, so cross-file features stop seeing one file as two. The document store keys on the URI the client sent, but the workspace scan, the `source`/autoload cross-file resolver and the entry-point resolver each constructed URIs with no shared canonicalisation — and where the spellings differed, find-references, workspace symbols and rename all mis-keyed. The canonicalisation is purely syntactic and RFC 3986 §6.2.2-defined: percent-escape hex pinned upper-case and a Windows drive letter pinned lower-case, which is the exact point where the server's `from_file_path` (upper-cases) and vscode-uri's `URI.file()` (lower-cases) disagreed and made a scanned file and the same file open in the editor look like two documents on Windows. The rest of the path is deliberately not case-folded. (#1214)
- **Clients that send folder URIs with raw spaces** — as some JetBrains- and Neovim-style clients do — can now start a session at all. Such a URI is not a valid URI, failed deserialisation, and took the entire `initialize` request down with it, so the session never started. The transport shim now repairs it (percent-encoding the characters a URI may not carry raw, preserving existing escapes) and normalises it. Well-formed URIs pass through byte-for-byte, so this is inert for VS Code. (#1214)
- **File watching is case-insensitive.** The `workspace/didChangeWatchedFiles` registration used a single-cased `**/*.{tcl,...}` glob, and VS Code matches watcher globs case-sensitively on Linux, so external changes to an `UPPER.TCL` produced no watch event at all. The glob now folds case per character (`[tT][cC][lL]`), staying one precise registration rather than a broad `**/*` watch, and incoming events are additionally filtered through the same case-folded `is_tcl_source` predicate the workspace scan uses. The server also registers `**/.tcl-lsp.ini` itself. (#1215)
- **The VS Code `workspaceContains` activation glob is generated from the extension registry.** It was hand-written, named only nine of the twelve indexed extensions (`impl`, `exp`, `apl` missing) and was single-cased, so a workspace of `UPPER.TCL` files did not auto-activate — meaning no index and no workspace symbols until a file was opened. The extension list now lives once in the registry, shared by the server's watcher glob and the CLI's source suffixes (the CLI copy had also drifted by `exp`/`apl`), and the manifest is regenerated from it under a drift gate. (#1242)
- **`switch` bodies fold per arm.** A clause-list command's trailing braced word (`switch`'s `{pat body …}`, Expect's `expect {…}`) carries a body role but is a *list* of pattern/body pairs, not a script; re-segmenting it read each pair as one bogus command, so no arm folded and nothing inside an arm was reachable — only the outer block folded. The fold walk now splits the clause list with the shared Tcl list grammar and folds and recurses into each arm body. The three walkers that each located the clause list with their own slightly different option-skip loop (semantic tokens, the reference scanner, the fold walk) now share one function. (#1216)
- `documentLink` no longer emits bogus `file://` targets. A `source` argument whose reconstructed text still carried `$` or `[` was treated as a literal path and percent-encoded the raw Tcl into a nonsense URI; it now resolves through the source graph's own auto-path evaluator with single-`set` copy propagation for the `set dir [file dirname [info script]]` idiom, with the document's own path supplied so `[info script]` resolves, and emits nothing when it cannot resolve. (#1140)
- **Incremental (per-item) analysis is byte-identical to whole-file analysis** across the whole corpus gate — 0/895 divergences on the tcllib and Tcl-library trees, and 0 findings over 150 files × 4800 edited states, down from 58 findings. The fixes restored, among others, missing W001 widget-subcommand diagnostics, W103/W300 message divergences, missing existence-probed ensemble subcommand invocations, missing `$cmd` const-dispatch and `$class` instance sites, W123 alias/rename facts recorded from inside proc bodies, and phantom or missing `instance_classes` entries. A non-ignored parity test now runs the byte-identity contract over the checked-in samples corpus on every ordinary test run so the gate cannot rot unnoticed. (#1123)
- The compiler explorer's dialect dropdown is populated from the worker's `ready` message rather than showing only a hard-coded `tcl8.6` until a compile happened to land, and pane renderers run in isolation: a failure is reported inside its own pane, `renderAll` never throws, the spinner always clears in a `finally`, and every contract list is treated as optional so a future field gap degrades instead of blanking the view. A compile requested before the WASM module finished loading is retried rather than lost. (#1183)
- The `lsp_client.py` harness gained a repeatable `--also-open FILE` flag for multi-file scenarios, and its workspace-scan timeout default was raised from 15 s to 30 s after measuring the worst case (2000 files) at ~12.5 s unloaded debug and ~15.2 s under CPU contention — the old default left no headroom once loaded. (#1111)

## Bug Fixes

### Read-before-set and dataflow precision

- **`puts {set y 1; return $y}` no longer draws a false W210.** SSA scanned every non-body argument word's de-braced text and harvested `$y` from a braced data word, even though Tcl substitutes nothing inside `{…}`. Uses are now *classified* rather than present-or-absent: a braced word at a body or expression position stays a definite read (so `expr {$a + $b}` and `if {$c} …` are unaffected), a braced word at a position the registry describes as data (`puts {$y}`, `string match {$pat*} …`, `lsort -command {cmp $x}`) becomes quoted, and W210/W213 skip quoted uses while liveness and dead-store analysis keep honouring every use — so `set a(k) 1; puts {$a(k)}` still does not draw W211/W220. A braced `return {$y}` is classified the same way. (#1142, #1237)
- A braced word at a command the registry does not describe at all is treated as a may-run script rather than data, so genuine true positives survive: a wrapper proc that hands its braced argument to an `uplevel`-ing worker really does evaluate it in this frame, and tclsh really does error on the unset name. The exception is a word that `set`s the name itself, which makes it that script's own local whichever frame it runs in. (#1142, #1237)
- **A brace-quoted `foreach`/`lmap`/`dict for` value word no longer draws a false W210.** The loop iterator recorded only the word's content with no record of its quoting, so the CFG's synthetic loop-header call harvested `$b` out of `foreach n {a $b c} {…}` as a variable read — where tclsh 8.6.14 simply prints `a`, `$b`, `c` with `b` undefined throughout. The inliner also no longer rewrites variable spellings inside a braced value word. (#1260)
- **Brace-quoted data words inside a non-lowered `switch` arm no longer draw a false W210.** A non-lowered switch keeps its arms in one opaque statement and the SSA read walk returned a bare name set, collapsing every quoted word into the substituted bucket; the classification is now threaded through the whole walk. Arm patterns had the same lowered-versus-opaque disagreement and are fixed via the existing braced-patterns fact. (#1266, #1247)
- **`dict update` pair locals are no longer modelled as unconditional definitions.** That defeated the key-aware read-before-set suppression and would have hidden the genuine absent-key warning, since tclsh leaves the value variable unset when the key is missing — the binding is conditional. (#1107, #1247)
- **W210 no longer false-fires on a three-frame `uplevel` chain.** A proc whose `upvar`/`uplevel` level lands *past* its own caller writes the frame of whoever called its caller, so the effect travels one hop further along an ordinary call than a level-1 effect does; the summary widened such a level and stopped there, so the outermost frame drew a false W210. A literal `uplevel N {body}` with N ≥ 2 (or an absolute `#N`, N > 0) was silently dropped entirely and now widens the same way. Level 1 stays non-transitive, as its own tclsh transcript requires. (#1019)
- **W210 no longer false-fires on an out-parameter filled by a helper defined in another file.** A call to a command this unit can resolve neither in the registry nor to a definition of its own is opaque, so the literal name-shaped words it spells stop being provably unset in that frame — decided per name and per frame, so an unrelated local, a substituted argument and a registry command all keep reporting. (#1019)
- **W212 no longer fires on `uplevel 1 [list set $var 99]`.** `$var` is substituted in the *building* frame, so the script that finally runs already carries the literal name — the substitution is the idiom, not a name/value confusion. The directly-written `set $var 99` spelling still fires. (#1019)
- **W143's `::oo::Helpers` additions introduce no new false positive** on code that installs the documented "TclOO Tricks" wiki helper `proc ::oo::Helpers::callback` behind a `package vcompare` guard. The user-resolution shadow check qualified a bare word against the call-site namespace and global only, so a member body's unconditional `::oo::Helpers` namespace path was invisible to it; it now takes the implicit path from the registry's TclOO member-body namespace path, so the W002 "disabled in the active dialect profile", arity and W143 flushes share the fix. (#1019)
- **W308 "Unknown method" no longer fires on a class that builds its public surface reflectively.** ticklecharts' `chart3D` installs its members via `constructor {*}[info class constructor …]` and a `foreach method {…} { method $method … }` installer; tclsh 9.0.4 and 8.6.16 agree the members are entirely real, but their spellings are only knowable at definition time, so `$c3 options` drew "Unknown method 'options'" on a call Tcl executes. A class whose body installs members the walk cannot read is now marked as having an incomplete member set and W308 abstains on it, exactly as it does for an external superclass. A class whose body is all readable declarations keeps its member set complete, so W308 keeps its teeth. (#1019)
- **`array exists PARAM` folds to false, not true.** The existence fold collapsed `info exists NAME` and `array exists NAME` into one query shape and applied the parameter rule to both, but a formal parameter is bound as a scalar on entry — Tcl has no pass-an-array-by-value — so `array exists PARAM` is provably 0. I230 reported the live branch inverted and O101 folded the arm that actually runs. (#1239)
- **`[info exists Params(key)]` now folds.** The existence fold refused any name containing non-alphanumerics, so an array-element guard never folded either way, even inside a barrier-free proc body where nothing ever creates `Params` and the guard is provably false (tclsh 9.0.4/8.6.16: `proc f {} { info exists Params(key) }; f` → 0). The fold is one-sided (false only) and rests on the *array* name's evidence, so a dynamic element key `Params($k)` folds too, with the same abstentions the simple-name path takes: scope-alias locals, TclOO instance state, dynamic-write barriers, any touch of the base under either spelling, and a parameter base. (#1173)

### Frame effects and the optimiser

- **O102 no longer forwards a stale global across a call to a proc containing `uplevel #0 {set x 99}`.** Such a write needs no global declaration so the global-write summary never saw it; the known-wrong test asserted `puts 5` where tclsh 9.0.3 prints 99. A literal `uplevel #0` body and a constructed `uplevel #0 [list set g …]` now contribute literal names, while a dynamic script or target sets an opaque flag that is transitive over the direct-call closure and becomes an opaque barrier at every call site (direct, embedded substitution, and `if`/`while`/frozen-loop conditions), so SCCP, O102, O109/DSE and branch folding all see the same fact. (#1198)
- **The optimiser no longer forwards stale values across a call whose callee rewrites them through a dynamic upvar alias.** `upvar 1 x $dst` (dynamic local side) was invisible to upvar-proc detection because the pair had no local key to file the alias under, so the summary read as empty and call sites never widened — while tclsh 9.0.4/8.6.16 confirm `proc p {dst} {upvar 1 x $dst; set $dst 2}` really does rewrite the caller's `x`. (#1165)
- **A `my` or `next` dispatch to a sibling method that reaches its caller's frame is no longer treated as a no-op.** A callee reached via `my` is a method and never appears in the upvar-procs table (the dispatch does not name its target), so its `upvar 1 $refvar ref` was invisible to the calling method's CFG. Concretely: an always-false I230 on `info exists ref` after `my Reference? $lookup ref` — where tclsh 9.0.4/8.6.14 give 1 on a hit and 0 on a miss — and a false W210 on reading the upvar-defined local. Widening is driven per method by the dispatch barrier, so one benign redefinition or an unrelated class's caller-frame helper no longer re-pessimises every dispatch site in the module. (#1177, #1097)
- **Frame effects reached through `my <method>` self-dispatch are resolved.** A mixin method reached by `my NameProcess …` names no callee in the call text; it is now resolved through the same method-resolution-order walk hover, go-to-definition and find-references share, and its frame effects are read off the resolved body. `next` still abstains, because it names no callee. (#1019)
- A fully-qualified `upvar ::tk::FocusGrab($i) data` target cell now has a definition, so hover, go-to-definition and find-references answer for it. The alias link had landed but the cell itself had no definition, so every anchor — the `otherVar` word, a sibling proc's `$::tk::FocusGrab($i)` read, `info exists`, `unset` — answered nothing. (#1139)
- Hover, go-to-definition and find-references answer on a **global cell defined from inside a proc body**, such as `upvar ::tk::FocusGrab($index) data`. The per-item graft merged a body fragment's proc scope only, so the cell never reached the document's scope tree — meaning the whole-file walk answered while the live server's incremental walk answered nothing. Find-references now returns the cell's two spellings plus both occurrences of the alias the `upvar` introduces. (#1019)
- A folded dynamic command head settles through the global fallback: `set ns tk; ${ns}::setdef …` written inside `::tk` resolved to the non-existent `::tk::tk::setdef` and stayed there, because the demotion step recovered the calling namespace from the *written* word rather than the folded one. Find-references from `::tk::setdef`'s own declaration therefore missed the call site while go-to-definition found it. C Tcl resolves a qualified name in the current namespace first, then global, so the call really does reach `::tk::setdef`. (#1019)

### Rename and references safety

- **Renaming a proc that is a `namespace ensemble -map` target no longer rewrites the subcommand word at the dispatch site.** A `-map` key is an arbitrary name with no required relationship to its target, so the old behaviour emitted a confident-looking WorkspaceEdit that produced a call to a subcommand that does not exist. Provenance is now tracked per dispatch site: a `-map` dispatch word is skipped while a `-subcommands` one — where the word genuinely is the target's tail — is still rewritten, and the `-map` *value* keeps being rewritten so the ensemble stays bound. Find-references, the code-lens count and call hierarchy are untouched, because a dispatch site is a genuine reference under either provenance. (#1281)
- **Rename no longer emits an untargeted edit that silently breaks running code.** The rename hazard check previously ran only when the cursor resolved through a trusted tier, so an untracked call site or an export bareword skipped it entirely and fell through to the untargeted tier with no gate. Both paths now consult one shared hazard function placed immediately before the untargeted tier, and the server surfaces the refusal as a JSON-RPC error rather than flattening it to "nothing renameable here". (#1273, #1019)
- **Rename started from a bare call that a live `namespace import -force` shadows** no longer rewrites the local definition the import had deleted — an unrelated proc — while leaving the call it was invoked from pointing exactly where it always did. Rename now retargets through the export oracle, and abstains when the reached definition lives in another document, leaving the cross-document tier to decide. (#1116)
- **Find-references no longer disagrees with itself under a `-force` import**: it resolved its *target* with a document-only view while filtering the resulting spans with the caller's whole-program view, so it seeded from a local definition the import had deleted and then dropped every span that definition owns. The cross-document tier had the twin bug — any candidate the workspace defines won outright, so a command a `-force` import replaced still claimed its own call sites and find-references filed the call under a definition go-to-definition no longer answers with. (#1116)
- **Find-references and rename, queried from a shadowed original proc's own declaration, no longer attribute an alias-redirected call site to that dead proc.** Renaming produced a complete-looking WorkspaceEdit that, applied, silently changed which body a live call site invokes — verified against the `interp alias {} ::ttk::spinbox {} ::tk::spinbox` shape on tclsh 8.6.16 and 9.0.4. The shared matching rule now asks whether the definition is still what its own name holds at the call site, gated on two ordering facts: the binding must be established after the declaration, and it must be unconditional at the call. A mutation sitting in some other proc's body may never run, so its call sites stay in the set rather than vanishing from an edit the user cannot inspect. (#1019)
- **Find-references, rename, the code-lens count and call hierarchy now see ensemble dispatch call sites.** `namespace ensemble create -map {…}` written inside a proc declared with a fully-qualified name at top level homes the ensemble to that namespace, and tclsh dispatches a later `::app::widget show` to `::app::widget::Show`; go-to-definition and hover answered correctly, but the enumerating surfaces never saw the site because the incremental per-item walk the live server always runs met the call site while the ensemble map was still empty and dropped it. Misses are now queued and replayed against the finished map, gated on the ensemble's recording preceding the call site, so both walk strategies record the same invocation set. A dynamic `-map` or ensemble name still records no mapping, so the dispatch site stays deliberately unattributed. (#1019)
- **The namespace-variable rename gate no longer refuses far more widely than the language requires.** It refused whenever *any* dynamic variable-name word appeared in a touched document, so a `set ::other::$n 1` next door blocked a rename of `::ns::v` it provably cannot reach. A word's written text bounds the names it can produce — a substitution can evaluate to anything, but the literal characters around it cannot change — so the word is now turned into a pattern (substitutions are wildcards) and matched against every spelling of the cell, keeping abstain-toward-refuse (a bare `$n` is a lone wildcard and still refuses). (#1093)
- The gate is narrowed further where the analyser has already proved the value: each dynamic variable-name word is recorded with the name it resolves to when the constant lattice dominates the site, so a bare `$n` with a proven value no longer refuses. Narrowing only — a site with no record, or one whose resolution is unknown (branch-dependent, parameter-fed, command-substituted), refuses exactly as before, and a brace-quoted name word records nothing because it substitutes nothing. (#1262)
- **Code actions no longer offer a quick fix for a diagnostic that has already been suppressed.** `textDocument/codeAction` lifted its quick fixes from the analyser's raw diagnostic set, so `Replace with 'ni'` was still offered with the lightbulb sitting over clean code — and accepting it rewrote a working call into a parse error (`missing operand at _@_` on tclsh 8.6.16 and 9.0.4). Both surfaces now read one published diagnostic set, so code actions also stop re-surfacing quick fixes for W120/W123s the package and auto-load refinements suppress, and now honour folder-scoped disabled codes. (#1019)

### Braced and reconstructed words

- **`namespace path {$ns ::a}` is no longer silently dropped.** The handler tested for dynamism on the IR word, which arrives with its braces already stripped, so the whole command looked computed and was skipped — no path entry and no per-element namespace reference, losing the path tier for bare-command resolution in that namespace for the rest of the file. Braces suppress substitution, so the token kind is now the authority: tclsh 8.6.14 records a namespace literally named `::$ns`, never a variable read. (#1245)
- The same reconstructed-braced-word mistake is fixed at two more sites: `namespace path {::$ns ::a}` recorded `::$ns` as a path entry but not as a namespace *reference* (one function disagreeing with itself), and `foreach n {aa {$b} cc} { proc $n {} {} }` abstained from the whole per-iteration simulation because of the single braced element — so none of the three procs were installed and every later call to them raised W123. (#1252)
- `namespace path {::a ::b}` elements each get their own reference identity at their own span, and a braced element (`{{my ns} ::b}`) is no longer broken into two bogus entries by a naive whitespace split. (#1113)
- A constant-dominated computed `namespace eval $ns { … }` target is settled through the same identity resolution `source`, `rename`, `oo::define` and the command head already use, so the block's procs home to the real namespace and the word is its declaring site. A branch-conditional or parameter-fed target keeps its per-site opaque domain. (#1113)
- `[set {$n}]` no longer credits a read to `n`, which was masking a real W220 (`n` assigned and never read); a braced word in a variable-name role is the name, not hidden text. (#1108)
- A `namespace eval` scope no longer claims a `[...]`-built body's bytes, which is text evaluated in the *calling* frame — owning it made scope-chain lookup answer nothing for `$file` in Tk's own `::tk::SourceLibFile`. Relatedly, a list-built command's argument words are already-substituted list elements and are no longer re-walked for nested `[...]` substitutions, which previously recorded a second, wrong-namespace invocation edge (`::helper` alongside the correct `::app::helper`) that rename and find-references could act on. (#1138)

### Formatter, minifier and refactorings

- **Formatting a file no longer silently changes a proc's arity.** The formatter scanned parameter lists by hand — whitespace runs and balanced braces only — so a parameter list containing a backslash-newline, which C Tcl 9 collapses in a pre-pass *before* list-parsing and therefore declares as two required parameters, was re-emitted as one *optional* parameter with a default. Parameter lists now run through the script-level backslash-newline pre-pass followed by real `Tcl_SplitList`/`Tcl_Merge` list semantics, in the order C Tcl applies them. A list that does not parse (unmatched brace or quote — routine mid-edit) has no canonical rendering and is preserved verbatim. (#1196)
- **The minifier no longer renames or drops anything that is observable identity in Tcl.** Four separate semantics-destroying bugs are fixed, with all observability knowledge coming from registry traits rather than command-name matching, and all four reproducers plus a 12-case regression corpus verified across four tiers against real tclsh 9.0.4 for identical stdout and exit status:
  - Array member keys (`arr(longmember)`) are data, observable through `array get`, `array names`, traces and serialisation — not private symbols. The compact tier's member compaction and its unsound name-prefix deny-list are removed outright. (#1192)
  - Name compaction no longer changes reflection results or public command identities. Proc names are renamed only under the `isolated` closed-world assertion, and even then only when no command-name-reflecting command (`info procs`/`commands`/`body`/`args`/`default`/`cmdtype`/`level`/`frame`, `namespace export`/`import`/`forget`/`origin`/`which`/`ensemble`/`unknown`, `rename`, `interp`, `unknown`, `auto_*`, `trace add`/`remove`/`info`) and no computed command head appears; a proc overriding a registry-known command (`proc unknown ...`) is never renamed. `info locals`/`vars`/`exists`/`globals` bar the containing scope, and `upvar`/`uplevel` bar every scope since the observed frame is statically unknowable. Bare-name reference sites are renamed in lock-step with the declaration — `set v 1; set v 2; return $v` previously compacted into a program returning 1. The optimiser also stops deleting reflection-observed stores, and stores a callee observes through an `upvar` alias or an `uplevel` write are now recorded and skipped by O109/O126. (#1193)
  - Minifier-generated alias variables no longer shadow live variables. The default tier's `[subst $alias]` template deduplication is removed — its `set alias {...}` preamble was a real variable write that clobbered live variables (`puts [set a]`), fired traces and changed `info vars`. The default tier is now frame-transparent by contract; the aggressive tier keeps aliasing, is documented as explicitly *not* frame-transparent, and seeds its generators with every live name the compiler can see so an alias can never collide. (#1194)
  - `switch` arms whose pattern begins with `#` are no longer dropped. A braced case list is a Tcl *list*, split with `TclListObjGetElements`, where `#` starts no comment. Both the minifier's case-list handling and the compiler's `lower_switch` now use the central list grammar via the registry's `case_list` descriptor (covering Expect-style clause flags generically); patterns keep their exact spelling, `a\ b` patterns decode to their list value for matching, and malformed or odd-length lists are preserved verbatim so runtime errors are unchanged. (#1197)
- **The two W302 catch-result quick fixes were anchored at the end of the word `catch`** rather than past the body, so applying either turned `catch {error oops}` into `catch result {error oops}` — which C Tcl reads as a catch of the script `result`, giving completion code 1 with `invalid command name "result"` and storing the message under a variable named `error oops`. The fixes are now built by the analyser with spans computed from the invocation's argument tokens, with the count and inserted names read off the dialect-applicable synopsis — so Tcl 8.4 and iRules, which document `catch script ?varName?`, correctly get one fix, not two. Multi-line, quoted, bracketed, empty `{}` and `::catch`-qualified forms all anchor correctly. (#1190)
- **"Fix All Safe Issues" no longer applies fixes that change Tcl semantics.** It selected from a hardcoded list of diagnostic codes and applied each diagnostic's first fix without checking anything, and at least two of those codes were unsafe: W100's brace fix breaks `set a {$x}; puts [expr $a + $b]` (5 before, an error after) and W110's `eq` rewrite turns `expr {"1" == "01"}` from 1 into 0. Safety is now a property of each individual fix (`SemanticsEquivalent` / `BehaviourHardening` / `StyleOnly` / `RequiresReview`, defaulting to `RequiresReview` so a new emitter cannot silently opt in), all 40 fix-producing sites were audited and classified at their emit site, and W100/W105 brace-wrapping is decided per instance — byte-identical when the word carries no `$`, `[`, `\` or `"`, and a deliberate removal of a substitution round when it does. The applied report now names each fix's safety class. (#1195)
- **The "Add `package require X`" code action no longer fires on text that merely resembles a package-qualified command.** A cursor anywhere on `http::geturl` in a comment, a quoted string, a `dict set` argument word, or a `proc http::geturl {} {}` definition offered to add the require — which is not harmless, since it changes what the interpreter loads and runs the package's initialisation code. The action now requires that the request range touches a recorded command invocation's head-token span, that the head is written literally rather than computed, that the head's leading namespace component *exactly* names a catalogue package (`json::write` is evidence, `jsonify` is not), that the shared definition resolver — which knows about namespace visibility, `namespace import -force`, static `rename` and `interp alias` — finds nothing, and that the package is not already required. A leading `::` is now stripped before the namespace component is taken, so the fully-qualified `::http::geturl` spelling that library code writes finally matches. (#1191)
- **Inline proc now performs real argument binding instead of splicing raw source text.** `f {a b}` passes the value `a b`, not the four characters `{a b}`, so inlining `greet {a b}` against `proc greet {name} { puts "hello $name" }` produced `puts "hello {a b}"` — printing the braces. And a parameter with no written argument is not absent: `proc f {{name world}}` called as `f` binds `world`, where the old splice emitted a read of an unset variable. The refactoring now handles positional parameters, declared defaults, the variadic `args` tail, and C Tcl's arity rules, and refuses with a plain-English reason for a multi-command body, a frame-sensitive body (`return`/`break`/`upvar`/`uplevel`/`global`/`variable` and kin, from registry data), a body that assigns a variable, a body that reads `args`, a wrong argument count, a value that is not a plain word, a non-numeric value in an expression operand, or a repeated parameter bound to a run-time argument. (#1199)
- **Extract into proc no longer silently changes program behaviour by passing written variables as value parameters.** The reproducer — `set x 0; set x 1; puts $x; puts "after=$x"` — printed `after=0` after extraction instead of `after=1`, because the write had moved into the proc's own copy of `x`. Variables are now classified from registry `VarWrite`/`VarRead` roles plus `$name` references: read-only becomes a value parameter, written-and-read-after is passed by name and re-bound with `upvar 1` so the assignment reaches the caller's frame, and written-never-read becomes a proc local (which no longer leaks). The definition is placed above the enclosing *top-level* command rather than at line 0, so it lands after the file's prologue, and its name is checked against workspace symbols and the registry so it cannot shadow a builtin. Refusals cover frame-sensitive commands, computed variable names, array-element writes, computed command heads, and a selection inside a namespace or class definition body. (#1201)
- Extract-proc's insertion and replacement at the same offset no longer interleave; refactoring edits sort by `(start, end)` descending rather than by start alone, where ordering was previously left to sort stability. The generated proc name is compared fully qualified rather than by simple name, since the definition is written at top level. (#1201)

### Line endings, BOM and encoding

- **A lone `\r` in a source file is treated as a command terminator**, exactly as tclsh's `-translation auto` channel does before its parser runs. Treating it as whitespace produced false E003 and W210 diagnostics and hid real errors, and the LF-only line index shifted folding, symbols, highlights and semantic tokens off the client's lines — a fully CR-terminated file was a complete feature blackout. The raw client bytes are still kept for formatting, will-save edits, fix-all splicing and the W118 line-ending-style lint, which must see real terminators. (#1122)
- **Format-on-save no longer silently corrupts a document containing a stray `\r`.** The whole-document formatting edit range was computed on an LF-only line model, so a single lone CR anywhere in the file made the returned range disagree with the client's clamp-then-splice. The edit range and range formatting now use the client's line model. The formatter also no longer rewrites every CRLF document wholesale to LF on format. (#1122)
- **A file whose first byte is a UTF-8 BOM no longer draws W123** with the mark glued to the first command name. Tcl 9's `source` skips a leading BOM and Tcl 8.x's does not, so this is dialect data: only Tcl 9 whole-file segmentation skips it, and the VM's eval path and every nested body re-lex still read a BOM as data. The skip starts the scan past the mark rather than rewriting the buffer, so every span keeps its true byte offset. (#1218)
- **The BOM rule applies at *every* provider entry point**, not just the analyser's. `\u{FEFF}proc` still lexed as one word everywhere else, so the first command's semantic token spanned the mark and the name together, its body fold was lost (a marked name resolves to no registry command and therefore carries no body role), and its document links, inlay hints and references all missed it. Folding, semantic tokens and their import/loop-var/snit-handle scans, document links, inlay hints, references, hover's compilation unit, and the iRules `when`-context scan now all opt in at the top level, with each depth-aware recursion demoting below depth 0 because a mark at the head of a *nested* body slice is data. Pinned by an 8.6 control, where a BOM'd first command really is `invalid command name`. (#1243)

### Interpreters, Tk and dialects

- **TK1001 (geometry-manager conflict) and TK1002 (widget path references a non-existent parent) are decided per interpreter domain** instead of across a single flat, file-wide map. `.top` inside `child eval { ... }` and `.top` in the parent script are genuinely two unrelated windows in C Tk, so the old flat state produced a false TK1001 (a parent-side `pack` "conflicting" with a child-side `grid`) and missed a real TK1002 (a parent created in one interpreter vouching for a child widget in another). `interp delete c; interp create c` now really does end the hierarchy. Unresolvable targets such as `interp eval $i { ... }` widen rather than accuse. (#1141)
- **A `rename` inside a child interpreter's eval body no longer poisons the parent's command table.** `interp create c; c eval { rename puts myputs }` renames only in `c`, but the analyser recorded the rename file-wide, so a later parent-side `puts hi` drew a false W123. Command-table facts are now scoped to the interpreter the statement is written in. Likewise `interp alias {} shout {} puts` inside a child body homes the alias in the child, not at the global root, and the alias-deletion form resolves an empty path to the enclosing frame's domain. (#1141)
- **Per-folder `tclLsp.dialect` actually reaches the server in a multi-root workspace.** The scoped configuration pull dropped the dialect key, the folder-dialect map was only ever fed by initialisation options no editor sends, and directory URIs resolved to the session default. (#1122)
- **Switching editor tabs no longer bakes the focused file's detected dialect into every other open buffer** as a session-global setting, which produced false W002 and W123 in untouched documents. The extension now updates only the status bar on focus changes and leaves per-document dialect detection to the server, and the config pull re-resolves open-document dialects at its single exit — which also closes the startup race where tabs restored before the first pull kept the stale default forever. (#1122)

### Miscellaneous

- **Sticky scroll no longer goes permanently blank for Tcl files.** VS Code treats a non-null but empty folding model as authoritative, so an empty folding array terminated the candidate chain for the whole session, while only a null response falls through to the indentation model. `textDocument/foldingRange` now returns null whenever the feature is disabled, the document is unknown, or the computed set is empty, on every branch (Tcl walk, BIG-IP stanza scan, salsa-served and cold fallback), and `initialized` sends a `workspace/foldingRange/refresh` once after the initial workspace scan settles so a sticky model computed before the provider registered is recomputed against real data. (#1122)
- Activation now logs a breadcrumb when the resolved sticky-scroll default model for Tcl is not `foldingProviderModel`, and offers a one-time, persisted Restore notification when a third-party extension's own dotted defaults block has clobbered ours, or when an extension language default has beaten the user's explicit global setting. A user-authored language-level setting always wins outright and keeps the extension silent. (#1122)
- **An external rename (`git checkout`, `mv`) no longer leaves a ghost entry in the workspace index** for the life of the session, which produced duplicate symbols and go-to-definition landing on a file that no longer exists. A DELETED watched-file event was previously skipped entirely for open documents. Files named with an upper-case extension (`UPPER.TCL`) are now indexed and rename-safety-checked; the source-file predicate matched extensions case-sensitively while every sibling predicate folded case. (#1122)
- **Calls to a proc whose parameter list is computed no longer draw a false E003 from another file.** `proc p [makeargs] {}` recorded one parameter literally named `"[makeargs]"` in the signature scan, and the cross-file arity table carried the parameter list but not the "computed" flag, so a computed list reached the cross-file check as an empty list — read as "takes no arguments" — and every call from another file was flagged. Verified against tclsh 9.0.4 and 8.6.16, where `proc makeargs {} {return {a b}}; proc p [makeargs] {…}` gives `info args p` → `a b` and `p 1 2` succeeds. Arity now abstains for computed lists at every tier. (#1107)
- The LSP cursor classifier and the analyser no longer disagree about whether a parameter list is literal. The classifier rejected any word containing a `"`, so the substitution-free quoted list `proc r "m n" {…}` was called computed while the analyser correctly called it literal (`info args r` → `m n`); it also rejected a bare word with an interior quote (`a"b`), which Tcl treats as ordinary literal text. Both now consume one shared predicate. (#1107)
- **A computed `source` path is no longer anchored on the language server's own working directory.** The evaluator absolutised a rootless fold result against the *analysing process's* directory; Tcl does resolve such a path against a working directory, but it is the interpreter's at run time, not the editor's at launch, so the same file resolved differently depending on how the editor was started, and a computed `source` path disagreed with the literal path written beside it. Each caller now applies the base it actually has: the sourcing document's directory for the source graph, the workspace root for document links, and the analysed document's own directory for the package database. `file dirname` of a single-component relative path now yields `.` as tclsh does, rather than the empty string the old absolutisation papered over. (#1019)
- **W138 no longer reports a bogus Tcl 8.6 requirement for `clock format $t -format {%b}`.** The DSL format-site recorder treated every format-string role as a printf `%`-string; it now gates on the sprintf family and leaves `clock`, `binary` and the other mini-languages alone rather than guessing. The registry's exhaustive argument-role list had also omitted the format-string and scan-format roles, so any consumer asking "does the registry give this argument *any* role" got the wrong answer for a `format`/`scan`/`clock -format`/`binary`/`regsub` conversion word. (#1185)
- `rename` with the wrong argument count no longer moves anything in the command table — `rename` takes exactly two arguments, and a `wrong # args` call moves nothing — and `CommandRegistry::command_table_effect` resolves `::`-qualified mutator heads, matching C Tcl, so `::rename format ::origfmt` really does rename. (#1185)
- The iRules object-reference walker resolves heads through the identity map, so a pool reached only through `interp alias {} p {} pool` or `rename pool p` no longer looks unreferenced. The reference graph is what `bigip-cleanup` decides deletions from, so this was a live-object-looks-orphaned bug, not a highlighting nicety. (#1275)
- **The compiler explorer's WASM tab rendered nothing and the compile throbber never stopped**: the Rust port of the explorer serialiser dropped the `types` array from the synthetic module header, and the renderer read `entry.types.length` unguarded, throwing a `TypeError` on every compile. `WasmModule` now exposes a non-mutating `type_section()` view that computes the table both serialisers emit, and the explorer JSON carries `types`, `totalInstrCount` and `functionCount`. (#1182, #1183)
- **The Spec Studio emitted an uncompilable spec for any command carrying a lifecycle.** `CommandSpec` and `SubCommand` declare one `lifecycle` field but the form edits it as three independent releases, and the renderer emitted each key verbatim — so a spec for `persist` (and every other lifecycle-carrying command) came out as `introduced_version: Some("21.1.0"),` and failed to compile, defeating the studio's whole promise of a drop-in file. The three keys are now collapsed into the one field at the position of the first, so field order is unchanged. A `RepeatedArgLayout` drafted in the WebUI also came back with `conditional_binding` silently lost, because the seeder built the literal from a hand-written format string listing five fields — the round trip looked clean while dropping the field. (#1185, #1210, #1278)
- Cross-file method hover now answers on a mixin method reached through a sibling file, and two package-gated arity false positives sharing one root cause were fixed. (#1273, #1019)
- Two e2e races that were real server behaviour: under the newly coalesced config reload an early reschedule can republish version 1 with the old profile before the pulled config lands, so both the optimiser toggle and the folding toggle could be observed running under stale settings — the settled state, not the first republish, is now the barrier. A second race in the diagnostics master-switch path: flipping `features.diagnostics` off does not bump the document version, so a converged or cross-file publish for the same version still in flight could be mistaken for the post-toggle empty publish; the wait now keys on the server's own master-off timing marker and reads the publish immediately preceding it under the same lock, with no TOCTOU gap. (#1213, #1135)
