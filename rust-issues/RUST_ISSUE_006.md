# RUST_ISSUE_006: the "every registry command needs WASM runtime backing" contract is enforced by NOTHING

> Part of the origin/rust (tip 6820b3c) branch bug sweep (2026-07-07). Master index: [../RUST_ISSUES.md](../RUST_ISSUES.md).

| Field | Value |
|---|---|
| **Severity** | high |
| **Subsystem** | Backend parity (WASM/VM/eBPF/registry) |
| **Location** | `registry↔runtime` |
| **Status** | Fixed |
| **Verification** | Reported by review agent (confidence: high) |

## Finding

registry↔runtime — the "every registry command needs WASM runtime backing" contract is enforced by NOTHING.
runtime/rust has no dependency on tcl-registry, there is no Rust parity test (no runtime_backed/not_required classification anywhere), no Makefile/CI gate. The only artifact `docs/generated/command-spec-coverage.md` is generated by `scripts/check_command_spec_coverage.py` which no longer exists (Python retired). So AGENTS.md:268-287's contract is asserted but unverified, and the table is orphaned/frozen (wasm_codegen_hook column 0/117). Confidence: high

## Resolution

The contract is now enforced by a native drift gate, `cargo xtask command-backing`
(`rust/xtask/src/command_backing.rs`), wired into `make xtask-check` (so it runs in
the Rust PR gate / CI). It reconstructs the check from live data rather than a frozen
table:

- **Source of truth** — `tcl-registry`'s core Tcl command specs
  (`tcl_command_specs()` filtered to `required_package == None` and available in
  Tcl 9.0 via the `DialectSet::TCL90` gate): 232 commands.
- **Backed set** — scanned from the runtime source for `register_builtin(b"…")`
  registrations, canonicalised on a leading `::` so `::tcl::build-info` (registered)
  matches `tcl::build-info` (registry). A small `HANDLER_EXTRA` list covers the
  commands the runtime backs natively but *outside* that literal scan — the `TclOO`
  metaclasses bootstrapped as objects (`oo::class`/`oo::object`/`oo::abstract`/
  `oo::singleton`/`oo::configurable`) and the per-object `my`.
- **Residue** — every remaining core command is explicitly classified: `STDLIB`
  (the embedded real-C-Tcl-9 `init.tcl`/`package.tcl`/`parray.tcl` fallback), an
  `is_expr_operator` predicate for the `expr` operator family (`+`, `tcl::mathop::*`,
  `eq`, …), `NOT_REQUIRED` (external process / socket / native load / event loop /
  dialect / debug-only, each with a reason), and `KNOWN_UNBACKED` (real gaps tracked
  by `RUST_ISSUE_007`).

A generated report, `docs/generated/wasm-command-backing.md` (committed,
drift-checked), records the per-command status. Current tally: 94 handler, 6 handler
(native), 11 stdlib, 111 not-required, 10 known-gap, **0 unclassified**. `--check`
fails on report drift, on any `UNCLASSIFIED` command (a genuinely new gap: a registry
command with neither backing nor classification), and on any stale classification
entry (a name no longer core, or one that has since gained a handler) — so adding a
command to the registry, or dropping one from the runtime, can no longer silently
diverge. The orphaned `command-spec-coverage.md` / retired-Python path is replaced.
