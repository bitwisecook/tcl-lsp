# Compiler registration slots

Compiler selection and callable resolution consume the same retained name table through distinct purposes. CompilerSlots selects the original registered wrapper, including genuine runtime alias tokens that have no authored source declaration. It does not follow a callable prefix or infer an original procedure allocation.

The actual runtime compiler row must match its interpreter/token and retained implementation generation. Runtime Alias and PartialAlias wrappers admit generic compilation only when the captured actual hook is absent. Hook presence or unknown hook availability refuses the descriptor; target names, procedure headers and source metadata supply no substitute hook.

NamedSlots and WithFallback continue resolving callable/source targets with their original publications, allocation/currentness and namespace context guards. The compiler projection exposes no terminal execution target or Source procedure grant.

Software metadata controls distinguish hook absence, presence and unavailability with a missing target; they assert compiler selection and no execution proof independently. Actual backend conformance is covered by the unchanged original VM alias-record and namespace-origin programs. Those programs remain partly failing in retained diagnostic captures; source-only controls do not certify native execution.
