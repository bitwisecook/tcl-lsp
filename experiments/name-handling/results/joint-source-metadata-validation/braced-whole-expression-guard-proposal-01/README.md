# Whole-expression source geometry guard proposal

The unchanged [existing owner control](../braced-source-repair-validation-01/README.md) fails for `expr {[format hidden]} + 1`: a unique authored Expr role on operand0 does not establish that the entire expression operation uses that one physical source word. Tcl may concatenate multiple arguments into a valid runtime expression; this proposal withdraws an unproved whole-source coordinate mapping, without making an interpreter acceptance claim.

Registry already owns `Traits::EXPR_CONCATENATES_ARGS` on the selected descriptor, actual argument offset and exact argv cardinality. The proposed whole `source_expression_script_bodies` guard borrows the same genuine source schema under the caller's retained full context. If its selected trait concatenates arguments, exact count must be argument_offset+1; unknown cardinality, unavailable schema and other counts decline. Non-concatenating schemas retain the existing unique Expr-role and original container/grammar guards. The separate `_at` API, whose caller independently retains an actual Expr AST base, is byte-unchanged; this is not a blanket one-argument restriction on if/elseif or all Expr-role commands. No new Registry field/API, local parser or command-name branch is needed.

The scratch patch is scoped-formatting clean. It is not applied, built or executed. The original multi-argument and cooked adverse assertions stay unchanged. Readiness retains the exact source preimage and proposed hash. Independent owner review and root apply/build grants are pending. Earlier four passing controls remain scoped to their preimage; the current owner failure remains sealed unchanged. This is a local source-coordinate contract proposal, not a Native identity/provider/canonical proof promotion.
