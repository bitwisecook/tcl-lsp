# Native VM source-entry baseline

The driver selects the actual C native core for the requested release, installs the matching compiler profile, and requires the selected physical Tcl distribution library. Host execution refusals remain outside guest completion. The default release is 9.0; `--tcl-version` selects 8.4, 8.5, 8.6, 9.0 or 9.1.

All four recorded Tcl 9.0.4 upstream selections stop during real `init.tcl` compilation with `native compiler preflight provider required`. None reaches the selected namespace, rename, trace or TclOO test. These are setup refusals, so they establish no pass or failure for those upstream cases. They cannot be compared as semantic outcomes against the earlier logical-driver captures.

`native-codegen-diagnostic.txt` retains the admitted diagnostic mode (`TCL_LSP_NATIVE_CODEGEN_DIAGNOSTIC=1`), which reports missing command-name recipes for `namespace which -command exec` and `namespace which -command tclLog`, at source offsets 3567 and 3862 in the real Tcl9.0.4 `init.tcl` (lines124 and135). The rejection reaches `rust/tcl-compiler/src/codegen/statements.rs:2559`, via the native byte command-name recipe owner. The captured physical execution point is C Tcl9.0Canonical; the statement invocation-policy diagnostic has no core point. The driver supplies an exact `tcl9.0` profile to the actual native core; replacing it with a logical issuer would not resolve the missing original proof.

`namespace-which-reduction.tcl` contains those exact commands for a direct native-core source-entry experiment. It is a source reduction, not a replacement distribution library, upstream test result or oracle claim. The shared native-byte compiler already derives its physical dialect from the actual compilation-entry execution point and validates its original name-policy receipt. The diagnostic invocation policy is independent. The next owner to inspect is the authentic selected ensemble worker: `registry.native_selected_worker::compile_original_selected_worker_path` reports a recipe refusal when that selected worker has no admitted original compiler plan. Resolve that worker proof while preserving typed refusal if its recipe remains unavailable.

`build-receipt.json` identifies the native executable, build invocation, modified worktree and captured source hashes. `runner-source.txt` is a source snapshot taken after this build; test-only additions and the factored native-core constructor were introduced while the build was active, so that snapshot is not an exact original build input. The immutable local executable path and its hash identify the actual measured driver. `driver-tests.txt` is the subsequent build of the final source, with three passing tests, including actual core selection and noncatchable absent-compiler refusals across all five releases.

The tests cover driver selection/refusal boundaries. Actual distribution initialisation across all five releases and the four selected upstream cases remain blocked by the source-owner proof refusal. No namespace lifecycle implementation was changed for this baseline.
