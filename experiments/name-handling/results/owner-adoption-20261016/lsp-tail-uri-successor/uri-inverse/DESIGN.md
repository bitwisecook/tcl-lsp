# Checked native document/workspace URI path

Core's existing `file_uri` owner gains `to_path(original_uri: &str, FileUriPathPurpose::VsCodeDocument) -> Result<PathBuf, FileUriPathUnavailable>`. The original protocol URI enters the actual `fluent-uri` parser, which already backs `ls-types`. The direct Core dependency exposes its typed authority and strict component decoding. There is no private URI parser, percent decoder, second path resolver, lossy source conversion or upward Core dependency.

Server `uri_norm::document_file_path(&ls_types::Uri)` is a thin original-URI adapter selecting that explicit product purpose. It exposes the Core refusal enum through the `DocumentFilePathUnavailable` alias. The original URI's `as_str()` is protocol input to its actual parser, not a displayed filename or Tcl-name identity inverse. The server has no parallel generic conversion algorithm.

This purpose retains nonempty POSIX authorities as counted `//authority/path` and Windows authorities as native UNC roots. `localhost` remains authority data here. `file_action_path` and its original assertions are byte-identical and retain nonlocal-authority refusal. Browser virtual paths remain a distinct unresolved purpose; this native API refuses unsupported host targets.

The actual whole URI parse refuses malformed input. File scheme, query/fragment and full authority structure are checked before conversion. Typed userinfo, port and unsupported IP-literal authorities refuse. The actual parser strictly decodes complete authority/path data; invalid Unicode, NUL, encoded native separators and unsupported host geometry refuse terminally. Literal Unicode replacement characters remain data, literal percent text is decoded once, and POSIX backslashes remain filename data. No component normalization, case folding, canonicalization or filesystem lookup occurs. Windows alone selects the drive/UNC recipe; unsupported verbatim namespace forms refuse. Pure foreign-platform recipe tests grant no native admission. Public admission requires `Path::is_absolute` under the actual native host.

The source-cleared V1 private conversion helper is byte-identical after moving to Core and renaming its argument/error types. Core's public wrapper adds actual whole-URI parsing and the explicit purpose selector, including typed `InvalidUri`. All original Core producer tests, Server URI tests and `file_action_path` implementation are authenticated unchanged. Tests retain exact native spelling rather than Path equality where duplicate separators matter. New malformed-URI controls exercise the public parser; negative component controls additionally exercise public native admission on supported hosts.

The result establishes only protocol-to-native-path data. It supplies no filesystem identity/existence, registered virtual-path association, source bytes/version/configuration, current analysis, load order, Tcl name identity, callable/Native authority or edit grant. Adopters must keep their actual source/store/current metadata checks. Conversion refusal is terminal; it must not fall back to lossy `Uri::to_file_path`, display data, or an absence assertion.
