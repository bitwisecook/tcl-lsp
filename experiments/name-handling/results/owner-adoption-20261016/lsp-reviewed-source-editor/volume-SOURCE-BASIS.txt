Why preserving old production Some is incorrect for the VolumeGUID fixture:
Actual original Windows path: \\?\Volume{01234567-89ab-cdef-0123-456789abcdef}\project\file.tcl
Installed ls-types0.0.6 uri.rs212-246: for an absolute path, prefixes file:///
and encodes its backslash-to-slash spelling without filesystem canonicalization.
Raw URI: file://///%3F/Volume%7B01234567-89ab-cdef-0123-456789abcdef%7D/project/file.tcl
Original server Windows repair strips the %3F/ marker, yielding:
file:///Volume%7B01234567-89ab-cdef-0123-456789abcdef%7D/project/file.tcl
Installed provider uri.rs174-204 Windows inverse removes the first decoded /
and returns Volume{...}/project/file.tcl, which is relative and not the original
verbatim-volume root. Thus prior Some is an unfaithful redirect, not evidence
for actual Windows volume-path acceptance.
