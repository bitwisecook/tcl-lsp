# EngineWasm command replay purpose review

Read-only checkout inspection; no EngineWasm source mutation or build. Prepared bounded root-entry proposal: `root-entry-original-input.patch`; exact source/proposal hashes and unexecuted status in `prepared.json`.

Runtime command receipts are genuine live identity records: actual installed namespace/simple slot supplies a reporting FQN; owner/interpreter/generation remain independent. EngineWasm creates/removes with counted original bytes and retains genuine generation receipts. Current/guard checks compare the actual live receipt; these checks must remain unchanged. Receipt `qualified` is a rendered projection, not a reconstructible original publication/removal request or portable namespace identity.

`lib.rs::apply` currently replaces the setup command's original bytes with receipt.qualified. `Engine::remove_command_bytes` similarly replaces the original successful removal request. These calls are independent engine entry operations; `Session::begin_entry` documents that they are not nested callbacks. Retaining the original bytes in Setup allows fresh replay to call the same existing counted create/delete adapters rather than reinterpret a display projection. The bounded proposal removes only those two replacements. It keeps actual creation/deletion, host receipt storage and current-generation guards unchanged. It is unapplied/unbuilt and needs the independent-entry context contract verified in actual guest controls before an execution claim.

`host_call::WasmRegistrar::{define_command_bytes,remove_command_bytes}` also writes receipt.qualified into Defined records. These operations occur inside a guest host callback and can inherit a non-root namespace. Replacing the projection with the original bytes alone is insufficient for relative qualified C API publication: unqualified publication is globally anchored, relative qualified publication uses the actual current namespace, and absolute publication selects root. Removal has its own live lookup context and token. Fresh replay must retain the operation purpose and authentic source namespace geometry without borrowing an old instance's token or generation. The present receipt ABI exposes only owner/interpreter/generation plus the projected FQN; it does not supply that portable context. A display FQN cannot repair the gap, especially when namespace components have literal colons. No callback rewrite is proposed until the actual context transport is selected.

Existing shared architecture: `NativeNameProtocol::command_c_api_publication_projection` owns C API registration extent/route; live Runtime `command_c_api_publication_at` owns actual token traversal. Removal reuses actual command lookup/rename owners. `interp/native_host_publication.rs::PublicationService` retains actual context, original bytes, selected purpose and an independently guarded actual slot receipt. The fresh EngineWasm replay adapter should follow this separation; no new resolver or string normaliser is needed.

Required bounded controls: existing `what_was_set_up_survives_a_trap`, `installed_receipts_keep_renamed_hosts_and_remove_old_name_replacements`, `compiled_receipts_refuse_foreign_and_replaced_handles_before_effects`, and `counted_publication_and_guest_completions_preserve_opaque_bytes`; add actual trap-rebuild tests for root lone-colon/interior-run/empty-component names and callback relative-qualified publication/removal under an actual non-root namespace. Retain independent C API creation versus deletion purpose and release/provider axes. No oracle failure or full fresh replay correctness claim follows from this source audit.

A separate inventory/query consumer in `extension_host.rs::LIST_COMMANDS` trims namespace/command colons while deriving command reporting rows. That consumer belongs to root's script query/report audit, not this replay proposal. Its reporting inventory grants no binding or mutation authority.
