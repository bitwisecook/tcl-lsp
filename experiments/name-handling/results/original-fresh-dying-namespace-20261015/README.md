# Original fresh dying-namespace operands

Two unchanged six-provider captures retain their exact executable/init hashes, probes, process exits and raw stdout/stderr. The [initial legacy-trace capture](manifest.json) uses `trace variable`; C8.4–8.6 reach the callback, while C9.0/9.1 reject that legacy trace form and pinned Jim reports no `trace` command. Those failed/unavailable rows and empty channels remain intact. The separate [trace-add capture](trace-add/manifest.json) reaches the unset callback on all five C providers; Jim again reports missing `trace`, which supplies no namespace observation. These are plain original Tcl/Jim executions with matching original C init libraries, not tcltest. No upstream HEAD query or provider rebuild is performed by this archive.

Inside the actual namespace unset callback, each operation receives a freshly formatted `retiring` operand. C8.4 reports namespace-exists true and namespace-eval succeeds. C8.5–9.1 report exists false and eval errors that the namespace already exists. Outer deletion completes and the final namespace-exists result is false in all five reached C runs. This is the measured fresh-source case; no cached/hot operand or physical header/lease chronology is inferred.

The [source anchors](source-provenance.json) separately bind exact selected original `SetNsNameFromAny` function excerpts to complete source-file hashes and line positions. C8.4 retains a found namespace, while later selected source rejects a dying namespace during fresh conversion. Source excerpts are not a replacement for the executed probes or a complete provider/SDK/build correspondence proof.

All28 original nonbinary files are byte-identical, including both failed legacy C9 rows and both Jim refusals. [SHA256SUMS](SHA256SUMS) covers retained/support files. `python3 verify.py --current-provider` checks exact retained bytes, optional currently available original executable/init/source bytes and original before/after equality. It does not execute a provider. `python3 replay.py --out /tmp/new-fresh-dying-namespace-run` writes a separate reproduction of both captures with checked original providers and selected library environment; it never overwrites this archive and its output is separate evidence.

These observations establish no Rust Runtime/VM, F5, cache/header identity, complete reentrant trace or final-free/lifecycle acceptance.
