# Control 04: original definition reporting owner

**Question.** Does script-form error reporting read the original definition target's name from a newly selected child's table before the actual definition owner settles its callback? [Measured control](../repair-02/vm-control-04.log): one unchanged test, exit 101, `cmd_oo.rs:427` panic `live object retains exact command reporting name`. The concrete observed predicate is `vm.oo.names.get(&target).is_some() == false`; the log exposes neither loop mode nor current/original interpreter IDs, call stack, or complete underlying typed cause. Owner mismatch remains a hypothesis, not a measured result.

**Actual producer and candidate reporting path.** `cmd_oo.rs:342` `OoState::allocate` attaches the reporting bytes to the actual freshly allocated stable object token. `display_oo_bytes` (`:421`) indexes the currently selected `vm.oo.names`; it takes only an `OoId`, with no retained interpreter/definition owner. The fixture `definition_exit/tests.rs:257` preserves its original selected interpreter, creates a real child and actual C9.1 class, and calls `definition_worker` followed by `definition_self_at`. `native_context.rs:456-469` uses `with_target` to rewrite the actual selected row, then `definition_self` (`:472`) supplies the real object's name and calls `run_define` in object mode. For script form, `run_define` calls `append_define_frame` on Error or `definition_error` (`cmd_oo.rs:3071-3093`, `:3132`) before `definition.finish`; that reporter reaches the unowned current-name-table query (`:3127`). The retained executable log has no backtrace, so this candidate reporting call site is not yet distinguished from other callers of `display_oo_bytes`.

**Genuine fixture action.** Observer mode 2 (`definition_exit/tests.rs:81-94`) selects the actual child, pushes its private namespace activation and installs child usage, then returns Ok. It deletes no original object. Modes 0/1 do not select that child. Thus an original target token used against child names is a credible cause; it is not evidence that target numbers identify corresponding child objects, nor permission to recreate/copy the name there.

**Existing owner boundary.** `OriginalDefinitionExit::check` (`definition_exit.rs:83`) first checks the actual captured call/namespace through `self.active.check_call_and_namespace(vm)`, then the retained row's activation and usage allocation identity. `finish` (`:119`) performs that check, retains the complete error, and retires/restores only through the existing captured cleanup owner before its final settlement. `with_target` (`:300-323`) checks after callback-bearing work and similarly restores the original row through `active.cleanup().oo_mut(vm)`. Script reporting can occur inside `work` before those existing post-work checks. The check is private: a credible fix should add a narrow owner-bound reporting operation using that existing check, not expose a generic new public authority or read a parked table solely because its label matches.

**Matching C9.1 source.** Current `tmp/tcl9.1.0/generic/tclOODefineCmds.c` hash matches retained v3's OO source receipt. `TclOODefineSelfObjCmd` (`:1526-1581`) obtains the original Object from the real definition context, retains it and its pre-script name, evaluates in the same passed `Tcl_Interp *`, calls `GenerateErrorInfo` before frame pop, then releases. `GenerateErrorInfo` (`:1116-1142`) uses the actual current object name for a live Object, or its saved pre-script name if deleted. C's unchanged interpreter argument is not analogous to the VM's changed selected interpreter table. Existing bootstrap v3 and the fresh public namespace oracle do not measure error-frame reporting across VM interpreter selection; no new C execution ran here.

**Next bounded experiment, unexecuted.** In a coordinated window, instrument only two temporary owners: this existing test file and `cmd_oo.rs`. Keep the exact unchanged test, real class/child factory, loop modes, arguments and assertions. Immediately before `definition_self_at`, log mode, original/current interpreter IDs and target token. In mode 2's actual callback, capture current interpreter before the existing switch, then log after the switch whether that actual original state's target object/name remain present and whether the currently selected child has that same token. At the failing `append_define_frame` query, log only current interpreter, target token, current object/name membership and the existing complete `execution_refusal` carrier; preserve the original lookup and panic. Do not add a currentness check as instrumentation, since it could change the first cause. Rebuild truthful dependencies, run exactly this one control with its full panic stack, retain source/binary identities and restore both owners byte-exact.

**Conditional minimal repair.** Only if that probe confirms changed selection precedes the reporter's lookup, route script Error reporting through the actual `OriginalDefinitionExit` owner: call its existing private currency check before any current object/name/error-line/errorInfo read; on mismatch retain the full first cause and pass the completion through existing `finish`, allowing physical cleanup without synthesizing a frame from the child's state. For a current genuine definition, retain normal C live-name reporting. Do not soften `display_oo_bytes`, use an empty/default name, render an opaque command key, copy the original name into a child, manufacture a Native entry, or treat token equality as ownership. Deleted/renamed object saved-name parity is a distinct C requirement and is not accepted by this one-gap proposal.

**Acceptance/limits.** A repair needs this exact unchanged mode loop to execute all original calls, row/usage identities, intended codes and child/original restoration assertions. Retain the passing original constructor and public namespace controls separately.
