# Actual allocation route and bounded repair proposal

The existing stock registration route `cmd_oo.rs:495` declares the real Helpers namespace before calling bootstrap (`:539`). VM `cmd_oo.rs:1105` bootstrap allocates the original object/class roots, generates each private namespace at `:1131`, stores the namespace holder and object creation identity, then calls `install_object_helpers` at `:1153` and stores its returned token. No private namespace creation occurs between these steps. Configurable's corresponding private allocation at `:1182` / helper call at `:1204` has the same omission; the declaration at `:1203` creates the public `oo::configurable` holder, not that object's private namespace.

`cmd_oo/native_context.rs:29` installs helpers on the token returned by `definition_namespace_token`. `interp.rs:11491` / `:10408` resolve a retained token or intern a path; they do not declare a namespace. `push_ns_token` at `:11512` counts the temporary activation, and helper installation pops it. A live intern entry is therefore insufficient evidence of actual allocation.

The existing genuine creation seam is `interp.rs:11694` `declare_namespace`, through `declare_namespace_path_with_origin` at `:11663`. It inserts the actual namespace into the declaration/child tables and calls `note_namespace_created` at `:11702` only on creation, publishing lookup/cache invalidation. It rejects dying subtrees and protects nonabsolute retained owners. Ordinary `oo_new` already calls this seam before helper installation (`cmd_oo.rs:1409`); `make_class_bytes` calls its token-returning `activate_namespace_written` counterpart before helpers (`:4722`, `interp.rs:10054`).

Matching C9.1 source establishes the missing allocation, rather than deriving ownership from a label. `tmp/tcl9.1.0/generic/tclOO.c:542` `InitClassSystemRoots` passes both original roots through `AllocObject` (`:557`, `:582`). `AllocObject` allocates the actual Object, calls `Tcl_CreateNamespace` for the generated private namespace until creation succeeds (`:898-915`), increments that exact namespace's reference count (`:921`), configures helpers and deletion callback (`:928-947`), and records the creation epoch before command publication. Configurable uses `Tcl_NewObjectInstance` (`:739`), which reaches the same `AllocObject` (`:2120`). Its current C creation epoch is 19; copying that epoch/name into the VM is not proposed.

The C lifecycle holds the actual namespace pointer: command deletion calls `Tcl_DeleteNamespace` (`tclOO.c:1107`), `ObjectNamespaceDeleted` performs object teardown (`:1387`), and the retained reference is released before clearing the pointer (`:1584-1585`). VM objects already store the exact `namespace_token`; `teardown_original` passes that token to the existing cleanup owner's `retire_namespace` (`cmd_oo.rs:2870-2889`), and command deletion reaches OO destruction (`:2987`). The central namespace teardown removes only that token's published tables and supports active-frame deferral (`interp.rs:13046-13208`). The cleanup owner's forwarding implementation lies outside this three-owner inspection; this proposal does not claim fresh lifecycle parity proof.

Retained C oracle: `rust/tcl-vm/tests/data/native_oo_bootstrap_capability/v3/9.1.0/receipt.json` reports provider/version 9.1.0, compile/process exits 0. Current `tclOO.c`, `v3/probe.c` and `9.1.0/stdout.tsv` hashes exactly match that receipt. Probe `snapshot` observes the actual lookup Object, `Tcl_GetObjectNamespace(object) == object->namespacePtr` (`probe.c:107`), and its namespace/helper path (`:121-122`). Rows `OBJECT_ROOT`, `CLASS_ROOT`, `CONFIGURABLE` each report `public_namespace_same=1`; private namespace rows have the Helpers/oo path. This retained probe observes actual pointer identity, but does not independently test `Tcl_FindNamespace` equality or post-deletion incarnation behavior.

## Proposed production change, unimplemented

Own only `cmd_oo.rs`. Immediately after each bootstrap-owned `fresh_obj_name` allocation (root loop and configurable allocation), call `vm.declare_namespace(&format!("::{private_namespace}"))` using the corresponding owned holder variable, before inserting the Object and installing helpers. The two call sites create all three actual private namespaces through the existing central allocation seam. Preserve generated holders, object/cache allocations, creation identities, original interpreter/provider selection, arguments, helper paths and command publication. Retain the token obtained after creation in the existing Object field, then use the existing exact-token lifecycle.

This creation belongs to the actual bootstrap object birth. Do not add declaration to `install_object_helpers`, change token interning, relax the Name target predicate, add a new Native entry, publish from a later failed guard, or manufacture a namespace owner from an incoming token/string. Do not change counters or copy C private names/creation epochs. Generated-name collision parity and broader object-retention semantics remain separate unless an actual unchanged control exposes them.
