# F5 capture and decoding tools

These are maintained entry points. Their historical source versions remain in
the indexed store, under their original paths, for existing observations.

| Tool | Role |
| --- | --- |
| `campaign.py` | Portable-pattern or broader-context campaign; retained source, ownership guards and context selection |
| `appliance.py` | Ordered native cross-rule calls, argument bytes and provider mutation |
| `persistence.py` | Stateful worker-owned cells and lifecycle phases |
| `namespace_owner.py` | Namespace/procedure-owner observations |
| `literal.py` | Literal loader acceptance, distinct from dynamic dispatch |
| `apl.py`, `browser_receipt.py` | APL renderer measurements and independently retained browser receipts |
| `capture.py`, `cases.py`, `broader_cases.py` | Source preparation, invocation and separate load/setup/lookup captures |
| `parse_capture.py`, `report.py` | Versioned log/chunk decoding and scoped results |
| `register.py` | Prepare reviewed proof descriptions; registration is separate from execution |

Capture outputs go to `../runs/generated/<run>`. Use each entry point's `--help`
for its context and fresh run selectors. Appliance execution requires an explicit
`BIGIP_PROBE_SSH_TARGET`; an optional `BIGIP_PROBE_SSH_IDENTITY` selects local key
material. `BIGIP_PROBE_ADDRESS` supplies the materialised virtual address from
`bindings.json`. Transport identity/path and fixture addressing are replaced in
receipts, with the redaction categories recorded by the capture tool.

Keep client, hosted/iRule server, backend and query roles from the selected
driver. An HTTP response generated by an iRule proves no origin-server exchange.
Stateful phases keep their predecessors and ownership checks. After review and
sanitisation, pack generated captures with `pack-oracle-evidence.py` and rebuild
the question views. The [store instructions](../captures/README.md) give the
update procedure; packing itself performs no sanitisation.
