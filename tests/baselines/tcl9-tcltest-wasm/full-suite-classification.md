# Tcl 9 full test suite — WASM runtime classification

Every upstream `.test` file under `tmp/tcl9.0.3/tests/` (168 files) compiled to WASM via `compiler/codegen/wasm/` and executed under wasmtime against the Zig runtime (`runtime/zig/`).  Bundling and execution use `scripts/dev/run_tcl9_wasm_core.py`; this table is regenerated by `scripts/dev/gen_tcl9_wasm_classification.py`.

> This is a **classification artefact**, not the regression gate. The enforced ship-gate stays scoped to the 68-stem core slice in `summary.json` (see `README.md`).  The per-stem `categories/<stem>.toml` files carry the same classification in machine-readable form.

> **Run envelope.**  This full-suite sweep used a tight per-stem cap (45 s wall / 30 s WASM watchdog) so the 168-file run stays tractable. A few CPU-heavy *core* stems (`cmdAH` — 5133 tests, `expr`) therefore show as `W0-timeout` here but complete cleanly under the gate's 180 s envelope; trust `summary.json` for their real floor.

## How to read the classes

- **real-mismatch** — the runtime is wrong.  C Tcl's error strings and stack traces are the contract; a divergence here is a bug in `runtime/zig/` or `compiler/codegen/wasm/`.
- **w9-internal** — the test asserts something about the interpreter's internal data structures (object representation, refcounts) or the generated bytecode (disassembly, `info frame` line tables, `info cmdcount`, the `tcl::test` C extension).  These can never match a from-scratch runtime and are skipped by design.
- **deferred-wasi** — the capability is simply absent under WASI (real sockets, threads, fork/exec, a writable filesystem with stat, dynamic load, zipfs, timezone data).  Tracked, not gated.
- **harness** — the bundle produced no tcltest summary or trapped during bootstrap; not a runtime correctness signal until the harness gap is closed.
