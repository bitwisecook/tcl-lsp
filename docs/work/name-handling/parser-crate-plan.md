# Shared parsing libraries for Tcl

Use one owner for each grammar and each observable spelling. Give the LSP, compiler, registry, VM, standalone runtime and tools access to that owner at the lowest layer that has the required inputs. The highest-value first change is to route optimiser folds through the command implementations already used at run time. Moving modules between crates comes after proving that the consumer can use the same contract. See the [production findings and oracle evidence](parser-audit.md) and the [existing owner map](../../design/contracts/shared-utility-contracts-rust.md).

## Crate decisions

The owner authorised implementation of the three extraction targets on 19 November 2026. Existing crate names below identify real dependencies. Start each extraction as a module boundary on `work`. Keep the current public API as a forwarding export during migration, migrate one consumer family at a time, then remove the old implementation. An extraction is ready when the proposed crate can build independently and two consumers use the same semantics. A host adapter may retain object lifetime, mutation or location bookkeeping.

| Library | Responsibilities and API boundary | Dependency implications |
| --- | --- | --- |
| Existing `tcl-core-types`, `tcl-dialect` | Keep counted names/opaque identities and dialect point, source grammar, logical invocation and engine policy as explicit inputs. Pass only the relevant policies to each reader. A missing policy produces an unavailable result. | `tcl-core-types` is a leaf. Keep registry lookups, host objects and compiler state out of these crates. Package versions in Tcl programs have a different grammar from the product version in `tcl-version`. |
| Existing `tcl-lexer` | Own source images, byte spans, original words, script/command boundaries, variable and command substitutions, nested script cuts, expression lexing, completeness and incremental reparse boundaries. Return original spans alongside decoded pieces where the mapping is defined. | Depends on core types and dialect. Both the full compiler CST and standalone runtime can consume its command/word stream. Preserve Jim's separate grammar and edit-time partial results. |
| Existing `tcl-syntax::naming` | Qualified/scalar/element names, decomposition and construction, namespace separators, written versus evaluated names, relative qualification and element boundaries. Keep the current shared owner. | Lookup uses a namespace, table and frame; binding and lifetime stay above syntax. A spelling alone cannot prove the identity of a variable, command, alias, class or object. |
| **Extract `tcl-value-syntax`** | Extract counted string/character access, byte decoding, list iteration and writing, concat, quoting, dictionary pair decoding, and output-origin policy from `tcl-syntax`. Give tooling spans as well as decoded bytes; expose iterator and writer paths so a simple length or lookup need not allocate all elements. `split` on characters and command `join` remain command semantics over this substrate. | Start with explicit escape/encoding inputs from dialect, shared lexer escape primitives, and core types. Audit `list.rs` links to string/value modules first. Move the dependent subset together or pass in a policy. Re-export from `tcl-syntax`; the new crate must never depend back on that facade. Keep native object mutation, traces, refcounts and cached internal representations in the engine layer. |
| **Extract `tcl-numeric`** | Extract integer/float/bignum/boolean reading and writing, radix and width selection, coercion, overflow, NaN/Inf, and conversions needed by expression, index and format. Expose full consumption and the selected error, plus exact canonical output where defined. | Start from `number`, `number_tower`, `scalar_getter` and the numeric policies in `tcl-dialect`. Distinguish numerical value from native object getter effects. The portable reader can consume counted bytes; platform rounding/formatting policy stays explicit. Never infer Tcl integer syntax with Rust decimal parsing. |
| **Extract `tcl-expr`** | Extract the expression AST, operator grammar, precedence, validation and pure evaluation surface. Provide source spans for operators and embedded substitutions and a callback interface for variable, command and math-function resolution. The LSP can inspect the tree without executing it. | The current parser uses the lexer, number policy and naming. First isolate that naming dependency in a small interface or leave the parser in `tcl-syntax` until extraction is acyclic. Then depend downward on lexer, numeric/value primitives and a leaf naming interface. Registries select functions. Hosts perform substitutions and report frames. |
| Existing `tcl-regex`; glob in `tcl-syntax` | Keep the C ARE and Jim regexp implementations and their different flags/offset contracts. Add read-only pattern token/span access for highlighting and diagnostics. Share glob pattern tokens with consumers of the *same* glob grammar. | `tcl-regex` already has an optional command-core adapter. Put the `regsub` replacement reader behind the shared command API or in a lower pattern module. Keep the core's engine trait to avoid a mandatory dependency cycle. Filesystem path globs retain their filesystem semantics. |
| Existing `tcl-registry` | Own selected command grammar: option lookup/abbreviation, `--`, reserved trailing operands, argument roles, command prefixes, clause plans, callbacks, package/extension availability and authored dialect metadata. Expose selected roles with original operand indices and unknown/dynamic residuals. | Depends on syntax and command semantics today. Compiler and tools consume data describing the genuine selected command. An LSP display candidate carries no authority to execute or edit. No downstream reader should independently reverse-engineer a command's option table from source strings. |
| Existing `tcl-cmd-core` | Authoritative operations over values: split/join/list/dict/array commands, indexing, sort/search comparison, string and binary operations, format/scan, regexp replacement, and completion-option handling. Expose typed, bounded literal evaluation to the registry wherever the selected semantics are known and pure. | Command implementation and its literal evaluator share error and serialization paths. Preserve the context for operations that can call script, observe a trace, or depend on object history. Decline a fold when those facts are missing. |
| Existing `tcl-runtime-api` plus a shared `frame_level` module in `tcl-syntax` | One reader for *a supplied level word* under selected numeric/level rules. Registry owns the earlier decision that a word is a level for this invocation. Runtime API owns interpreter, frame, cell, namespace, error stack and continuation identity; VM and runtime supply activation and storage. | `tcl-cmd-core` and `tcl-runtime-api` already depend on syntax. Extract the pure input classification to that lower layer. Keep actual frame walking, re-entry, coroutine switching, and partial effects with the engine. Keep `return -level` a separate option operation. |
| Existing `tcl-bytecode`, compiler and codegen | Keep opcode/operand layout, literal pools, jumps, line maps and verification in bytecode. Compiler owns binding, IR, proof, recovery CST and source-to-IR provenance. Codegen consumes selected operands/proofs. | Bytecode immediate selection can reuse numeric/index readers; decoding an instruction is a different operation from parsing Tcl text. Preserve direct, compiled and sourced-file execution when comparing error stacks. |
| Existing package and domain libraries | Keep Tcl packages/versions and manifests in their package owners, SpecTcl in its loader and source grammar, BIG-IP/tmsh/APL in `tcl-bigip`, iRules semantics and host hooks in their owners, query DSL in `tcl-bigip-query`, and SslicTcl's configuration languages in `tcl-sslictcl`. | Embedded Tcl crosses the boundary as a source slice with the correct entry policy. For browser and editor clients use the existing server, WASM or host adapter, or generate vocabulary from the owner. A second implementation in TypeScript, Kotlin or a generated grammar must not decide proof-level answers. |

### First public interfaces to migrate

| Consumer request | Starting interface on `work` | Adapter work |
| --- | --- | --- |
| “Return each original word of this nested script” | `tcl_lexer::script::group_commands` and `native_script_words_in_with_purpose` | Expose a shared cursor query for an original word, including a delimiter inside a braced word. Carry the same source image through the LSP and compiler. |

Use explicit command semantics for string split/join; compare C and Jim representation. |
| “Decode dictionary pairs or look up a value” | `canonical_dict_slots`, `tcl_cmd_core::dict::get_using` and `merge` | Keep source-pair order and canonical lookup available separately. Decide when to return original text from the actual command operation. |
| “Parse a numeric operand or expression under this policy” | Native scalar getter, `tcl_cmd_core::index::read_under`, `parse_expr_with_syntax_context` | Offer a span-preserving inspection path and a strict evaluation path with actual function bindings. | “Where is the variable or command addressed?” | `tcl_syntax::naming`, `FrameEffectSpec::resolve_arguments`, native frame protocol and runtime frame API | Return a syntactic address for static consumers; resolve a live activation only in the actual interpreter. Lookup, completion and rewrites have different proof requirements. |

## Grammar inventory and consumer contracts

This table covers the distinct operations a caller might describe as “parsing”. Each row gives the direction that is easy to overlook and a discriminating case for its migration. The named API may require a new projection. The individual verified faults are in the audit.

| Family | Owner today or first destination | Required distinction and acceptance case |
| --- | --- | --- |
| Source encoding, bytes, NUL, offsets and line maps | `tcl-lexer` source image/map; `tcl-syntax` raw/native string; LSP protocol conversion at the edge | Preserve original byte offsets through decoding, escaped characters, UTF-16 editor coordinates, BOM, NUL and invalid/non-UTF-8 native input. Count bytes, code units or characters as the selected operation requires. |
| Backslashes, escapes and continuation | `tcl-lexer::substitution`, `tcl-syntax::backslash` | Braced words, quoted/bare script words, list elements, replacement strings and a host encoding can all interpret the same slash differently. Test backslash-newline in each context and release-specific escape widths. |
| Script → commands → words → parts | `tcl_lexer::script`, native word owners; compiler segmenter/CST as client | Cover comments at command start, newline/semicolon, quote at word start versus mid-word, braces, expansion, adjacent substitutions and nested bodies. Preserve both source range and evaluated word. |
| Incomplete scripts and editor recovery | `script_is_complete`, `first_parse_cut`, structural index, compiler recovery | A partial open bracket has a completion answer and can have display spans. Proving a command ran needs the reached prefix. Compare incremental edits against a full parse and Tcl completeness where applicable. |
| Source variable and command substitution, `subst` | Lexer word parts, Jim script/subst owners; registry `option_effect` | Distinguish one substitution from a compound word, handle embedded scripts and option abbreviations before the reserved operand. Test `subst -noc {…}`, a script operand named `-nocommands`, an escaped dollar, and a literal non-breaking space beside `[id ok]`. |
| Strings, codecs, Unicode, trim and comparisons | Native string/raw string and trim owners; cmd-core `string`/encoding | Distinguish source spelling, list rendering, case mapping and native character semantics. | Qualified names, namespaces, commands, aliases and ensembles | Naming owner, registry selection, runtime namespace/command identity | Join/split exactly according to the requested purpose. | Call frames, stack levels, scope, coroutines, errors and completions | Registry frame effect; cmd-core frame/return options; runtime API call/error stacks | Distinguish relative `0`, absolute `#0`, default level and the first script operand. | Integers, floating point, booleans and indices | Dialect numeric policy; syntax number/coercion; cmd-core index, list and native protocol owners | Cover `010`, `08`, sign, base prefix, whitespace, widths, bignum overflow, negative zero, NaN/Inf, integer-looking decimals, `end-1`, nested `-index` lists and Jim's expression indices. | Expression operands, operators and functions | Lexer expression tokens; `tcl-syntax::expr`; registry math-function selection → expr crate | Braced versus unbraced `expr`, quoted operator text, substitutions, laziness/short-circuit, conditional operators, mathfunc lookup and errors. | Command options, subcommands, switches and script roles | Registry option, invocation and clause grammars; cmd-core selected behaviour | Respect exact/unique/ambiguous abbreviations, selected release, first/last repeated option rules, `--`, dynamic words and captured prefix arguments. ## API contracts to settle before extracting a crate

- A reader accepts a counted original source slice or an evaluated value with an explicit grammar. Return the consumed byte range, the raw spelling, and decoded bytes when available. Make components borrowable. A literal editor range may be used for edits only when it still maps to that original source.
- Represent complete success, malformed input (with the native error and offset when known), a recoverable partial result, and unknown policy or value as distinct outcomes. A malformed list must not become an empty list; a dynamic package or unknown binding supplies no command semantics. Keep recovery entry points separate from strict proof entry points.
- A writer takes a **purpose**: list element, whole list result, command word, prefix script, or a dialect-specific result spelling. For example, parsing and writing `{a 1 a 2}` as a dictionary can change what `puts` observes. Only an explicitly supported operation may preserve or discard that representation. Test exact originals, canonical output and `read(write(value))` at the intended layer.
- A command query receives original argv, selected binding, dialect and entry state. A grammar describes operand roles, arity and spans. A strict evaluator additionally checks runtime availability, side effects and representation. Keep display, reachability and rewrite consumers on those separate interfaces.
- Frame and namespace resolution receive the active interpreter, namespace/command table and applicable frame; source-only clients may carry symbolic facts instead. Cache keys include each input the answer depends on. Compare a fresh parse/lookup with incremental reuse after a dialect flip, alias rebind and package load.
- For original scripts, stack frames and diagnostics, retain the execution mode and source identity through the reader. A compiled syntax error and an executed error can have identical result text but different line/frame information.

Other command-specific operand grammars belong with the command owner. `trace` legacy operation letters and modern operation lists already have distinct readers in [trace.rs](../../../rust/tcl-cmd-core/src/trace.rs). Channel translation and encoding pairs are in [channel.rs](../../../rust/tcl-cmd-core/src/channel.rs); clock units, zones and format arguments in [clock.rs](../../../rust/tcl-cmd-core/src/clock.rs). File permissions, package requirements, interpreter paths, `after` callback prefixes, Tk bindings and options, and regexp replacement templates each need their own fixtures when first migrated. An architect choosing between a new crate and a module should trace both the smallest valid input and one invalid or release-dependent input through the real consumer.

## Migration sequence

1. **Stop the wrong rewrites.** dataflow-optimiser owns the literal folds and values reviews their strict inputs. Drive the optimiser through its normal entry, execute the original and rewritten scripts on each applicable oracle and compare completion/output/error and exact displayed list/dict text. Include direct `puts`, nested substitutions and an unchanged-call control. Separate product fixes from retirements of duplicate tests.
2. **Repair externally visible parsing.** lsp-features owns hints, semantic spans, code actions and BIG-IP document symbols. Tooling owns Spec Studio, SpecTcl nested lists, APL embedding and CLI package paths. Use public editor/loader/build entry points. Keep a positive and negative case per grammar, use a shared fixture when multiple layers expose it, and keep an end-to-end witness where integration can lose a span or select the wrong profile.
3. **Remove proof-path re-parsers.** analyser-binding, diagnostics and values migrate substitution/variable reads, TclOO receiver words, path and child-interpreter keys, and cache dependency scans. Use actual variable/command identity and source maps. Run the strict optimiser, rename/refactor/reference consumers and incremental-versus-fresh comparisons. Count a false refusal separately from an unsound acceptance.
4. **Join VM and runtime consumers.** execution owns typed conversion adapters, object/string boundaries, frame argument classification, source-file error frames and list-element locations. Compare VM, runtime and oracle with the same entry, including direct/file/compiled paths. On F5 use the 9.1 physical simulator and installed authored hooks. Attribute remaining device-dependent semantics in the ledger.
5. **Introduce the library boundaries.** Begin with value-syntax and numeric modules, then extract their crates behind forwarding exports after eliminating cycles. Follow with expression syntax once naming and numeric dependencies are isolated. Keep names, spans and decoder lifetimes stable for existing callers. Measure native and WASM builds and allocation-sensitive paths (large lists, deeply nested scripts, repeated incremental queries). Keep the existing owner when moving a crate would add a dependency without removing a second implementation.
6. **Close the migration per family.** The area owner records source, consumer, selected policy, tests and independent reviewer in the [scrub](../test-scrub/README.md). Run the C/Jim matrix with all required flags, `cargo fmt`, `cargo clippy --all-targets` and `make xtask-gates` on the rebased head. Extend `owner-resolution`, `segmentation-drift`, `number-drift` and registry gates for specific retired readers and their proved replacement. Include standalone runtime and feature-gated WASM callers in coverage. Keep intentionally different scanners only with their purpose and a differential corpus. A gate that recognises a spelling cannot establish equivalence by itself.

## Coverage and sign-off

The [family register](parser-coverage.tsv) gives each grammar an intended owner, a concrete starting fixture and the work still needed. A fixture proves only the cases it exercises. All rows opened with the implementation request. To close a row, record the reviewed source revision, owning API, callers in each shipping product, applicable oracle results, and the checks that would catch a second implementation. Record a reason and evidence for each inapplicable caller or dialect. Keep device observations in the [F5 ledger](bigip-name-checks.md).

The [direct and default caller register](parser-callers.tsv) opens with 224 individual call occurrences on combined revision `e1caf3e94d` and additional sites found by following their callers. The first scan grouped these into 208 rows. This includes calls where selected dialect provenance still needs tracing. Reviewers must trace the data reaching each caller and record the owning API and test or the reason a different grammar applies. The occurrence number distinguishes repeated calls to the same target within one method. A traced row records a source inspection and can still contain a known defect or an unverified behaviour. The verification column states the remaining check. Reconcile this list on each migration, including moved and newly discovered sites.

Run `cargo xtask parser-ownership --report` on the revision under review. On `e1caf3e94d` the wider pass inspected 6,227 Rust source trees, including the standalone runtime. It reported 5,557 functions for structural inspection, 919 uses of host parsing operations, and 616 foreign source entries. Each item is a review lead. Looping over data and parsing Tcl have different dispositions. For generated and bundled assets, trace the generator, source and embedding rule. A wrapper can be accepted only with its selected grammar and reachable caller established.

Use the all-files inventory alongside Cargo targets/features, standalone manifests, build scripts, generated grammars, packaged files and embedded-language boundaries. Trace host-language scanners, regular expressions, splitting, joining and manual byte/character loops to their inputs and consumers. Follow data into delegates and generated artifacts. Check a deliberately introduced private scanner, a forwarding adapter and a genuine host-language parser when validating the ownership gate. A newly tracked source or a previously unseen grammar requires review.

## Source census and limits

From the checkout run:

```sh
python3 docs/work/name-handling/validation-tools/parser_census.py
python3 docs/work/name-handling/validation-tools/parser_census.py --sites > /tmp/tcl-parser-sites.tsv
python3 docs/work/name-handling/validation-tools/parser_census.py --files > /tmp/tcl-parser-files.tsv
python3 docs/work/name-handling/validation-tools/parser_census.py --cargo-targets > /tmp/tcl-parser-targets.tsv
```

The [census](validation-tools/parser_census.py) lists components, source files, reader/writer declarations, common host parsing primitives and known shared-owner calls. The second command emits a file and line for each lexical lead. At the reviewed revision it scanned **6,772 files across 73 component groups** under `rust`, the separate runtime, editors, grammars, scripts, AI and spec roots. It reported 2,375 declaration matches, 1,051 host-primitive matches and 1,299 owner-call matches. These are line matches, not counts of implementations or defects. Configured source suffixes and exclusions are in the script. Inline test modules and some generated inputs can still match. The counts exclude generated tree-sitter C parsers and vendored sources. TextMate assets, tree-sitter injection queries and associated generator ownership were also examined separately.

The six area reviewers traced production consumers and negative controls. Database queries, engine adapters and editor clients often receive an already parsed object or delegate to the server. Preserve that direction. External libraries, all third-party dialect packages, every Cargo feature combination and real-device behaviour have not received an exhaustive execution pass. The candidate index makes those boundaries and further manual review reproducible. The verified cases in the companion audit are the starting backlog, not a certificate of parity.
