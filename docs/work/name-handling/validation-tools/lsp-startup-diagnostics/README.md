# Hosted native startup diagnostic

Temporary `work` evidence tooling. Dispatch `Performance` on `work` with mode
`lsp-startup-diagnostics` and `runtime_sha` equal to the full workflow commit.
The checkout must be that exact commit. Root alone integrates and dispatches.

An empty external target builds the current selected native server with the
`ci` profile and strict Rust warnings. Cargo must emit one successful fresh
binary event and no warning/error messages. This measures compilation for that
binary only. It grants no eight-package/all-target typecheck, editor-host,
shipping-profile, latency or release acceptance.

The original typical v3 and two-folder Context v5 worker bodies are preserved.
Context's fixed local checkout path is replaced with the explicit hosted root;
AGPL comment headers are added. See `original-protocol-provenance.json` for
original hashes. Request/scan30s, Context initialise30s/configuration15s/
diagnostics6s and each original worker180s remain unchanged. Current coarse
reload observers are enabled. An ordinary semantic failure remains a failure
while the separately owned Context worker may still run; a process, capture,
input or artifact failure stops continuation.

The reviewed `runtime-diagnostics-exec.py` owns each subprocess group. Locked
native Cargo fetch has a separate600s housekeeping limit, build2400s, then
two workers180s each. The70-minute job bounds setup, hashing and cleanup too.
Each owned command monitors a2GiB disk floor. Aggregate build/fetch/worker
stdout/stderr and server wire logs share20MiB. Limit exhaustion is incomplete
evidence. Worker `-B` avoids generated bytecode altering their input seals.

Receipts bind the exact tracked checkout; original client, sampler and editor
fixture inputs; compiler/native tools and versions; Rust sysroot libraries;
the full fetched Tcl9.0 provider tree; and fetched Cargo registry/cache/git
sources sealed before build. Current dependency/source/provider/tool/server
hashes are checked again before runtime and at closure. Native workers verify
the actual running server image and inherited owned process group.

Upload uses an explicit evidence file list. Cargo targets, Tcl source trees,
materialised worker sources and generated workspace fixtures are excluded;
JSON hash maps and bounded original wire logs preserve their evidence.
Missing receipts or false final seals do not establish acceptance.
