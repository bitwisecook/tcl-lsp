# Decision needed: authenticated complete-report comparison

Prepared after actual current TEMP3 closure; this is a proposal, not an implementation or equality proof.

The current required gate compares the complete `AnalysisResult` with its existing equality operation. Three unchanged assertions failed on the same current compiler artifact, with source/provider equality and no warnings: aliases (22.78s) refused report capture in both analyses at `declaration-site-count`; E003 (10.11s) had two present/current reports but its first diagnostic's NativeSource arity subject differed in `analysis_owner` identity; hosted HTTP collect (23.58s) refused both report captures at `unsupported-source-domain`. The alias trace establishes `count != 1`, not whether the count is zero or multiple. It is not permission to drop the count guard. The E003 trace found all other emitted issuer fields equal; it is not a complete source-correspondence proof. These observations concern these three actual fixtures, not the full perf corpus.

Proposed choice: authorize a distinct **authenticated complete-report comparison** operation, called only by the perf/report harness. Keep global `AnalysisResult` equality, typed runtime-owner equality, Salsa cutoff, cache currentness and host eligibility strict and unchanged. Independent actual owners remain different runtime owners. The new operation would compare every report field and typed diagnostic subject, using a separate correspondence only where both real current analyses supply complete, unique actual source/input/registry/body-owner issuers. It would never use Debug output, advisory names, equal bytes alone, numeric IDs, pointer normalization or omitted fields as a substitute for that correspondence.

The operation must return `Unavailable(reason)` if any required carrier, field purpose, owner correspondence, inventory completeness or unique mapping is missing, stale, unsupported or ambiguous. Unavailable must fail the perf equivalence gate; it must never mean equal. A valid operation returns Equal only after every field is compared, or Different with the first actual field mismatch. Existing strict runtime identity is neither rewritten nor discharged by a report correspondence.

This requires real implementation work: inspect the alias declaration-site count and correct only an authenticated count/producer defect under existing policy; supply a genuine hosted-domain report carrier with all applicable debts/currentness checks rather than removing its exclusion; issue explicit typed diagnostic-subject report correspondence rather than weakening its Native source owner. A comparison result cannot grant compiler visits, physical entries, normal completion, reaching cells, callable targets, quiet effects or host admission.

The acceptance contract changes explicitly: the perf gate currently requires full `AnalysisResult ==`; after authorization it would require a successful complete authenticated report comparison for every all-old and mixed-engine result, while retaining evidence of strict runtime/global equality outcomes separately. Existing failed equality assertions must not simply be inverted or removed as a purported repair. Add separate operation tests for Equal/Different/Unavailable, independently genuine analyses, each report field and subject, malformed/missing/duplicate/stale/foreign owner and changed input/config/registry/body cases; preserve strict runtime/global-identity negatives. Re-run the complete actual all-old and mixed corpora before accepting or forwarding any perf patch. No current equality proof exists.

Alternative: retain the present full-equality acceptance gate and leave the perf patch withheld while these failures remain. No new comparison operation or hosted eligibility is authorized by that alternative.
