## How it was measured

- **Gate harness.** The gate ran unmodified through the same symlink harness as the gates agent, with `syn` 3.0.9 and `rustc_lexer` 0.1.0 from its lockfile. Root disk had 1.8–1.9 GB free, below the 2 GB build floor, so `CARGO_TARGET_DIR` was put on the `/dev/shm` tmpfs (16 GB, RAM-backed). This uses no root disk. The targets are about 25 MB each and were deleted at hand-back. xtask itself was not built.
- **Consumer finder.** This is a scratch copy of `source_internal.rs` with a driver added. For every failing entry it loads the owner crate exactly as the gate does and finds the owner's module and declaration. It then tries every function, method and type in every **other** module of that crate whose body names the entry. For each one it runs the gate's own `check_row` with routes `static`, `type`, `signature-type` and `self`. A probe also records the receiver origins the gate computes, and each one is retried as a `parameter:` / `field:` / `producer:` route. Only routes that `check_row` accepts were registered, so every added row is a fact the gate verifies, not a claim.
- **"Shared" means a consumer in a different module.** Consumers in the owner's own module were never registered. For bare method names (`formal_name_field`), the finder also tried the qualified `Type::method`. When that registered, the manifest entry was renamed to the qualified form.
- Up to three registrations per entry were kept, each from a different consumer module, so 146 rows were added (+1 retarget). An entry with more consumers keeps the first three, ordered by module path.
- **Failing registration rows.** All 83 were removed and replaced by finder-verified rows where one exists. They are listed below.

- **registered**: one or more verified cross-module consumer rows were added. "entry qualified" means the bare manifest name was replaced by the real `Type::method`.
- **retargeted**: `IndexLoader::collect_word` is now only called inside `index_loader.rs`. Its outside consumer calls `IndexLoader::collect_word_in_plan`, so the entry was renamed and that route registered.
- **withdrawn**: the entry is private or crate-internal and has no consumer outside its own module (test modules do not count). This group also includes the four entries that never existed (`VendorSourceLiteralPurpose::EventName`, `Vm::refresh_native_jim_namespace_helpers`, `Vm::namespace_unknown_subcommand`, `OriginalSourceVariableAliasOperands::namespace_target_scope`) and `NativeInvocationState::arguments`, which is public only in `experiments/`. The item was removed from its row, keeping the row's other items. Six rows were left with no entry and were removed: Reached original Jim Try names and message getters; Actual archive member path selection; conditional declared overwrite advice; supplied unindexed viewport and deep compiler input; Original Logical alias source occurrences; Original Jim namespace helper provider and diagnostic dispatch.
- **withdrawn (shared, gate cannot check)**: a real consumer outside the module exists, but the gate cannot verify the route. The usual reason is that the consumer's receiver comes from an expression the gate does not type (a `let` without a checked producer, a chained call, a closure, a glob-imported owner type). The other reasons are a generic owner (`<E: From<ValueError>>`, `<O: NativeDictionaryObjects>`), an owner that is macro-generated (`SOURCE_PRESENTATION`), behind `cfg(feature = "engine")`, or declared through `#[path]`, and owners in `tcl-registry`, which exceeds the gate's 2048-module bound. These entries are **not** claimed as checked. Each one is listed, with its actual consumer and reason, in a new contract subsection, "Shared entries the owner gate cannot check", just after the source registration table. That way the ownership fact stays in the contract.

**The three "checker limitations" from gates-NOTES:**

- `OriginalLinkedSourceSpelling::text` and `RetainedSourceModuleBindings::matches_module` were not checker limitations. These are pub methods on crate-private types, and they register normally through the source table, so both are now **registered** (`::spans` too).
- `SOURCE_PRESENTATION` is macro-generated, and its consumer is the `tcl-spectcl` crate. It was withdrawn with a documented reason, and the checker was not taught macro expansion.
