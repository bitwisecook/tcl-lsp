# Astra design review: iRules compound-string seal split (2026-10-28)

Recommendation: option (a) scoped as "one selector, not one realm" - every List/Dict producer and consumer that can run inside the authored simulation takes its recipe from InterpState::object_materialization() (or an OriginalAuthoredOperandScope); actual_native_invocation_dialect().native_string_protocol() only at physical-only sites (bootstrap, error stack, compiled-literal registration, LogicalEval's physical pin). No seal relaxation; no boundary reparse (b). Option (c) changes observable iRules semantics - a product decision; reviewer recommends against.

Cause: two selectors disagree inside one proc in one realm. LiveSession::eval runs try_eval_source (tcl-irule-test/src/live.rs:537-540); `$args` is an unsealed list (tcl-vm/src/exec.rs:4515); `lindex $args 0` via NativeListIndexOps uses actual_native_invocation_dialect() = C9 (value_ops/native_list_index.rs:62-69,144-160; interp/native_numeric_ops.rs:88) and seals C9; `linsert $args 0` via NativeIndexOps::index_list_elements uses object_materialization() = AuthoredLogical(C8.4) (value_ops/native_jim_index.rs:761-783) and is refused. Further physical sites: cmd_switch.rs:98-108, exec.rs:7479-7487/11793-11800 (tailcall), literal_pool.rs:235,649. scf_loader is the same shape on the name axis (native_variable_names.rs:55-65,1646-1671 requires NamePolicyAuthority::Native; interp.rs:3570-3577).

Recipe differences (as modelled, oracle-pinned): rendering - leading `#` in element 0 is bare in 8.4, braced in 8.5+ (tcl-syntax/src/list_result.rs:27-55; fixture native_list_result_ascii.tsv 120/2304 rows; tcl9.0.4 tclUtil.c:1101 DONT_QUOTE_HASH). Parsing - element backslash decoding (tcl-dialect/src/grammar.rs:367-397): 8.4 unbounded \x keeping the low byte, no \U, three-digit octal. Numbers are not part of the compound recipe.

(c) observable divergences: `[list #comment x]` -> 8.4 `#comment x`, (c) `{#comment} x`; `lindex {a\x4142 b} 0` -> 8.4 `aB`, (c) `aA42`; `lindex {\U0001F600} 0` -> 8.4 `U0001F600`, (c) U+1F600; `lindex {\400} 0` -> 8.4 NUL byte, (c) `\40`+`0`; also internally inconsistent with LogicalEval's Tcl84 word lexer.

(b) unsound: loses object identity/sharing and intreps, materialises pure byte arrays, forces string generation the seal prevents, drops canonical flag/empty identity; no lossless answer for literals whose parse differs.

(a) change set: (1) native_numeric_ops.rs:81-93 capture object purpose; (2) native_list_index.rs index/copy/range/member recipe from it; (3) cmd_switch.rs:98-117; (4) tailcall exec.rs sites (selector or documented unreachable); (5) literal_pool.rs:649 logical compiles (authored recipe or refuse typed list literals); (6) name axis separately - authored-aware variable-name recipe for store_original_c_array_member; (7) drift gate restricting native list/dict constructors to protocols from ObjectMaterialization/OriginalAuthoredOperandScope outside an allowlist of physical sites.
Invariants: authored realm objects sealed C8.4 or refused; host-source objects C9; sealed crossing refused, never reparsed; registry the only place naming C8.4 for the authored recipe.
Tests: VM test proc p {args} {lindex $args 0; linsert $args 0 x} logical (C8.4) and host (C9); oracle cases [list #a b] -> `#a b`, lindex {a\x4142 b} 0 -> aB vs tcl8.4.20 and 9.0 forms through ::tmm::_orig_*; negative: authored lindex on ::tmm::_orig_list result refuses; drift gate; re-enable harness_runs_the_tmm_84_surface and scf_loader_stores_parsed_snatpool_members.
