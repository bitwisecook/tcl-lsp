# Luna-32 review of Sol-28 (`original_script_words_in` shares NestedBodyCutMemo)

Verdict: **ADMIT-WITH-CONDITIONS**. The code is sound, and its results are provably identical to the unmemoised walk. The conditions concern evidence and tests, not the code.

Reviewed: `git diff` on `work`, which is byte-identical to `sol-28/sol-28-final.diff`. Static review only. Nothing was built or run, and the repo was not modified.

## 1. Image binding and purpose exactness: PASS
- `SourceOriginId::original_script_words_in` passes `self.source_image().clone()` and `self.original_lexical_projection().nested_cuts()`. That memo is the per-origin sidecar, keyed by the actual `Arc<SourceOriginKind>` pointer plus a Weak upgrade (`AllocationMemoTable::get_or_init`). The only other user of that memo, `capture` (via `original_lexical_command`), also passes `self.source_image()`. So every walk sharing the memo passes the same image. `source_image()` reads the immutable kind, so a Derived origin uses its own derived image both times. No decoded or foreign image reaches this memo.
- The memo has two further safeguards. `NestedBodyCutMemo::bound_to` checks `SourceImage ==`, which compares the full bytes and the channel, and bypasses the memo on any mismatch. `first_parse_cut_region_in_checked_with_memo` anchors only when the local bytes equal `whole[origin..]` and the channels match. In `capture_native_script_words`, `local` is always `from_bytes(region bytes, image.channel())`, so these checks always hold.
- **Purpose:** the key is `{whole-image span, LexerConfig, channel}`. The `LexerConfig` is the walk's `parse_config`, which equals `purpose.config(config).normalized()` with `strict_quoting=false`, and with `leading_bom=Content` when `region.start != 0`. A body walk (`body_frame` → `NestedScript.config(top)`, `content_part_frame`, word jobs) reads only the body bytes, that top config and the channel. `base` and `report_at` affect only the offsets of a cut, never a clean verdict (covered by `nested_body_memo_keeps_the_variable_index_reporting_anchor`). `descent` is always `RecursiveCommands` under an anchor, and the memo is skipped before lookup under `EnclosingScript`. So a purpose can influence the walk only through `parse_config`, which is in the key. WholeInput and NestedScript keys therefore differ unless their `parse_config`s are equal, and when they are equal the computation is identical. No verdict can be valid under one purpose and wrong under another.
- **Call-site equivalence:** the root plan used `native_script_words_in`, which is WholeInput, and is now explicitly WholeInput. `BodyWalk::script` was NestedScript and stays NestedScript. The origin, config and region are unchanged. The memo path (`first_parse_cut_region_in_checked_with_memo`) and the plain path (`first_parse_cut_image_in_checked`) both reach `first_parse_cut_channel_in_anchored(..., RecursiveCommands, anchor)`. They differ only in the anchor.

## 2. Never recording cuts or unreadable streams; first-cut ordering: PASS
- `record_clean` runs only when a body's `Frame::Words` runs out of jobs, which means every child frame popped without a cut. Each of these returns before that pop, so the body is never recorded: a `Cut`, a `ParseError` component, a `Parts` fallback (unterminated quote), `WordJob::Unavailable`, a `lex_and_group` `LexicalStream` error, or a `SourceGeometry` error.
- Skipping a recorded body is a deterministic no-op, because a re-walk would yield no cut and no `Err`. The first cut, its term, its kind, its `report_at`, `fatal_tail` rebasing and the word geometry are therefore all unchanged. Plan construction (groups, tokens, extents, words) does not depend on the memo.
- The `MAX_DEPTH` guard in `BodyWalk::script` is untouched. The lexer walk keeps its documented lack of a cap, so no cap is changed.

## 3. Concurrency and ownership: PASS
- `NestedBodyCutMemo` consists of a `OnceLock<SourceImage>` and a `Mutex<HashSet<Key>>`. Each lock is held only for a single `contains` or `insert`, and never across lexing. `Frame`'s `Rc` stays inside one `drain` call. Concurrent walks can at worst duplicate work, and inserts are idempotent. Poison recovery is pre-existing and harmless here.
- `original_lexical_projection` takes the global `MEMOS` lock, which is pre-existing weak-sidecar state, not new global state. It releases that lock before returning, so no lock is held during the walk. Nothing in `native_compilation_source` calls back into advice, so there is no re-entrance into the projection's `OnceLock` init.
- Lifetime: the memo is owned by the origin's sidecar and is retired when the owner dies. No test inspects the sidecar table's size, and `trace_counts` counts only `capture`, so creating new sidecars from advice walks does not change those predicates.
- Performance-only note (not blocking): every `BodyWalk::script` call now takes the global `MEMOS` mutex, which runs an O(live origins) `retain`. This could contend under parallel analyses. If profiling shows contention, hoist the `Arc<OriginalSourceProjectionMemo>` once into the walk context.

## 4. Sol-28's evidence: verified, with caveats
- I recomputed the before/after comparisons (`cut -f1,2 | sort`, then `diff`). The status sets are identical for `compiler` (191), `core` (102) and `lexer` (25), which total 318, and also for `lexer2` (90). The `.list` files are identical. `compiler-v2` and `core-v2` also match their baselines.
- **Provenance:** the "after" runs (09:02–09:17) used `memo-v1.diff`, which has the same code as the final diff apart from the doc comment and the proof-doc sentence. `sol-28-v2.diff` equals the final diff plus `word_expr` and `token_word_span` hunks that were later dropped. I could not recheck which binaries were used, because `sol-28/bin/` is now empty.
- **Caveat A:** the comparison is by status only. 54 compiler selectors are not PASS (50 FAIL, 3 stack overflow, 1 timeout) in both runs, and 49 of the 169 `source_transition_advice` selectors are among them. That is the directly affected area. FAIL==FAIL does not show that the failures are identical.
- **Caveat B:** the lexer suites are only controls, since `tcl-lexer` is unchanged.
