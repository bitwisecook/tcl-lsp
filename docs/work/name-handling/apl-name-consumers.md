# APL variable names

The APL convention owner in `tcl-bigip::apl::variable_names` serves the public converters, model export reports and iApp source diagnostics. It projects dotted presentation fields to double-underscore variable labels. Reverse projection uses shared counted colon geometry, preserves lone-colon data, and declines namespace-qualified roots and empty simple components. Actual reference extraction requires an explicit root marker; relative convention-like reads cannot establish an appliance global and leave absence coverage partial. Conventional rooted export strings are reports; they do not establish source addressability, native variable cells or appliance publication.

Configured extraction consumes `tcl-irules::original_hosted_source_variable_references` under the original selected profile, Registry context and full LexerConfig. The existing analyser retains genuine original words and Registry source-body roles. Original lexical components and selected expression syntax supply reference spans. Comments, escaped dollars and inert braced data are not substitution reads; arbitrary braced words are not entered as scripts.

`IappSourceReferences` separates positive candidates from absence coverage. The current closure covers valid flat source with original selected cell routes and no unknown/computed/nested entry. Positive original candidates can still inform undefined-field diagnostics when source coverage is partial. Unused-field diagnostics require `complete_references`; a missing implementation, unknown source route or partial coverage does not prove a field is unused. LSP sibling-source and BIG-IP report callers pass the registered `f5-iapps` profile/context/config; report evidence records partial source when absence coverage is unavailable. The slice-returning convenience extractor is a compatibility report of positive candidates, without a coverage guarantee.

Original C Tcl 8.4–9.1 and latest Jim source controls are retained in `experiments/name-handling/apl-source-variable-geometry`. The BIG-IP publication questions are in `experiments/name-handling/apl-source-variable-geometry/f5-questions.md`. Source geometry tests do not establish iApp export rules; appliance result documents must retain actual declaration, input, interpreter/context, status and output before those rules become conformance tests.
