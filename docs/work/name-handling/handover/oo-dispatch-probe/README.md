# TclOO, class-system and dispatch probe

Fixtures behind queue items 2 and 3 of the [signed scan and precedence handover](../signed-scan-precedence.md). `bodies/` puts a signed-byte comparison and a precedence hazard in every body form; `variables-lookup/` does the same for one variable read per scoping context (the probe also asks references and rename), and `variables-flow/` holds analyser-only flow cases. `namespaces/` holds namespace-operation fixtures (engines and analyser diagnostics) and `namespaces/nav/` navigation fixtures (`;# CALL word`, cursor on the word's first character). `frames-semantics/` holds frame and level fixtures run through tclsh, the VM (`target/debug/tclvm --tcl-version X script`) and the Rust runtime (`target/debug/examples/run_script --quiet --tcl-version X script`, built in `runtime/rust`); `engines.out` and `analyser.out` hold the results. `frames/` puts one call in each evaluation context (procedure, method, `apply`, `uplevel`, alias target, `after`, `namespace code`, `inscope`, `forward`) and `frames.out` records what go to definition, hover and diagnostics answer for it, at the `;# CALL` word. `discriminating/` holds minimal variants that separate causes (analyser output only, in `discriminating/analyser.out`). `variables/`, `dispatch/` and `dynamic/` (non-OO evaluation, namespaces and aliases) are programs that run cleanly, with each wrong call wrapped in `catch` and marked `# BAD`. The `.out` files are generated by the conformance rows (below).

Run a fixture under every release (TclOO needs 8.6 or later; `oo::configurable`, `classmethod`, `private`, `link`, `callback` and `initialise` need 9.0):

```bash
for f in dispatch/*.tcl; do for v in 8.6 9.0 9.1; do echo "$f $v: $(tclsh$v $f 2>&1 | tr '\n' ' ')"; done; done
```

itcl 4.3.5 for Tcl 9 is bundled with the Google Cloud SDK in this container; prepend `lappend auto_path /opt/google-cloud-sdk/platform/bundledpythonunix/lib` to the script and export `ITCL_LIBRARY=/opt/google-cloud-sdk/platform/bundledpythonunix/lib/itcl4.3.5`. snit and critcl are not installed, so their rows are static only.

There is no Tk for the shell interpreters here, but Python's tkinter carries Tcl/Tk 9.0.3: run a `tk/` fixture with `xvfb-run -a python3 -I tk/run_tk.py tk/t01-basic-layout.tcl` (it prints each `puts` and any error). Tk 8.6 rows are static only.

## Conformance rows

Every fixture below this directory is one conformance row (`definitions/` has its own gate). `cargo xtask conformance` runs each row under C Tcl 8.4–9.1, jimsh, the VM (`tclvm --tcl-version X.Y`) and the runtime (`run_script --quiet --tcl-version X.Y`), and through the analyser, the optimiser (C Tcl runs the file before and after its rewrites) and, at `;# CALL` and `;# READ` marks, definition, hover, references and rename, under tcl8.6 and tcl9.0 (and jimtcl for `jim/`). The harness is `rust/tcl-lsp-core/tests/conformance/`; each row is one reported test.

The committed outputs are snapshots of those rows and a row fails when one disagrees: each area's `engines.tsv` (`expressions/fixture-engines.tsv`, beside item 28's `exprs.txt` table), the analyser views `bodies.out`, `dispatch.out`, `dynamic.out`, `frames.out`, `tk.out`, `variables.out`, `variables-flow.out`, `variables-lookup.out` and the `analyser.out` files of `discriminating/`, `frames-semantics/` and `namespaces/`, the `analyser-mcp.out` verdict files, and `tcl-areas-head/`. Each engine runs a fresh copy of the fixture's directory with a cleared environment (only `PATH`, `HOME=/home/tcl-conformance`, `LC_ALL=C.UTF-8` and `TZ=UTC`), so host package trees and anything a fixture writes never reach a row. Engine output is normalised (object names, addresses, channel names, thread IDs, scratch and checkout paths) and joined with ` ¶ `. A fixture whose first line starts `# conformance: timing-sensitive.` documents a timing race; its rows record the exit status only. `cargo xtask conformance --update` rewrites the outputs; an `analyser-mcp.out` verdict survives only while the codes it reviewed are unchanged, otherwise it reads `review`. Arguments after `--` go to the harness (`cargo xtask conformance -- row::dispatch/`).

## Constants

`constants/folds/` holds the constant-folding fixtures (`c*`, `d*`, `e*`; see [constants and folding](../../constant-folding-design.md)). `constants/optimiser.out` lists the non-hint rewrites per fixture and profile (`CF` lines; `expressions-and-lists` lines are the `expressions/exprs.txt` cases as `x01`–`x61` and the `lists-dicts-arrays/folds/` cases; `NONE-VS-9.0` lines compare a `None` dialect with the 9.0 profile). `constants/execution.tsv` runs each fixture under tclsh 8.6 and 9.0 before and after applying the rewrites. The probe calls `crate::optimiser::optimise_with_dialect(&source, &registry, Some(tcl_dialect::DialectProfile::find(rel).unwrap()))`, applies the non-overlapping, non-hint rewrites from the end of the file backwards and writes the result; always pass a profile, since `None` folds nothing that depends on the release.

## Name-resolution validation

`name-validation/` holds the cases the code inventories flagged as likely disagreements ([name-resolution validation](../../name-resolution-validation.md)): `p01` relative `namespace path`, `p02` a namespace procedure shadowing `lindex`, `p03` an empty ensemble subcommand, `v01`–`v04` variable names (`a(b` as a scalar, `global ::x`, a non-ASCII byte ending `$name`, `upvar #0 ::g`), and `m01` TclOO linearisation. Run each under tclsh 8.6/9.0, `target/debug/tclvm` and `target/debug/examples/run_script` (with `TCL_LIBRARY` set), and through LSP definition and hover calling `definition::definition` and `hover::hover`. All agreed with tclsh on `d0e48391`.

## Fourteen Tcl areas

`traces/`, `special-variables/`, `coroutines/`, `event-loop/`, `errors-returns/`, `unknown-autoload/`, `interps/`, `exec-pipes/`, `threads-subsystems/`, `encodings-channels/`, `regex-patterns/`, `tcl9-changes/`, `comments-continuations/` and `jim/` each hold fixtures, `engines.tsv` (tclsh 8.4–9.1, Jim, VM, runtime) and the audit's `analyser-mcp.out` (cached MCP build). `tcl-areas-head/` re-runs the analyser and optimiser on the current source and executes every rewrite; see [the audit summary](../../tcl-areas-audit.md).
