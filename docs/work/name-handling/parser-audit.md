# Parser ownership audit

19 November 2026. Source baseline `819c0f8b66` on `work`. The subsequent Jim pin at `a6c66517c7` selects the Jim revision used here. The first migration should remove the registry's independent literal evaluators. Their callers can replace runnable source, and four different families already produce oracle-contradicted output. The next consumers are edits, diagnostics and generated specifications. The [crate plan](parser-crate-plan.md) covers the rest of the language, execution contexts, host formats and migration checks.

## How to use these findings

A **product reproduction** compares an observable through a normal product entry with the selected interpreter or with another public product surface. A **reader discrepancy** identifies a production caller and a disagreement in its reader, projection or helper. An earlier guard, or a later check, can still preserve the final answer. A **coverage gap** needs the indicated experiment. The expected answer for a source edit includes completion, output and errors. Original bytes, spans, frames, object representation, traces and dialect can all affect those answers.

The six interpreter builds were C Tcl 8.4.20, 8.5.19, 8.6.18, 9.0.4, 9.1.0 and latest upstream Jim `0.84-15-g2f8e155`. Evidence from a package, logical editor environment, or F5 simulator has its own scope. Record appliance questions in the [BIG-IP ledger](bigip-name-checks.md).

## Controls and open boundaries

- [The runtime parser](../../../runtime/rust/src/parse.rs) already groups the shared byte lexer's output. VM and runtime substitution adapters use the lexer. [Script completeness and reparse windows](../../../rust/xtask/src/segmentation_drift.rs) have a different input and contract from complete command vectors. Keep their corpus differential.
- [Dictionary bindings](../../../rust/tcl-compiler/src/dictionary_bindings.rs) already use selected list rules and canonical slots. A C variable-name argument, a source `$a(k)`, a braced substitution, an incomplete editor prefix and Jim dict sugar can all require different answers from the same text. Native formal validation and tolerant signature display also have different obligations.
- A configured expression refactor can withhold edits despite a bad candidate detector. Production completion uses original word spans. Several apparent local parsers in receiver, package-resolution and F5 translation code are test-only. Filing a defect requires a reachable production caller.
- `lsearch` and `lsort` have similarly named `split_index` adapters. They call the shared list reader. Check release selection, byte fidelity and error wording before consolidating a wrapper. The Thread 2.8.13 comparison above required installing the matching extension. Stock-interpreter command absence supplies no answer for extension semantics.
- A tmsh stanza reader, APL outer grammar, filesystem watcher glob, TLS/HTTP record, JSON-RPC message, bytecode stream and Tcl script each have their own delimiter and escaping rules. Delegate only where a typed field actually contains Tcl. An independent C oracle or device capture remains independent evidence.


## Additional boundaries verified in the callers

- Tolerant TclOO signature display accepts partial formals, while the release formal validator rejects a method parameter with too many fields. The public owner is `parse_formal_parameters_in`. A [WASM fast path](../../../rust/tcl-codegen/src/codegen/wasm/native_add/retained_publication.rs#L114) still splits formals on whitespace. All six accept `proc add {{a} {b}} {return [expr {$a+$b}]}`. Confirm the lost fast path and preserve the parsed default/variadic facts.
- [The editor's APL grammar](../../../grammars/tree-sitter-apl/grammar.js#L163) has the same raw bracket-balance problem as the Rust reader. Keep an APL injection-range fixture in both clients. For tmsh configuration files, the Rust and tree-sitter scanners treat quotes and braces differently in rule bodies. Device acceptance of the quoted-word/stanza witness remains open.
- For the compiler's 8.4 source error, execution compared full entry paths. Running a file directly, literal `catch`, `eval` and `uplevel` matched their corresponding oracles. Via `source` the VM reports “while compiling” where C Tcl reports “while executing”. [The source path](../../../rust/tcl-vm/src/command/native_encoding_source.rs#L320) needs the selected entry semantics as well as file identity. A common parser must preserve that distinction.
- A conservative [scan diagnostic](../../../rust/tcl-compiler/src/scan_predicate.rs) still abstains outside ASCII. The handling of leading Unicode whitespace by `scan %d` differs across C and Jim. Remove the second conversion scanner only after the selected scanner can represent that difference.
- The [minifier list reader](../../../rust/tcl-lsp-core/src/minify/case_lists.rs#L40), [Spec Studio's writer](../../../rust/tcl-spec-studio/src/render_spectcl/tcl_words.rs#L50), [array name decomposition](../../../rust/tcl-syntax/src/naming/array_elements.rs) and package resolver's source segmentation are migration controls. They already consume their shared owners for those operations.
- The documented forgiving [switch-body splitter](../../../rust/tcl-syntax/src/switch_body.rs#L38) has an in-tree text search result limited to its own module and tests at this revision. Check public/exported use before retiring it. Clause-list logic already has a [selected-syntax entry](../../../rust/tcl-syntax/src/case_list.rs#L238). Keep forgiving display results out of rewrite permission.
