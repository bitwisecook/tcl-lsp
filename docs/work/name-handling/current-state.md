## Coordinator rulings awaiting the owner's review, 16 November 2026

Made so sessions were not stalled; each can be overruled.

- **Recovered tail.** The proving walk does not enter commands recovered after an unterminated delimiter. The tail is an editor tier: display facts from written words plus the registry; diagnostics limited to registry-only arity, subcommand and option errors on a single literal bareword head the reached prefix does not rebind; no flow, existence, type or taint diagnostic and no edit-producing consumer there.
- **Bytecode target.** Structured `if` / `while` / static `eval` are lowered under the bytecode target as on `origin/rust`, with the selected compiler's original vector kept on the statement for native emission, instead of teaching the escape summary and both inliners to read a control plan off a call.
- **`return` / `set` selection.** Both halves are on `work`: the `return` half (`a4e9d10e`) and the variable-link half (`a0fdadb2`), the second with one named, owned regression (a unit-scope seed, analyser session).
- **Diagnostics.** A variable defined only in the body of a possibly-empty loop is silent; a standalone document's global frame is open except for what the document itself proves; the unreached-site `proc` fallback stays restricted to child-interpreter scripts.
- **Taint.** Hosted metadata may supply getter colours and sanitiser transforms to the taint diagnostic only; each F5 claim has a BIG-IP check.
- **F5.** An unpinned hook is still told 8.4 for F5 profiles (the F5-only rule read as about evaluation); procedure bodies under `f5-iapps` and `f5-tmsh` are entered for a braced body only.
- **Common AOT plan.** Direct-body and constant-store proofs use the token-owned trace check, as the call decision does; a traced procedure or variable must still decline.
- **Summaries.** A binding at the call's execution point decides a global-write summary; fixtures that relied on an installer nobody calls now call it, with one row kept for the as-written shape.
- **Tooling.** Code that asks whether text is one complete command uses the checked segmenter; a supplied analysis input stays exact and the supplier resolves it once for unit and analysis; a directive that cannot be read selects nothing.
- **References.** Callback selectors in unentered method bodies may be reported as read-only reference spans; rename keeps them as a hazard.
- **Naming gate.** Colon trims count as hand-written name handling; four `::` joins in `f5-cli` and `tcl-bigip` are listed as not Tcl names.

The dominant failure shape is an analysis that returns nothing where the test expects an answer (a diagnostic, fold, token role, reference or hover). Causes established:

- A profile with no `NativeNameProtocol` (`tcl`, every F5 profile, Jim before 0.84) takes the Logical path; a concrete release takes the Native path, which withholds an answer whenever a proof input is missing.
- One dynamic word in a command leaves its role set incomplete, and consumers then drop the whole command's roles.
- Fixtures built from the profile-less default registry no longer see an authored `proc` as a procedure.

Semantic tokens: 74 token tests failed in `tcl-lsp-core` and `tcl-lsp-db`, and 10 in the server e2e suite. At `df7dccbc`, 38 fail in `tcl-lsp-core` and 5 in the server e2e suite; no other `tcl-lsp-core`, `tcl-compiler` or `tcl-registry` test changed result. Faults fixed, all in the token walk unless marked:

- `registry_overrides` returned before its per-word schema queries when a dynamic word left the role set incomplete, so `switch $x {…}` lost its case list and `return -options $o` its option. An incomplete command now also takes display roles from its written spellings (`unset arr($i)`, a regexp pattern with a substitution, `uplevel $level {…}`).
- The case-list walk read the enclosing context's operand instead of the argument's own, so a top-level case list was never entered on a release profile.
- The shape-based option scan for a computed head (`$obj cfg -real 1 -- -literal`) had been removed.
- The `--` terminator and an inline definition member word (`oo::define C method …`, `self method`) had no colour.
- A command the analysis recorded no invocation for (inside a body it did not enter) had a plain head and no roles. An unrebound bareword there now reads the document's own descriptor.

- A hosted iRules document's `when` event and top-level `proc` name had no reader.
- Regex source literals were read only on a Logical profile.
- A `my` call in a method body the analysis never entered had no class. The walk now carries the analysed class into its bodies.

Naming port. The compiler's own `::` tests, joins and prefix strips (60 files) now call `tcl_syntax::naming`; with the earlier ports of `tcl-cmd-core`, `tcl-codegen`, `tcl-vm`, `runtime/rust`, `tcl-runtime-api`, `tcl-registry`, `tcl-lsp-core` and `tcl-lsp-db`, no production crate outside the owner builds or splits a qualified name itself. First-paint semantic tokens. On this branch the server's coarse tier had become a structure-only analysis of the whole document, so the first response waited for it: 61 s on a cold 6,000-line file. What changed, each returning what the code it replaced returned (the commit messages give the argument):

- **A command's registry words are computed once.** The memo row is keyed on the head's conditional-metadata row and on the scoped bodies containing the head. `process_command` now records that row before anything asks for the words, and the path-constant pass runs after the walk of its batch instead of before it, so both read the row every later consumer reads. Nothing in the walk reads the path inventory.
- **The realm memos hold a large document.** Prepared command tokens and point bindings were retained for the first 256 commands only, and the stamped-token, body-inventory and registry-word memos stopped or cleared at 4,096; past those sizes every query prepared its command again. That was most of the rise in cost per command with N and all of the step near N=450. All five hold 65,536 entries.
- **Four scans that grew with the file.** A variable root compares its span before its owner (`record_qualified_var_ref` compares a root with every earlier root); `extend_conditional_math_invocations` looks for a call site inside the script before it compares an expression's observations; the command table derives, once per table contents, the rows under each command token's hash (`retained_target_is_current`) and its authored keys (`original_advice_candidate_from_paths`).
- **The two caller-frame scans of a procedure body share one list of commands and their assistance** (`param_traits::caller_frame_facts`).
- **Two queries a provider asks of a finished analysis.** The four queries that take a retained procedure row (`original_procedure_formals` among them) find it by address before comparing it with every row, and the comment-line walk borrows the analysis's realm instead of copying it, so it shares that realm's memos and indexes.
- Still in place from the first half of this pass: per-reference queries over the retained bindings read indexes keyed on their inventory's allocation; state forks share `rebound_names` and the command table's values instead of copying them; a document image keeps its validated text beside its bytes, so "is this text the realm's image" compares addresses.
