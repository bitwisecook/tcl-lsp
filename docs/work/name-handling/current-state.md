Updated 15 November 2026. Results apply to their captured source and stated purpose. **The LSP is not release-ready.** Sections below the measured state are dated snapshots from 4 to 13 November.

Failures by crate: `tcl-compiler` 2,666 of 13,074; `tcl-lsp-core` 862 of 4,887; `tcl-codegen` 326 of 1,531; `tcl-vm` 191 of 3,200; `tcl-lsp-db` 78 of 244; `tcl-cli` 60 of 288. `tcl-syntax` (936), `tcl-lexer` (820), `tcl-cmd-core`, `tcl-dialect` and `tcl-core-types` pass in full. About 2,930 of the 4,407 failing tests carry a name that exists on `rust`.

The dominant failure shape is an analysis that returns nothing where the test expects an answer (a diagnostic, fold, token role, reference or hover). Causes established:

- A profile with no `NativeNameProtocol` (`tcl`, every F5 profile, Jim before 0.84) takes the Logical path; a concrete release takes the Native path, which withholds an answer whenever a proof input is missing.
- One dynamic word in a command leaves its role set incomplete, and consumers then drop the whole command's roles.
- Fixtures built from the profile-less default registry no longer see an authored `proc` as a procedure.

Semantic tokens: 74 token tests failed in `tcl-lsp-core` and `tcl-lsp-db`, and 10 in the server e2e suite. At `df7dccbc`, 38 fail in `tcl-lsp-core` and 5 in the server e2e suite; no other `tcl-lsp-core`, `tcl-compiler` or `tcl-registry` test changed result. Faults fixed, all in the token walk unless marked:

- `registry_overrides` returned before its per-word schema queries when a dynamic word left the role set incomplete, so `switch $x {…}` lost its case list and `return -options $o` its option. An incomplete command now also takes display roles from its written spellings (`unset arr($i)`, a regexp pattern with a substitution, `uplevel $level {…}`).
- The case-list walk read the enclosing context's operand instead of the argument's own, so a top-level case list was never entered on a release profile.
- The shape-based option scan for a computed head (`$obj cfg -real 1 -- -literal`) had been removed.
- The `--` terminator and an inline definition member word (`oo::define C method …`, `self method`) had no colour.
- A command the analysis recorded no invocation for (inside a body it did not enter) had a plain head and no roles. An unrebound bareword there now reads the document's own descriptor.
- A SslicTcl or SpecTcl document's own grammar was not selected on its concrete core.
- A hosted iRules document's `when` event and top-level `proc` name had no reader.
- Regex source literals were read only on a Logical profile.
- A `my` call in a method body the analysis never entered had no class. The walk now carries the analysed class into its bodies.
- Fixtures: the regex-source tests and the tclsh 9.0 oracle built a dialect-blind standalone unit while naming `tcl9.0`; three sources read an unset `$s`, which raises before `regexp` runs.

Open token faults and their cause:

- Object handles, about 15 tests. A nested `[Class new]` word was typed only from a bounded construction proof; it is now a candidate of a class the unit declares, which types `set p [Pin new]` in a profiled unit. Still untyped: collections (`dict set Pins $k [Pin new]`), loop variables over them, widget paths and snit components. The 20 failing `object_types` tests in `tcl-compiler` build a standalone unit, whose class roster is empty (`class_roster.selected_result declared=0` under `TCL_LSP_TRACE_ORIGINAL_FACTORY_GUARDS`); they need a profiled fixture or a standalone roster.
- Receiver receipts (`semantic_tokens::receiver_source`, 7 tests) and snit or itcl implicit receivers (`$self helper`): the compiler answers only for a receiver its execution entered. Hover and definition share that lookup (`receiver_identity::method_at_command`).
- The four `large_file_*` promptness tests and `test_issue_898_default_library_modifier` in the server e2e suite.
- `st_irules_event_fallback_survives_generic_tcl_registry` contradicts `event_declarations_read_the_documents_own_registry`; one of the two expectations has to go.

The server e2e suite is not deterministic on this host: 14 tests that passed in one full run failed in the next and each passed again on rerun; `spec_packs::a_pack_added_after_startup_reloads_and_re_analyses_open_documents` passed one run in four alone on one thread.

## Tokens, owner and tooling area, 15 November 2026

Crates: semantic tokens in `tcl-lsp-core` and `tcl-lsp-server`, `tcl-syntax::naming`, `tcl-lexer`, `tcl-registry`, `tcl-spectcl`, `tcl-irules`, the tooling crates and `xtask`. Measured on the same host at test profile `opt-level 1`.

Naming port. The compiler's own `::` tests, joins and prefix strips (60 files) now call `tcl_syntax::naming`; with the earlier ports of `tcl-cmd-core`, `tcl-codegen`, `tcl-vm`, `runtime/rust`, `tcl-runtime-api`, `tcl-registry`, `tcl-lsp-core` and `tcl-lsp-db`, no production crate outside the owner builds or splits a qualified name itself. The owner gained `is_absolute`, `is_absolute_bytes`, `unrooted_member_key` and `authored_namespace_hint_tail_bytes`. `cargo xtask owner-resolution` now counts, in every production file outside the owner, each string method given the literal `::` and each format template that only joins holes with `::`, and holds each file to the count in `docs/generated/naming-delimiters.md`: no site remains (44 in 20 files when the gate landed), and a new one fails the gate. The compiler's last sites call the owner (`scope_variable_key` names the analyser's flat scope-and-variable key, `::::x` for the root, in one place); SpecTcl, spec-studio and the registry name their hook, Rust-path and `rule::procedure` separators as constants owned by those formats; four matches in `f5-cli` and `tcl-bigip` join a report label, a configuration object key and a hash input, which are not Tcl names, and the gate lists and subtracts them.

First-paint semantic tokens. On this branch the server's coarse tier had become a structure-only analysis of the whole document, so the first response waited for it: 61 s on a cold 6,000-line file. It is now a *source shell* (`Analyser::source_shell`, `SourceAnalysisOptions::unentered`): the analysed document and its resolved input with no command interpreted. The token walk colours a command with no retained invocation from its written words and the document's registry: head (a qualified head split by `naming::written_command_tail`), subcommand, options, bodies, expressions, case lists, parameter lists, variable-name arguments, definition-body members, and the comments of every script region it enters. `tcl_lsp_core::semantic_tokens::coarse` and `coarse_range` are the entry points; the server's full and range handlers both serve them when the analysed read misses its 40 ms budget.

Two causes of the analysis cost were removed on the way; the rest belongs to the analysis-performance session:

- `SourceImage::document` copied the document at about 800 call sites and every later image equality compared whole documents. The lexer keeps the few most recent document images per thread, so a repeat request returns the same allocation.
- The realm's array-root and namespace-operand queries rebuilt the binding of every earlier command site per variable reference; they now read the realm's site memo.

Other token faults fixed in this pass:

- The written-word fallback for a command with no invocation asked the registry for an empty role set, so it coloured only the head. It now reads every display role, which also colours bodies the analysis did not enter in the analysed tier.
- A command at a site the interpretation never reached (a `[expr …]` inside `return` in an uncalled procedure) was treated as rebound and lost its colours and its expression. It now reads its descriptor unless the document itself rebinds that name; a site the interpretation dispatched and could not prove stays generic.
- A comment inside a body the analysis did not enter (an `if` arm of an uncalled procedure) had no token although the commands around it did.

Tests collapsed in the owner: 18 single-assertion tests of `normalise_var_name`, `normalise_qualified_name` and `qualify` became three table-driven tests with the same rows (53 tests to 38 in `naming.rs`).

What changed, each returning what the code it replaced returned (the commit messages give the argument):

- Per-reference queries over the retained bindings read an index instead of every row: declaration layouts by word extent and by sole variable word, variable accesses by owning invocation, implicit math sites and formal components by key range. An index keys on its inventory's allocation through a weak handle and is built on the second query of an unchanged inventory.
- State forks stopped copying by value: `rebound_names` is copy-on-write, the command table shares its values (a `BTreeSet<MayBinding>` leaf is about 3.5 KB, and every `proc` copied the table), and a join leaves a name alone when the incoming alternatives are already held.
- The nested-layout visit set no longer hashes each parent's whole lookup world; the Jim stock continuation scan and the first-row self-comparison in `select_declaration_layouts` are gone.
- A document image keeps its validated text beside its bytes (`SourceImage::try_text`, `has_bytes_of`, `shared_text`), and the analyser holds its source through that buffer, so "is this text the realm's image" compares addresses. `SourceMap::from_image` no longer validates the document per call.
- Query sites borrow the realm's bindings instead of cloning them.

What remains, in the order it should be taken:

- **The per-command constant.** The profile is flat: about 10,000 `malloc` calls per walked command (a third of the time with their frees and drops), and per command the same text is tokenised about 26 times, its words rebuilt about 96 times, its registry semantics resolved about 71 times, the lookup state cloned about 62 times and a `SourceInvocationBinding` cloned about 26 times. No single site is above 4%. Reaching 1 ms per command needs each walked command to compute its tokens, words, stamped binding and registry facts once and hand them to every consumer (`source_registry_words*`, `stamp_original_tokens`, `retained_original_tokens`, `original_native_compiler_words`, `capture_with_nested_cuts`), not more memos under each consumer.
- **Per-definition copies that still grow with N.** A `proc` definition still copies the command table's keys and handles, `rebound_names`, the original command world and the allocation counts once each. They need persistent (structure-sharing) maps to become constant.
- **`original_catalogue_bindings_for_slot`** scans the command table per command head; it now tests the simple name first but is still one pass per lookup.
- **`extend_conditional_math_invocations`** reads every retained expression per script.
- **`SourceImage::document`** compares its text with up to four recent images per call when the caller's buffer is not the image's own; the analyser walk now passes the image's buffer, other callers do not.
- **Full analysis.** `emit_cfg_ssa_diagnostics` builds a compilation unit per analysis; at N=400 a third of the diagnostics phase is `SourceCommandBindings::module_projection`, which joins every point's state into one (each join reads state the size of the document), and the unit build walks the source a second time. - The semantic-token walk over the finished analysis was not changed here.
