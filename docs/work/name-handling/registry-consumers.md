## Outstanding actual owner/representation obligations

A. At the audited baseline, `registry.rs` semantics producers and pinned Jim admission namespace-normalised command descriptor labels. The current unexecuted edit replaces only their explicit metadata-label root projection, retaining exact bytes, with custom descriptor and stock-roster negatives; tests await the parent source freeze. The shared contract says that namespace normalisation is unsuitable as a universal command identity normaliser; `CanonicalCommandDescriptorKey` preserves exact selected labels. `effective_semantics`/`authored_source_semantics_in_context`/`effective_semantics_for_dialect_in_realm` seed Compiler `BindingBaseline`; stock admission is called by VM `profile_admits_registry_builtin` with retained original registry identity, including renamed-stock provenance. Thus replacing these with a universal written command canonicaliser would repeat the same provenance error. The normaliser also drops a final empty command component and folds interior separator runs. Pinned shipped ASCII rows conceal the distinction. Required next work: actual custom-store descriptor negative controls for trailing empty/literal-colon labels, determine whether initial binding publication receives authored written syntax or exact constructed labels, then use the already selected correct owner and preserve each distinct roster purpose. Compiler `command_binding.rs` has additional namespace-normalised descriptor equalities owned by the Compiler agent; coordinate that boundary. No new executable failure has yet been captured for these sites. Syntax `normalise_qualified_name` API docs currently call it a command/procedure normaliser although the durable contract limits its purpose; documentation must match the final owner semantics.

B. `namespace.which` still uses `HookFrom(V8_6)`, leaving every C86+ query as unmodelled hook selection. Original C source/probes show `-variable` and non-SIMPLE/non-command option forms decline; accepted command forms compile `resolveCmd`. C86/90/91 public decline retains the selected private worker and emits `invokeReplace`, not ordinary `invokeStk`. Oracle agent owns exact sources/raw captures and scratch helpers in `/tmp/namespace-which-decline{,-original}.rs`; accepted command forms remain Unknown until an actual resolve-command instruction is modelled. Known decline must pass the existing actual registration/source/hook/offset gates, and Generic must preserve selected-worker rewrite. No checkout integration or tests for the new selector yet.

C. `named_ensemble_grammar` still repeatedly trims roots and conflates checked original source heads with constructed target labels. The unknown-head default uses `lookup.prepended.len()` to infer retained selectors; one-root comparison alone cannot repair this. Real Compiler/Runtime selected workers already route indirectly through `native_selected_worker::compile_original_selected_worker`, whose named branch takes explicit original `operand_from`; reuse that owner. Direct Compiler Native byte compilation refuses nonempty implementation prerequisites, so an executable operand-loss bug must not be claimed from the mixed pure selector alone. See revised `/tmp/registry-named-operand-layout.md`. Actual original arity/evaluation expectations are retained in `experiments/name-handling/registry-operand-layout/`; they are oracle expectations, not shipped original Compiler/Runtime conformance.

D. Expanded byte-oriented search identifies `native_namespace_binding_compilation::scalar_tail`'s last-separator scan as a remaining delegation opportunity. Existing `written_separator_extent(value).end` matches the last complete colon-run end, including trailing runs and lone-colon data; preserve the separate terminal-parenthesis rejection and `complete`/nonempty suffix gate. The helper receives source-materialised suffix bytes, so do not replace it with whole-command or C-string-normalised lookup. Changes and exact boundary controls await a later edit window. `native_property_lookup`'s separator presence may delegate existing `is_qualified` on its already selected C-string extent; other two-byte shape guards need no new utility.
