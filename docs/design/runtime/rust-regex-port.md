# The `tcl-regex` crate — a pure-Rust port of Tcl 9's ARE engine

`rust/tcl-regex/` is a from-scratch, idiomatic-Rust implementation of Tcl 9's
Advanced Regular Expression (ARE) engine — the Henry-Spencer engine that
`tclsh` 9.0 uses (upstream Tcl C sources: `regcomp.c`, `regc_*.c`,
`regexec.c`, `rege_dfa.c`). Being a pure-Rust port, the crate needs no
vendored C sources fetched at build time.

It is **not** a transliteration of the C. The C engine is built from intrusive
pointer-linked NFA arcs, a union-tree colour map, and a `subre` child-pointer
tree, with a DFA fast path and a backtracking dissector. The workspace forbids
`unsafe`, and a literal port of that machinery would be neither idiomatic nor
safe. Instead the crate reproduces the engine's **observable behaviour** —
exactly what `reg.test` checks — over data structures chosen for Rust:

- match positions and submatch participation,
- the subexpression count (`re_nsub`),
- the `re_info` bits (`testregexp -about`),
- the `REG_*` compile-error codes.

## Architecture

```
src/defs.rs     Constants & typed enums: Chr/Color, the REG_* compile/exec
                flags, the re_info bit values, and the `Err` error-code enum
                (with `.name()` / `.message()`), plus `RegMatch`.
src/ast.rs      The compiled form: a `Node` tree (the idiomatic analogue of
                `struct subre`) + `CharSet`/`ClassKind` (replacing the colour
                map — each set carries its own membership predicate, with
                `-nocase` and `-linestop` folded in at compile time) +
                `leading_pref` (the match-preference propagation).
src/parser.rs   Lexer + recursive-descent parser (regc_lex.c + the
                parse/parsebranch/parseqatom logic of regcomp.c). Produces the
                AST and accumulates `re_info` bits, `nsub`, and `REG_*` errors
                at the exact points the C does. Post-parse it computes the
                structural bits: `UEMPTYMATCH` (nullable), `UIMPOSSIBLE`
                (constraint contradiction), `USHORTEST` (leading preference).
src/exec.rs     The matcher. Two phases mirroring the C's DFA + cdissect split:
                `reach` (an NFA-style reachable-end-set simulation) finds the
                POSIX leftmost-longest (or, for a non-greedy-led RE, leftmost-
                shortest) overall extent; `dissect` walks the tree over that
                fixed extent assigning submatches with the right longest /
                shortest / last-iteration preference. Backreferences (which
                make the language non-regular) take a separate backtracking
                path that threads capture state.
src/lib.rs      Public API: `Regex::compile`, `nsub()`, `info()`, `exec()`,
                plus the typed `InfoFlag` / `Info` surface.
src/cmd_core.rs The `cmd-core`-feature adapter: `AreEngine`, the
                `tcl_cmd_core::regex::RegexEngine` impl both runtimes drive.
```

## Why reachable-set + dissection (not backtracking) for the core

Tcl ARE is POSIX leftmost-longest, including a hierarchical "earlier
subexpression is as long as possible" rule for submatches. Naive greedy
backtracking gives Perl leftmost-*first* semantics, which differ — e.g.
`(a|ab)(c|bcd)(d*)` on `abcd` is `ab`,`c`,`d` under POSIX but `a`,`bcd`,`""`
under greedy-first. The C engine resolves this by finding the overall extent
with its DFA and then *dissecting*; this crate does the same, which is why the
core matcher is set-based rather than a backtracker. Backreferences are the one
construct that cannot be handled this way, so they fall back to a preference-
ordered backtracker.

## Test corpus — the real engine as oracle

`tests/reg_test.rs` runs `tests/data/reg_cases.tsv`, a corpus generated by
`tests/data/dump_reg.tcl` driving the **real** Tcl 9 engine (`testregexp`, in
the `tcltest` shell built from `tmp/tcl9.0.3/`) over every variant of every
`reg.test` directive — including the `&` ARE/BRE expansion. Each row records the
authoritative `nsub`, `re_info` bits, compile-error code, and `-indices`
submatch positions. Because `reg.test`'s own assertions are against this very
engine, matching the corpus is equivalent to passing `reg.test`. The corpus is
materialised into strongly-typed Rust values; the flag-string → `cflags`/
`eflags` mapping ports `tclTest.c`'s `TestregexpXflags` + `reg.test`'s
`TestFlags`.

Regenerate after a Tcl version bump:

```
tmp/tcl9.0.3/unix/tcltest rust/tcl-regex/tests/data/dump_reg.tcl \
    > rust/tcl-regex/tests/data/reg_cases.tsv
```

(The `tcltest` shell — which carries `testregexp` — is built with
`cd tmp/tcl9.0.3/unix && make tcltest`.)

`REG_EXPECT` (the `t` flag) is `regex.h`'s internal "report details on
partial/limited matches" probe; its `rm_extend` output is a DFA coldspot
artifact, not reachable through `regexp`/`regsub`, so the corpus records the
real match in the normal slots and does not assert the coldspot.

## Consuming the engine

With the `cmd-core` feature the crate implements
`tcl_cmd_core::regex::RegexEngine` (`AreEngine`), so the shared `regexp` /
`regsub` / `lsearch -regexp` / `switch -regexp` command plumbing can drive it.

The **bytecode VM** (`rust/tcl-vm`) now uses it, replacing the approximate
`regex`-crate path: the VM gains full ARE syntax (`\m`/`\M`/`[[:<:]]` word
edges, POSIX longest-match submatches, the complete escape and class set) and
matches tclsh 9.0. The command-level behaviour is covered by
`rust/tcl-vm/tests/regexp_e2e.rs` (cases ported from `regexp.test`, expected
values captured from real tclsh).

The Rust runtime (`runtime/rust`) also uses it: its `cmd_regex` adapter drives
`AreEngine` directly. This **replaced** the C Henry-Spencer engine that
`build.rs` used to compile and link (`have_regex`): the FFI module, the
`build_regex` step, and the `regex_shim/` C sources are gone. Because the new
engine is safe Rust with no FFI, `regexp`/`regsub` now work on **wasm32** too
(they were stubbed out there before, since the C engine could not link).

### Shimming for C consumers

`runtime/rust` is the C-extension host (it links compiled user code + C
extensions into one module), so it carries a thin C-ABI shim,
`src/regex_capi.rs`, that re-exports the engine under the Tcl regex C symbols
(`TclReComp` / `TclReExec` / `TclReFree` / `TclReError`) with the `regex.h`
`regex_t` / `regmatch_t` layout and `REG_*` codes (header:
`runtime/rust/include/tcl_regex_capi.h`). A C Tcl build or extension that used
to link the C engine links this instead, unchanged.

The shim is where the impedance mismatch lives, by design: the safe-Rust API
speaks `&[u32]` codepoints, typed `ErrorCode`/`InfoFlag`, and half-open
`Span`s; the shim converts to/from the C `regex_t` (opaque `re_guts` =
`Box<Regex>`), the `regmatch_t[]` of `size_t` pairs with the `(size_t)-1`
non-participation sentinel, and integer `REG_*` codes. `tcl-regex` itself
inherits the workspace's `unsafe_code = "forbid"` lint; all the raw-pointer
work is in the shim, in one of the few crates that opts out of that lint
(`runtime/rust`).
