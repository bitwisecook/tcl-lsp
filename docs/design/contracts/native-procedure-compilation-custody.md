# Original native procedure compilation custody

An actual procedure allocation owns its original body, formal storage keys and
constructed namespace. A command name, equal source bytes, a registration
snapshot or a source declaration cannot establish that allocation or show that
its compiler was reached.

At a real procedure preparation boundary, the runtime issues an immutable
`OriginalProcedureCompileRequest` through the declaration's live native role
ledger and the interpreter's private compiler-pass owner. The request retains
its original whole body and derives its selected compiler prefix internally.
Its opaque declaration identity is independent of reporting names. The
request's weak lifetime adds no command, activation or cache reference and
cannot postpone actual resource retirement.

The original body, formal keys, namespace and interpreter bind once. Discovery
of changed original inputs or an actual body-namespace relocation withdraws
previous requests permanently. Among request-issuance failures, only changed
original inputs may use the old compilation callback without custody. Retired
owners, foreign compiler issuers and invalid prefix extents refuse the request.
Anonymous sources and legacy compiler services retain their existing callbacks
without acquiring request-based custody. A captured compiler environment cannot
be upgraded to its issuing owner.

The compiler consumes the request's own operands and the matching native entry.
That match proves their original-source relation relative to the supplied
entry; it does not authenticate an arbitrary constructed entry. The runtime's
original scope, namespace/profile and native registration/compiler guards
remain mandatory.
The captured declaration binding context is independent of the active invocation
policy. Ordinary Tcl formal storage keys reach the owned byte procedure route
only when the original binding plan is Tcl, has no retained static or adapter
bindings, the active policy is Tcl, and every key is valid UTF-8. The legacy
unowned byte route retains its conservative treatment. Captured Jim reference
bindings under an active C policy cannot become ordinary locals. Method,
lambda and other adapter bindings supply no implicit formal names. Unsupported
bindings still use the ordinary compiler path without new formal evidence;
the classifier custody wrapper declines that unsupported context. This supplies
no variable contents, physical compiled-slot provider or Native handler from a
name.

`NativeCompiledProcedure` lowers the original request into a fresh compiler
Module and moves that body's IR into one Module-issued `Installed` body. It
creates no authored declaration site, callable publication or original formal
header; the original C formal-list spelling is unavailable. Its
`original_compiled_body` query requires the live original allocation and
compiler issuer, complete body, unchanged source entry, namespace, grammar,
registry and Procedure, the same Module issuer, and the retained source owner.
An equal-source foreign Module or changed body cannot borrow that custody.

Custody is independent of compiler admission, escape analysis, argument binding,
frame elision and physical relocation. Their existing guards remain required.
Source-only readonly bodies gain no executable inlining decision. A declaration
without body compilation issues no compiled-body result, and a refused
compiler cannot publish a successful compiled-body result.
