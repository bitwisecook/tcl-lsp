# Shared name handling

This is the entry point for consumers of Tcl names across the analyser,
compiler, LSP, middleware, runtimes, code generation, tooling and AI surfaces.
Use the [implementer guide](../compiler/name-resolution-implementer-guide.md)
for purpose-specific entry points, the
[consumer matrix](naming-consumer-matrix.md) for actual integrations and
[shared-utility-contracts-rust.md](shared-utility-contracts-rust.md) for ownership.
The [proof index](../analysis/name-resolution-proofs/README.md) owns semantic
questions and their provider-specific evidence. An experiment capture does not
establish an unexecuted implementation result.

Original C and Jim inputs, hosted F5 inputs and explicit Logical reporting have
different owners. Original queries retain the complete image/channel, lexer
configuration, Registry, actual input purpose and positioned binding receipts.
Missing ownership is terminal for definite identity or mutation. Logical
candidate helpers provide bounded assistance; their strings cannot manufacture
native objects, command entries, completed worlds or editable occurrences.

## Logical variable source scopes

`AnalysisResult::logical_variable_scope_advice` is the shared Compiler entry
for source table eligibility under independently retained Logical advice.
It requires the exact complete image/channel, lexer configuration and a cursor
within that image. Missing input, Native/hosted source and original readonly
alias receipts cannot issue this owner. Core definition, completion and rename
adapters use its eligible scopes; they retain table selection, cell identity,
collision checks and their independent edit requirements.

The Compiler owns smallest-containing-body descent and uses the selected
Registry frame-level parser. Namespace tables retain their selected root
alternative. Procedure/method source bodies retain local tables. Absolute zero
uplevel selects independently retained root source tables, relative zero retains
the source caller's frame, and an unknown caller cannot donate enclosing local/namespace/root
lookup tables. A nested declared body selects its own source boundary.
A missing namespace coordinate preserves the body's source table without a
root fallback or a guessed qualifier. Embedded interpreter bodies cannot
borrow the document root and decline this source selector.
Independent root completion candidates require rooted insertion when the
selected source scope cannot use their bare names. This source view supplies
no entered activation, completed alias, current contents or Native capability.

## Source-read and body selection

`OriginalDeclaredLogicalBodyContext` keeps original declaration ancestry separate
from a selected-frame body. The shared Registry source layout selects relative
zero under the current source coordinate. Absolute zero retains the actual
original body, level input and effective ordinal before selecting an independent
Logical root coordinate. Exact source/input/configuration/context and selected
body containment remain required. Invalid, dynamic and unavailable caller
coordinates decline; a procedure or method namespace cannot stand in for them.
This source recipe supplies no entered frame, physical namespace or edit span.
Immediate child mutation coverage reuses that exact body/frame owner and the
selected naming policy's source argument roles. Sequential selected-frame
operations retain their independently selected coordinates. Possible child
binding changes and unknown namespace path/export effects still withdraw
subsequent source advice.

The Compiler's `SourceReadScope` obtains declaration/read schemas from the
original transition catalogue. `CompletePrefix` retains completed source
commands before a fatal tail; it does not admit partial words or execution.
The owner checks the exact allocating site, original argv, body issuer,
source image/configuration, Registry/context and any actually selected target.
Source-only catalogue rows cannot establish reached runtime applicability or
current stores. Consumers must keep their independent execution/frame proofs.

Conditional body lookup effects share the source-catalogue adapter. Exact
command-binding and namespace-resolution changes still withdraw affected
lookups. Variable and observer effects with complete source role layouts retain
their separate uncertainty instead of erasing unrelated source namespace
coordinates. Immediate script bodies and incomplete role layouts keep their
existing effect projection. This distinction supplies descriptive source schemas,
without proving a quiet physical cell or callback absence.


`original_variable_name_role_words` selects read/name roles through the actual
analysis and `source_registry_words`. It requires the retained whole source,
channel, configuration, availability context, original receiver and word
correspondence. Effective argument roles project only onto their genuine
written operands; captured prefix values do not borrow call-site geometry.
The original word supplies its content span, while its independently known
literal value supplies the name. Literal `$` content and the empty name remain
valid names. Dynamic or opaque values and changed/foreign source inputs decline.
These are readonly source references, without execution or edit authority.

`original_literal_argument_data_for_module` decodes literal argument data from
its exact retained whole Module, Registry, original analysis attachment,
complete original word vector and lexer configuration. The original syntax
owner supplies the value; source sigils, empty names and literal element keys
remain data. Dynamic words, changed owners and NUL values decline. This supplies
no command selection, Native admission, cell identity or successful store.
`LoweredOperation` carries its actual Script-issued original command tokens;
Native assignment and update consumers retain their independent operation and
observer guards. WASM direct-assignment plans retain and emit the decoded name
alongside the value. `CellReference::from_name_data` and `name_data_place` partition
already decoded names through the shared element grammar. Variable reads still
require the original whole-reference grammar and their independent read proofs.

For positively retained Logical aliases,
`SourceCommandTarget::original_logical_prepended_name_inputs` supplies captured
original words to source schemas and symbolic operations. The Compiler retains
the complete alias declaration argv, original allocation and inherited alias
chain separately from the Native prefix owner. Queries check the exact input,
whole image, lexer configuration, ContextRegistry and authored name policy.
Snapshots preserve this provenance; a conflicting or unavailable receipt for
the same alias at a join withdraws it. A captured word keeps its declaration
geometry and cannot acquire a call-site edit span. Native and hosted inputs use
their existing original prefix owner.

`VarReferenceScanner::scan_lexical_word` traverses shared original variable/index
components under the caller's lexer configuration. A written command head
cannot supply a receiver's roles. Actual source role consumers use the retained
invocation owner. `scan_standalone_word` explicitly applies detached catalogue
assumptions as protective liveness advice; it proves no selected binding,
completed read, Native frame or source applicability. Lexical and standalone
cache entries remain separate, with the exact Registry semantic identity in
standalone keys. Supplied source consumers must not replace missing ownership
with a standalone query.

`Module::retain_procedure`, `retain_method` and `retain_body_unit` issue shared `ProcedureId`
values. Module clones retain existing IDs and share issuance state; separately
built modules cannot join equal ordinals. Inventories retain every body,
including repeated display names. Native callable body selection uses
`source_procedure_for_target` or `source_procedure_for_allocation`, after genuine
allocation and source correspondence agree. Conditional original declaration
summaries use `original_source_procedure_bodies` and
`original_source_procedure_for_target` under the actual unchanged Module owner;
they do not widen Native callable admission. Never recover a body ID from a
printed name. The ordinal is only a within-module presentation field.

`AnalysisResult::original_procedure_formal_name_sources` joins an exact retained
declaration to readonly name bytes, optional tight source extents and quoted
source markers. Native formals use their independently retained topology;
Logical formals use the selected authored schema and original whole parameter
word. Escaped or unmapped parents withhold source extents. Consumers match the
actual declaration site and current complete input, never a procedure display
name. These rows grant no activation, cell or edit permission.

Interprocedural summaries, taint, escape facts, inlining and target code
generation select bodies by these IDs. `BodyFrameId` distinguishes the actual
module root from retained bodies. Method kind and declaring source owner are
separate metadata, so a method named `<constructor>` cannot become a constructor
through its label. Source calls select their independently retained allocation
before joining an analysis; an equal display name cannot supply that join.

Function-unit and source-provenance joins retain that ID separately from their
name. `BodyAnalysisCapsule` retains the genuine whole compilation unit;
`BodySummaryInputs` retains actual dependency IDs. `BodyLatticeInputs` checks
the original request and restores current source and variable proofs when
reusing a closed analytical correspondence. Missing correspondence retains exact
inputs or recomputes. Cache reuse grants no Native entry or selected-command
authority. A runtime artifact cache retains
separate candidate IDs and declines when multiple current candidates agree
only in name/body/namespace geometry.

## Original member and case source metadata

`OriginalSourceLinkedMember` joins a link's authentic original class/member body
and member side to the selected `TCLOO_BINDS_METHOD_ALIAS` source schema. The
alias publication and literal target method name have separate inputs. Symbolic
receiver-relative or absolute alias geometry cannot create an object namespace.
Definition and hover use the exact retained target. References and rename use
`original_source_linked_member_reference_spans`; unreadable or ambiguous aliases
withdraw the complete edit set. A static field needs unchanged raw bytes and
original list ancestry before it supplies an editable target extent. One-field
links couple the target and call spelling; publication that changes that
spelling declines coupled edits. These source records establish neither an
entered alias nor a Native helper, receiver or private worker.

`OriginalSourceCase` describes original case patterns, possible bodies and a
subject's exact scalar parameter reference. The Logical issuer requires the
selected original source schema and complete input/word correspondence. The
Native issuer accepts only an already typed `Switch` with its actual closed
handler. Captured prefix values retain their origins; only original whole words
supply geometry. Unknown option/body selection and possible no-match remain
explicit. This view grants no compiler admission, completed handler or frame.

## Conditional dictionary source phases

`ResolvedInvocation::authored_dictionary_scope_source_phase` selects accepted
arity and typed dictionary grammar from the actual source descriptor. Its sealed
phase retains additional effects separately before coalescing with mapping
accesses; generic invocation UNKNOWN effects remain unchanged. Logical
dict-with continuation requires the original whole written lexical-empty body,
current SameInvocation timing, exact roles, quiet owned scalar dictionary and
complete trace-free source inventory. Unrepresented additional writes, scripted
helper implementations and nonempty bodies refuse. Only conditional contents
footprints survive; unknown keys retain an unknown alias contents clobber.
Scratch entry values, body entry, physical bindings, writeback completion and
Native/Normal proof do not enter this source model.

## Representations

A name's spelling, identity and presentation are different values:

| Value | Meaning | Rule |
| --- | --- | --- |
| Written name | Source word or an evaluated Tcl value used for lookup | Parse with the selected dialect and the operation's grammar at ingress. Preserve the source span separately. |
| Namespace identity | A namespace in an interpreter, or a known static path | Retain its identity and lifetime. Its rendered name cannot identify a recreated namespace. |
| Command slot | Namespace identity plus the exact simple name | `CommandSlot` is the runtime representation; `StaticCommandSlot` expresses a statically known slot. A slot's occupant can change. |
| Command identity | A live command object, distinct from its table slot | Use `CommandId` and the runtime's generation/lifetime checks. Imports and traces can retain identity across renames. |
| Variable place/cell | Frame or namespace plus scalar/array identity and links | Resolve under the actual frame context; follow links through the variable owner. |
| Display name | Tcl-facing or user-facing rendered text | Render at output. Never parse it back into identity. |
| Compatibility key | Encoding for an explicitly selected reporting adapter | Keep it separate from Original bytes and allocations; do not expose it as Tcl text or infer a native identity from it. |

Distinct slots can render as the same FQN: namespace segment `a:` with
simple name `p`, and segment `a` with simple name `:p`, both render
`::a:::p`. No string normaliser can recover which slot produced that text. Runtime trace add/remove/info retain the checked CommandId generation and project only that live token for reporting. Rename source selection uses the original operand and the same generation's current physical slot; a vacating C entry and its destination share that token. Reports never select or redirect a rename window.
The same applies to caches, workspace aggregation and editing identities.

`NameBytes`, `ByteNamespacePath` and `ByteCommandSlot` retain exact bytes and
constructed geometry. They do not identify an interpreter allocation. Native
objects additionally retain their issuer, selected purpose, physical storage,
cache and lifetime. Static Original consumers use authentic source allocations
and lookup receipts. Flat strings remain explicit reporting projections; the
existence of a structured type does not establish a consumer's ownership.

## Context and observable semantics

Command lookup needs the current namespace, ordered namespace path, selected
release/dialect, live command existence and interpreter domain. Absolute
names search globally. Relative names, including `inner::p`, use
current/path/global candidate order, with command existence deciding the
winner. Native adapters pass retained namespace tokens to the shared base
iterator and resolve the global token only when reached. They keep their own
physical child traversal, liveness and generation checks; equal displayed paths
do not merge tokens. Snapshot lookup validates later namespace rows only after
an earlier binding is absent. There is no implicit ancestor search. Tcl 8.4
excludes namespace-path entries under its original naming protocol.
See [command-resolution.md](command-resolution.md).

Registry descriptor adapters remove one optional root marker through
`naming::unroot_rooted_key` and preserve the remaining exact bytes. Their labels
identify selected metadata; original binding, compiler hooks, generations and
operation currency remain independent prerequisites. Math-function reporting
labels use the shared constructed-key decomposition; the resulting simple name
cannot establish an interpreter allocation. Private implementation-namespace
source diagnostics use shared written component extents and registry package
exclusions, and decline Jim's absent C implementation namespace. The dialect
scanner uses shared written-name geometry only to produce a bounded source hint.

Simulator mock publication uses Registry's `SimulatorMockName`, an authored
ASCII label convention independent of measured F5 lookup. The generator and
pure-function registration share its suffix/category/action projection; Tcl
registration consumes the generated exact-label table. One optional root marker,
first namespace and final action select the authored mock. Nested labels can
share a mock suffix intentionally; original registration labels remain distinct.
Missing, opaque, Unicode, noncanonical separator or empty-component labels have
no simulator recipe. Derived suffixes cannot begin with a colon that would alter
the owned publication namespace; registration presence uses exact command lookup.
The hand-maintained simulation roster remains distinct from environment
availability and provides no appliance binding or frame authority.

CLI purity snapshots use Syntax's
`naming::original_namespace_variable_snapshot_support`. Their keys retain the
selected namespace address and original simple variable word. Reads, array
access and traces run with that context and explicit global operation heads;
qualified reports never supply an inverse for the original word. Exact private
namespace subtrees and exact root error metadata are excluded independently.
Ambiguous namespace reports, array-shaped simple reports and unavailable queries
produce an unsupported purity result while ordinary questions continue. These
script coordinates grant no Native namespace incarnation or variable-cell
identity.

CLI SpecTest presence retains the original command operand and root query
context. Syntax's `ScriptRootCommandPresencePlan` supplies separate inventory
patterns: C Tcl retains namespace qualifiers literally and escapes the original
simple tail, while Jim escapes the whole flat-table pattern. The shared script
support selects the audited C8.4–9.1 or Jim0.84 query grammar; unsupported grammar
and missing original-byte transport remain unavailable. The autoloader and
subsequent calls keep the original word. Inventory reports grant no command
allocation or Native entry identity.
Namespace.which's query purpose cannot certify this presence check across
providers: Jim can return no query name for an actually callable lone-colon
command. No pattern result grants Native invocation or allocation identity.

SpecTcl native argument-role hook IDs resolve through
`CommandRegistry::native_argument_role_hook`. Exact qualified command descriptors
precede command/member interpretations, even when the selected command lacks
that hook. This descriptor grammar preserves catalogue labels and provides no
written lookup, original invocation or evaluated operand authority.

Native registration metadata caches retain the exact descriptor query label and
selected dialect. A permitted one-marker fallback compares exact descriptor
labels without applying a second rooted lookup; extra root markers are not a
request to canonicalise written Tcl syntax. Selected registration and operand
layout remain independent of this metadata result.

Registry binding rosters preserve exact descriptor bytes when adding an optional
root marker. Namespace normalisation cannot fold descriptor separator runs or
discard an empty final command component. Jim stock registration metadata uses
the same exact descriptor projection against its measured roster; this supplies
no written lookup or live registration authority.

Original procedure-read flow validates the declaration header, complete current
input, original body/formal correspondence and unanimous source alternatives.
Its immutable source graph uses registry roles and successor-layout barriers;
whole read spans must round-trip through the original correspondence map.
The source graph supplies conditional diagnostics. Executable body entry,
physical variable absence, publication and editing retain separate owners.

Conditional member-body catalogue advice retains its actual definition-body
issuer, source/configuration and applicability. Its absolute command-prefix
projection can expose source metadata for an alias without representing an
executed transition or native frame. Core, DB and server consume the same source
channel and retain its explicit obligation.

Variable lookup needs the frame kind, selected release, lookup operation,
namespace, array syntax and alias links. `n::x` is qualified even without a
leading `::`; an unqualified variable in a proc is ordinarily frame-local.
Tcl 8.x namespace-scope fallback differs from Tcl 9.x. Reads, writes,
creation, introspection and declaration operations must not be conflated.
See [runtime-variable-frame-model.md](runtime-variable-frame-model.md) and
[compiled-scope-and-name-lowering.md](compiled-scope-and-name-lowering.md).

Renames, imports, aliases, ensembles, traces, unknown handlers and namespace
teardown modify bindings or lookup context. They use the same lookup policy,
with operation-specific identity and lifetime rules. `interp alias` retains
a target name and re-resolves it; an import retains command identity.
See [command-binding-and-aliasing.md](command-binding-and-aliasing.md).

Static consumers publish a resolved identity or a justified abstention with
its context. A display-tail match cannot turn an unresolved call into a
proved reference. Rename and refactoring require source spans and identity
proofs; source colon-run widths cannot be reconstructed from display names.
Per-command roles and semantics come from the registry, including overlays
and stubs, rather than spelling tests in consumers.

## External inventory and authoring

Syntax owns `original_script_name_query_support` and
`original_script_command_inventory_support`. External query-family selection
uses the real shell's observations and issues no Native identity. C inventories
retain original simple words in their namespace context, exclude inherited
global fallback, and verify each proposed root operand. Namespace reports are
bounded traversal addresses, never inverse command keys. An ambiguous or opaque
address makes the whole inventory unavailable. Jim uses its flat root table
and original exact presence query independently of C namespace traversal.

SpecProbe transports checked UTF-8 root operands. Studio uses exact original
operands as authoring keys. Scanned C literals remain separately recorded
`c_registration_operands` with unresolved publication context; literal spelling
cannot identify the entered interpreter, namespace, API purpose or allocation.

C alias query, target selection, deletion and inventory use
`NativeAliasRegistrationTable` at the original registration coordinate. The
backend retains the actual command token across relocation and removes the
record only after actual deletion. C8.4 replaces an occupied registration;
later C releases allocate a unique original token by prepending `::` on a
collision. Inventory retains the original objects in physical table order.
Callbacks reread the same original input and check token currency before
retry. Jim retains its separate command-object alias policy.

`NativeCommandNameProtocol::selected_binding_is_current` validates a fresh
lookup's selected token and generations. `cache_is_current` additionally
applies the release's cached-reuse namespace gate. A fresh binding in a dying
namespace cannot be rejected solely because a previous cached binding there
was unsuitable for reuse.

## Dynamic code and familiar naming patterns

Tcl naming is executable behaviour. Definitions, command prefixes, aliases,
imports, variable links and object commands can be assembled, changed and
invoked at runtime. Static analysis must support familiar metaprogramming
patterns and demur where their meaning cannot be established. A dynamic source
shape alone is insufficient reason to stop analysis: constant propagation,
finite alternatives, declared effects and frame context may recover its meaning.

Keep the evidence and its permitted use explicit:

| Evidence | Consumer behaviour |
| --- | --- |
| Proven identity in the modelled context | Publish the target/place and its provenance. A rewrite still needs editable spans, completeness and binding/effect proofs. |
| Conditional identity | Retain the assumptions and context that make the result hold. Consumers must verify them or use guarded runtime dispatch; do not silently treat them as unconditional. |
| Plausible candidates from a familiar pattern | Offer ranked completion or an explicit candidate list with supporting evidence. Do not present a candidate as a definite reference or use it to authorise mutation or optimisation. |
| Unknown or ambiguous | Preserve the reason and any bounded candidate set. Demur on definite target selection, unsafe edits and unsupported diagnostic conclusions. |

Each shared projection retains its own uncertainty and permitted use.
Bounded reporting views cannot manufacture a missing identity, execution or edit
receipt; consumers select the existing purpose-specific owner.

Recognise common idioms through the existing semantic owners:

- Names assembled with constants, `list`, `format`, string concatenation and
  `${ns}::name`; flow-sensitive constant command heads and finite alternatives.
- List-built callbacks, `{*}` command prefixes, `namespace code` and `inscope`,
  with their captured namespace and actual invocation frame.
- `rename`, `interp alias`, export/import/forget and ensemble maps, including
  wrapper commands with declared prefix arguments and binding lifecycle.
- `global`, `variable`, `upvar`, `namespace upvar`, array-element names and
  frame-forwarding wrappers with known argument/effect contracts.
- Package/autoload/source conventions with indexed files, declared overlays
  or stubs and proved load order; repeated procedure factories over finite
  literal inputs and recognisable definition-body grammars.
- TclOO object-handle provenance, `my`/`self`/forwards/mixins, supported framework
  definers, and shared execution scopes such as Tcltest setup/body/cleanup.
- F5 `call` and rule namespaces where rule/profile context is known, keeping
  protocol command prefixes and BIG-IP object paths distinct.

Knowing the bytes of a computed name does not prove which command occupies its
slot when invoked. Knowing a callback prefix does not prove when or in which
frame it executes. Establish these separately. Pattern recognition consumes
registry roles, binding facts, value provenance and shared name/frame policy;
framework knowledge belongs in registry declarations or supported summaries.

Each heuristic needs concrete preconditions, evidence, mutation/invalidation
rules, a bounded evaluation budget and an abstention reason. Unknown writes,
traces, eval/source/uplevel, dynamic factories and external package effects
widen or invalidate affected facts according to their proved effects. Preserve
facts outside that affected scope. A single candidate in an incomplete workspace
does not prove uniqueness; a variable read in an opaque frame does not prove it
is unset. Avoid blanket diagnostic suppression and confident false positives.

Measure useful coverage as well as correctness. Test ordinary developer idioms
that should resolve, near-matching patterns that must not resolve, shadowed
builders, intervening mutation, conditional definitions and cross-file order.
Retain real-oracle programs and outcomes for semantic claims. Review rejected
patterns to improve coverage rather than relaxing the proof required for edits
or optimisations. See [the pattern acceptance matrix](../../../experiments/name-handling/case-catalogue.md#dynamic-pattern-acceptance).
The [wild-pattern catalogue](../../../experiments/name-handling/patterns/README.md)
retains inspected examples, experiment sources and per-oracle evidence. Maintain
it alongside new naming findings; a source example or another provider's result
cannot answer an unexecuted semantic question.

Discover and prioritise patterns using the maintained corpus in
[docs/CORPUS.md](../../CORPUS.md), its authoritative pinned manifest/fetcher,
and the Tcl Wiki. Retain concrete source locations and revisions, check runtime
claims against real oracles, and evaluate coverage and wrong targets on held-out
projects. The [source and investigation protocol](../../../experiments/name-handling/pattern-sources.md)
defines the evidence record. Corpus frequency and Wiki explanations support
pattern discovery; they do not establish an individual call's identity.

## Surface boundaries

LSP providers, server middleware, CLI tools and MCP tools consume common
analysis/lookup facts and adapt their presentation. Native/WASI/browser hosts
and editor clients must preserve those facts and their invalidation context.
AI prompt templates describe the same API contract; generated copies follow
their generator.

Compiler analyses and codegen consume binding and variable-place facts.
Direct/native specialisation needs a binding proof and guards; generic runtime
invocation preserves call-time lookup. WASM procedure definitions transport the
existing evaluated original argv to the shared Runtime procedure owner; the
internal compiled-body key supplies no Tcl name or namespace. See
[original command arguments](../runtime/original-command-arguments.md#compiled-procedure-definitions).
IR, CFG, compilation units, bytecode procedures and compiled-entry tables join
by module-owned `ProcedureId`. Display names remain separate report fields.
Read-only analytical adapters refuse ambiguous displays; they cannot select
original implementations. Retained method and summary consumers preserve their
independent source allocation and purpose boundaries.
