# Explicit standalone unit taint context

The whole-unit taint query distinguishes missing supplied metadata from the
existing explicit standalone compatibility tag. A default dialect-blind build
already selected that tag; the taint query does not select a dialect, change
source entry or manufacture a supplied input.

Only the actual CU top-level function may reborrow this compatibility. The
existing original-authored-function predicate requires the current exact CU
function pointer, Module source/entry/registry/grammar and original CFG.
The private original SSA topology snapshot must be present and match the
current CFG original statement payloads, terminators and successors. The current CFG and SSA must agree on
entry, block inventory and every whole
statement. Every retained source point, including synthetic operations, must
agree with the current CFG source carrier under the Module's issued original-
analysis attachment. The actual immutable semantic-input owner and complete
registry snapshot must remain current. Identical text
from a different unit, changed CFG, missing source tokens, supplied metadata,
unknown history, Native or hosted entry cannot borrow this issuer.

The context reuses the existing OwnedInvocationMetadataContext standalone
adapter. It grants the same detached diagnostic compatibility already declared
by that explicit tag, never Native execution, a physical cell/frame, Normal,
source erasure or callable publication. Body functions and module-only callers
retain the existing strict source-input path. Existing sink/taint policy,
shadowing, observer, callback and replay refusals remain unchanged.

This adds a bounded source-owner scan at each top-level taint-context creation.
Explicit Standalone SSA construction also retains the existing private CFG
topology snapshot when no source-variable symbols were needed. This adds
per-block terminator/successor storage plus an immutable Arc-backed copy of
original statement payloads for that purpose. Statement cloning can traverse
nested Scripts and retain source owners; later snapshot clones share those
payloads. Existing topology equality still compares exactly terminators and
successors; statement custody is a separate check at this diagnostic boundary.
The adapter does not create source or execution ownership.


## Independent Document grammar and authored naming

An explicitly Standalone original source point may retain a versioned authored
naming abstraction while the caller independently selected its Document lexer
grammar. The default fixture constructor, for example, uses Tcl 9 document
escapes with a Tcl 8.6 registry. Source metadata must form its complete original
head through `SignatureSourceNameKey::from_original_logical_source_word`, which
retains the original Document grammar and authored naming purpose separately.
It must not require that word to satisfy a Native string recipe.

This applies only to the existing explicit Standalone tag with AuthoredSimulation
naming and a Document source channel. Present Native, Logical, vendor or hosted
input and unknown entry remain excluded. Other purposes keep the original Native
word constructor and all its grammar checks. Full original source/vector/config,
registry, namespace and candidate guards remain in their existing callers;
formation failure remains terminal. No source entry, naming policy, grammar,
physical frame/cell, Normal completion, compiler operation or publication is
created or changed. The resulting layout is conditional source metadata only.


The same purpose guard projects only the **returned source advice** dialect's
lexer grammar and word-value rules from the retained configuration. Its model
version/core point, naming recipe, baseline and entry remain unchanged. Canonical
authoring already makes this projection at ingress. An explicit Standalone
driver with no invocation dialect can instead inherit the registry dialect;
normalising the returned advice keeps escaped argv consistent with its actual
Document words as well as its head. Supplied/Native/Logical/hosted and unknown
purposes retain their old dialect and constructor path.


## Standalone SCRIPT source values

A root SCRIPT variable identity comes only from its original analysis attachment,
complete original vector, exact source/configuration/Registry, retained Global
source frame and owned namespace geometry. It is separate from procedure BODY
locals, supplied inputs and Native cells. The shared counted C/Jim variable-name
constructor supplies the namespace source identity; spelling does not select a
cell or an entered frame. Unsupported arrays, independent accesses, changed
inputs and missing ownership do not become scalar projections.

Private original SCRIPT point rows retain their source-only access and original
SSA symbol/use/definition versions. Every version of these identities, including
zero and phi versions, stays plain unknown in compatibility taint maps. An
unrepresented intervening write therefore cannot preserve a clean source value
for raw or interprocedural consumers. BODY-only and Native identities do not
acquire this tag. This supplies no executable store, sanitizer, Normal event or
optimizer erasure capability.

An independently owned literal-read advisory may describe trusted source data
only at the same current original point, operand, symbol and version. The whole
selected block must still match the private original statement payloads. From
the definition to that read, only closed, quiet, entirely literal Set source
steps on the same or proved-disjoint source identities are supported. An
unrepresented operation, array or independent access, callback, alias, trace,
synthetic unseen call, barrier, missing local definition or branch leaves the
value unknown; graph or owner corruption refuses the advice. No unknown effect
is ignored to manufacture a positive literal case. All requested-name and
operand/issuer checks precede conservative unknown taint.

This is conditional source diagnostic information, not equality to runtime
contents or full source-effect coverage. The query stores compact point rows
and repeats source preparation and same-block coverage scans.
