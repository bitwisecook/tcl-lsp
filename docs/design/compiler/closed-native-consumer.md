# Closed Native transcript execution

The ordinary optimiser cannot erase native expression conversions or result allocation merely because an arithmetic value is known. An open interpreter can retain variable objects and share channels whose callbacks observe their representations. The C8.6.18 fresh-child channel regression demonstrated that the original `set x 1; puts [expr {$x + 1}]; puts $x` and its literal replacement have equal output bytes but different observable integer caches.

`tcl_engine_tclvm::execute_optimised_closed_source(String, TclVersion)` admits a separate observation domain. Its concrete engine adapter creates a private Native interpreter, compiler and memory output inside an owned worker. It accepts source and an explicit supported Native release, with no imported VM, host, writer, callback, registry, object or cell. The result contains detached stdout/stderr bytes and passive proposed source text. That text grants no permission to execute a rewrite in an ordinary interpreter.

The public return and refusal types live in `tcl_runtime_api::closed_native_consumer`. The concrete [engine adapter](../../../rust/tcl-engine-tclvm/src/closed_native_execution.rs) owns execution; the [compiler plan](../../../rust/tcl-compiler/src/optimiser/closed_consumer.rs), `tcl_compiler::optimiser::closed_consumer::ClosedSourcePlan`, supplies checked correspondence.

The compiler's `ClosedSourcePlan` is inert correspondence. It retains the complete source, registry semantic key and selected profile, checks original invocation and expression owners, and rejects incomplete or unclassified commands. The initial domain contains fixed ordinary scalar assignments, canonical bounded integers, scalar reads, and original stdout output. An output may contain one original braced arithmetic expression using only integer addition, subtraction or multiplication. Before compilation-unit preparation, source is limited to 256 bytes and shared lexical scanners bound braced-word and command-substitution nesting. The worker uses the existing shared source-walk stack budget explicitly. A resource-only pass through the shared command syntax, registry operation metadata and checked expression parser rejects unsupported operators before general compilation analysis; it returns no execution proof. Command count, expression size/depth, every integer intermediate and complete output are bounded during that pass and checked again with the retained original owners. Functions, dynamic commands, callbacks, namespace/array access, control flow and unsupported effects refuse.

Before registry construction or analysis, the private worker monotonically denies external pack evaluators. Denial requires an actually absent thread receiver and its actual no-host generation; it never clears or replaces a receiver to manufacture absence. Installer lookup, installation, availability and dispatch remain blocked through thread teardown. Other threads retain their ordinary evaluator behavior.

The concrete runtime separately authenticates every selected original command token and implementation, physically restricts the command table, proves planned scalar roots initially absent, and owns all I/O. Actual Native entry and registry/source currency are recaptured before selection and consumption. Plain compilation retains the actual Native entry and its complete emitted instruction inventory must satisfy the private execution boundary. There is no fallback to profile-only compilation or an open execution path.

The runtime-api kernel owns the backend and lends an uncloneable scope. Selecting another proposal retires previous selections; execution takes the backend exactly once. Whole-source validation and actual-state checks run again at consumption. The private interpreter, compiler, values and captured metadata retire before detached output leaves the worker, and the public operation joins the worker before returning. No cell or representation survives for later inspection. A new thread alone is not a default floating-point-environment proof; the bounded integer domain admits no floating-point arithmetic or conversion. Guest work and output are bounded; thread join does not promise a deadline for external infrastructure locks.

The private observation contract covers admitted execution and successful detached returns. Unexpected host failures have a separate boundary: a Rust panic can invoke the process-global panic hook and write diagnostic stderr before join. This API does not promise panic freedom or intercept the hook, and a fatal process abort cannot promise retirement or join. It does not install or change any process-global panic hook.

Ordinary source analysis receives no scope, Native entry or retained operand proof. The original fold fixture explicitly selects this concrete owner while retaining both literal-fold assertions. Its open-source counterpart and unknown-effect, callback, rebinding, value-escape and stale-owner controls remain refusals. Differential output checks validate the implementation; sampled equality is not the issuer of erasure authority.
