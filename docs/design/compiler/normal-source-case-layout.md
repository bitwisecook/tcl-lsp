# Normal-source case layout

A successful source-continuation question can inspect the original case-list
regions without asserting that the invocation succeeds or that its compiler
enters those regions. The immutable registry descriptor, exact argument count,
one dynamic final subject and one literal final clause list own this layout.

Pinned C Tcl 8.5.19, 8.6.18, 9.0.4 and 9.1.0 handlers reserve the final two
argv words while scanning options. The compiler is a separate protocol: after
a literal option prefix without an option terminator it declines when only
two words remain. Tcl 8.4 scans the subject as a possible option and registers
no switch compileProc. This narrow normal-source layout refuses Tcl 8.4.

The producer retains the existing possible-case projection, including its
unknown-selection and no-match fields. It does not alter complete argument
roles, instruction selection, source purpose, physical frame or completion.
Only the original C source mutation-coverage walker consumes the new facade.
It checks every genuine braced child extent and preserves all previous graph
uncertainty, arity debts, reentry, child error effects and refusal paths.
No possible child publication is installed into its containing graph.

The supported prefix has no output-variable roles; unrepresented bodies,
malformed lists, dynamic prefixes, expansion, inline clauses, other matching
protocols, changed source/configuration/registry or foreign input still refuse.
Ordinary lowering remains a generic Call where it was generic before.
Logical source keeps its independent existing issuer and Native guards.
