# naming.source.original-scoped-command-schema

Kind: `implementation-contract`

## Problem statement

A scoped command can have source vocabulary without a global command-table entry. Reconstructing a global descriptor from a reporting region or child word can lose its real body issuer, parent availability and original operand geometry.

## Question

How can a source consumer retain independently selected scoped vocabulary and use the common Registry selector/form schema while preserving the authentic body, whole image/configuration and actual context?

## Conclusion

OriginalSourceScopedCommandSchema joins a genuine OriginalSourceScopedBody to its independently selected ScopedCommand. The vocabulary projects an inert owned source descriptor with the parent availability/package metadata. The common Registry descriptor resolver selects subcommands and argument form against complete original words. Compiler and Core borrow that same schema only while body/image/configuration/current ContextRegistry and Registry correspondence agree; reporting regions and global head labels establish no scoped issuer.

## Scope

Authored Rust source-schema controls only. Complete genuine body/child source ancestry and actual current source owners remain required. A source descriptor establishes no package installation, safe-interpreter alias, global command entry, Native handler, body/frame entry, current value, Normal or edit permission. The named selector supplies coverage binding; independent exact Rust execution receipts retain their frozen source scope, and all native providers are not tested by this implementation contract.
