# naming.vendor.original-source-context-input

Kind: `implementation-contract`

## Problem statement

A floating F5 profile does not identify the appliance build or its name producer. Routing an opaque hosted source word through a Tcl 8.4 compatibility recipe or reporting String can collapse source inputs and fabricate runtime lookup authority.

## Question

How do hosted F5 source names retain their actual context and original input without borrowing native Tcl/Jim execution rules?

## Conclusion

Vendor source inputs retain the complete original word, source channel, full lexer configuration, actual lexical command site and independently selected hosted authoring context. The exact measured TMM variable projection is a separate observed authority and is available only for its recorded operand purpose. Unsupported opaque, escaped or computed materialisation remains owned and unavailable; it does not reopen reporting-string advice or select a C/Jim recipe. Source cards, Registry operand roles, byte publication, storage, compiler locals, Normal completion and edits require their own consumers. The shared readonly lexical issuer retains complete original vectors inside genuine NativeWord executable Command arenas under the same whole image, full configuration and original source origin, independently of the parent invocation executing. Inert braced source data and escaped brackets do not become script coordinates. These descendants supply source schemas only, with no completed world or native declaration publication. Independently selected original Body and case regions retain complete child vectors through OriginalSourceScriptBody under the same sealed source argv, full configuration and actual context. A child with no modeled lookup retains its issued body ancestry and explicit UnknownCurrentLookup/UnknownSourceNamespace obligations; an existing blocked lookup cannot borrow this path. Cooked, inert, concatenated or unsupported body geometry stays opaque. These conditional lexical descendants establish no executed body or native procedure publication. The hosted source Realm retains the actual complete ResolvedAnalysisInput through source options, entry, baseline, cache and lowering. Its independently supplied source InvocationDialect and full ContextRegistry select source catalogue naming. A C-compatible Registry profile does not mint C execution or storage policy for that hosted input. An explicitly supplied execution policy remains separate. Concatenating script descriptors issue a body receipt only when their sole Body role is the final effective argument and that argument owns one genuine complete original word.

## Scope

Implementation contract for explicitly authored TMM, tmsh, iApp implementation and iCall contexts. Registered environments select only their own context; iCall can be supplied explicitly. APL and unmeasured presentation callbacks do not inherit implementation Tcl. Plain ASCII literal source units are the narrow implemented advice projection; numeric escapes, Unicode and counted raw-zero materialisation are not guessed. Exact observed BIG-IP build/event variable addressing remains bounded by its independent existing policy. No native execution or appliance reconfirmation is asserted.
