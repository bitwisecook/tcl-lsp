# naming.diagnostics.retained-logical-class-family

Kind: `implementation-contract`

## Problem statement

Logical source object diagnostics can need an observed class-family descriptor while Native canonical class/formal/dispatch proofs remain unavailable. A default family or copied reporting label cannot select that purpose.

## Question

When may a genuinely retained Logical source class-family descriptor classify independently produced object facts without borrowing Native canonical class, parameter grammar or dispatch authority?

## Conclusion

Analyser::retained_logical_class_definer_grammar requires positive actual retained Logical declaration-advice input, complete original source/configuration correspondence and matching actual availability context/Registry generation. The independently produced class and any metaclass provider must retain source Observed provenance before the selected Registry family grammar is queried. Stand-in/default, missing or stale context refuses; Native and hosted family classification keeps its canonical original producer path and cannot fall back to Logical report rows. The admitted family descriptor classifies source diagnostic facts only. Plain Logical naming/family metadata does not supply absent formal parameter grammar, Native class/object/worker identity, closed method table, constructor success, entered frame or dispatch activation.

Seven linked producer controls retain conditional authored object-family information through original new/create, moved constructor, ambiguous local families, factory returns and method returns. A missing method word is a source-family condition; method-specific arity and unknown handlers keep their own independent premises.

## Scope

Current pure source family selection for object diagnostics and companion variable consumer metadata. Three fixed controls check observed source definer with unavailable formals, default/missing/stale correspondence refusal and all-five-C/Jim/hosted Native fallback refusal. Existing bare-object diagnostic producers use positively retained Logical source input independently of canonical Native producers. All seven providers are not tested for this API contract.

These source diagnostics do not execute a factory, object dispatcher, method return or rename. Retained Logical family and source return facts grant no Native allocation, command identity, method-table absence, handler/frame entry, Normal completion or assertion outcome. The existing actual input/source-family admission controls and seven not-tested provider rows remain unchanged.
