# naming.alias.jim-original-core-prefix-object-storage

Kind: `native-observation`

## Problem statement

Retained original Jim alias prefix members must be distinguished from rendered query bytes. A genuine integer member with no resident String allows a bounded object observer to check original result/member equality and cache state across definition, query and invocation.

## Question

What original name-result and prefix-member pointer-equality booleans, descriptor names and resident-String presence does the exact Jim core object-vector observer report before definition and after alias definition, info alias query and alias invocation?

## Conclusion

The actual pinned Jim core-only observer returns BEFORE|int|0; DEFINITION|0|1|int|0; QUERY|0|list|1|1|int|0; and CALL|0|list|1|int|0. The original integer member has descriptor int and no resident String at all four sampled points. Definition returns the original alias-name object (pointer equality1); the query result is a list whose target/member entries are the original target and integer member (both equality1); invocation returns a list whose first entry is the original integer member (equality1). These are actual original-pointer comparisons printed as booleans by this fixed counted API vector, not an identity inference from equal rendered strings. The observer retains its objects across the windows and prints no addresses or refcounts. C8.4–C9.1 each print CORE_ALIAS_PREFIX|NOT_APPLICABLE under the explicit incompatible-API branch and supply no object-storage answer. All six standalone observer processes exit0 with empty stderr. This bounded observation proves neither arbitrary object cache behaviour nor identity/lifetime after the observed owners are released, private command tokens, namespace membership, child crossings, C alias equivalence, Native compiler/argv/frame admission or an executed Rust assertion.

## Scope

One exact C99 probe compiled against six separately pinned header/archive/build pairs, with one fresh process per provider. Jim calls Jim_CreateInterp and Jim_RegisterCoreCommands only, then genuine Jim_NewStringObj/Jim_NewIntObj constructors and unchanged Jim_EvalObjVector operations; no static-extension or source-library installer is used. The version operation is separate from the original counted vectors. The observer samples descriptor/cache fields and object pointer comparisons at fixed definition/query/call boundaries without allocator instrumentation, addresses or refcounts. Whole probe/request/launcher/provider source copies, six cc/ELF artifacts, all streams/receipts and original required pins are retained. No arbitrary object/store/cache frontier, BIG-IP or software pass is tested. The marked Runtime and VM API controls independently retain their genuine original alias-name result, prefix target/member objects and integer member without resident String through definition, original alias query and invocation. Repeated query prefix-header equality is an additional software-owner assertion; the fixed native273 observer samples one query and does not supply that repeated-header observation. Genuine current lookup, object liveness and selected Jim core purpose remain necessary; public inventory274 bytes do not issue object ownership. Linked assertion definitions do not imply a current Rust pass or an arbitrary cache/lifetime law.
