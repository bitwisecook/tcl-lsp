# naming.inlining.original-reference-descriptor-selection

Kind: `implementation-contract`

## Problem statement

Reference-body import can compare raw source command tails against Registry descriptor tails and recreate a rooted key from descriptor punctuation. This mixes written source, descriptor labels and produced declaration keys and can import an unrelated same-tail backing before independent admission guards run.

## Question

How does reference-body import use the original closed Registry descriptor advice and actual produced backing declaration key without turning source tails or descriptor punctuation into Native command identity or runtime admission?

## Conclusion

The import prefilter collects exact descriptor labels from closed unanimous original Registry advisory words, retaining the original Module/input/argument tokens and reading all callers before any reference appendix mutation. Missing/foreign/changed owners or open alternatives produce no candidate. A backing body is lowered as the actual source producer; exactly one original procedure and top-level declaration, no redefinition and retained body text remain mandatory. Its produced Procedure.qualified_name is queried through Registry descriptor lookup and must select the same expected backing row. No local tail or root parsing remains. Own module definitions still take precedence, and existing live reference facts, source appendix mapping, replayable-site and runtime ReferenceBody claims remain separate requirements. Two fixed unexecuted software controls cover a genuine Logical alias versus unrelated qualified/source-defined same tail, missing/changed original source and a genuinely replaced same-name Registry row, plus produced declaration-key/exact-row selection and extra declaration refusal. No assertion/provider execution is attached.

## Scope

Finite inlining/reference original candidate/definition producers, reached by both current compile_service entry adapters. This is conditional source import metadata, not a Native NameKey/parser, lookup result, executed procedure creation, selected actual command/namespace incarnation, pack fact, splice or runtime admission proof. Existing SourceContext/frame, selected binding, source replay, codegen/SiteClaim and VM admission owners remain independent. Other hierarchy/dispatch ledgers are not certified by this question.

- [rust/tcl-compiler/src/site_claims.rs](../../../../rust/tcl-compiler/src/site_claims.rs), `reference_body_facts`: Existing independent selected pack provenance; labels and constructor keys cannot supply it.
- [rust/tcl-compiler/src/inlining/reference.rs](../../../../rust/tcl-compiler/src/inlining/reference.rs), `inlining::reference::tests::original_reference_candidates_use_selected_labels_instead_of_source_tails` (linked): Original Logical alias source selects the exact string descriptor label and never the alias reporting name; an unrelated qualified name or source-defined same tail does not select that label. Missing metadata, changed whole source or a Registry with a genuinely replaced same-named row withdraws candidates. This is conditional import-candidate advice, not pack or Native admission.
- [rust/tcl-compiler/src/inlining/reference.rs](../../../../rust/tcl-compiler/src/inlining/reference.rs), `inlining::reference::tests::reference_definition_uses_its_produced_key_and_exact_registry_row` (linked): The actual lowered authored single-procedure declaration supplies its produced qualified key and must select the exact expected Registry row. An unrelated qualified tail, two declarations, or an equal-name fresh row from a different Registry is refused. No body is imported or executed by this control, and no Native name or procedure identity is granted.
