# naming.source.closed-syntax-script-regions

Kind: `implementation-contract`

## Problem statement

Readonly source-role geometry may follow conditional schemas or declaration cards whose handler applicability is unresolved. A selected pre-operand layout can also cease to apply after an argument changes lookup.

## Question

Can recursive syntax compaction obtain body regions without promoting conditional source roles or pre-argument lookup into descendant edit permission?

## Conclusion

The closed syntax traversal checks the actual full source/configuration, omits declaration and incomplete-body supplements, and follows Registry script, lambda or expression descendants only for the shared Selected source view with an independent original argument lookup-preservation facet. That facet checks every original observation, exact Registry contents and the target observer boundary through the existing operand-effect kernel. Conditional and hosted schemas do not supply it. Authentic lexical command substitutions retain their own source syntax. Readonly capture is unchanged. This supplies bounded source regions, not Native dispatch, compiler preparation, Normal completion or general body equivalence.

## Scope

Rust source-region implementation contract. The linked controls distinguish quiet selected source bodies, complete conditional literal roles, a known custom handler, cooked quoted bodies and head replacement during argument evaluation, plus changed owning source/configuration. The dynamic-condition head-replacement input has an explicitly unavailable legacy readonly role layout and no lookup-preservation facet. Native dispatch/result observations are recorded separately and cannot supply a Rust execution claim.
