# naming.source.native-baseline-conditional-source-roles

Kind: `implementation-contract`

## Problem statement

An authentic captured command table can become unknown after a conditional source mutation. Navigation and source inspection still need the original possible grammar, while execution consumers must preserve the unknown table. Rebuilding that grammar from a reporting head would resurrect shadowed, deleted or unsupported commands.

## Question

Which entry facts can retain possible written argument roles after source uncertainty without establishing a selected handler or definite grammar?

## Conclusion

The shared authored transition tape seeds native source descriptors only from visible Registry implementation rows in the authentic closed entry. The complete name policy must agree and the retained current namespace must be the root; unsupported entry contexts decline this projection. Missing inventory entries, opaque implementations, conflicting slot rows, authored shadows and deletions are terminal. Earlier uncertainty stays attached to each source receipt. NativeBaselineSourceApplicability and UnavailableActualLookup distinguish this conditional source use from current lookup. Navigation unions only genuine whole written argument roles. Captured prefixes and expanded children never acquire whole-word source coordinates. Definite role consensus still uses actual lookup. The source tape never changes command bindings, selected handlers, entered frames, completion, Native compiler admission or rename authority.

## Scope

Compiler source inventory and navigation. Root native entry inventory only; non-root current namespaces, incomplete native entries, initial aliases/imports and opaque implementations are explicit refusals. This is a Rust implementation contract, not an observation of native runtime behaviour.
