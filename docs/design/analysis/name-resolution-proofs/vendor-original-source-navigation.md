# naming.vendor.original-source-navigation

Kind: `implementation-contract`

## Problem statement

A hosted source link can borrow native loader grammar, mistake a dynamic or unsupported word for a filename/package, or select a source subcommand after the actual handler is shadowed or deleted.

## Question

Which actual authored source schema, original operand purpose and complete availability context select a hosted filename or package source-card link?

## Conclusion

The actual authored Registry invocation selects File argument zero or the PackageRequire argument after its real member/option prefix and exact original cardinality. Compiler VendorRegistryInvocationShape retains this descriptor with the complete independent hosted vector and context; guarded conditional vendor metadata applies the shared occupied custom/tombstone barriers. Core consumes the actual whole-source/configuration/Registry words and supported original SourcePath or PackageName units. Unknown values/cardinality, unavailable units, handler changes and unsupported TMM source vocabulary withdraw the link. The descriptor supplies source-card geometry only, without C/Jim naming conversion, native loader, package identity, filesystem existence, execution, Native or edit authority.

## Scope

Current hosted document-link source advice and shared Registry descriptor. Fixed assertions preserve filename-only and selected package option ordinals and reject dynamic/opaque/expanded operands, stale source, custom/tombstone handlers and unavailable TMM source grammar. All seven providers are not tested; no native observation or Rust execution receipt is attached.
