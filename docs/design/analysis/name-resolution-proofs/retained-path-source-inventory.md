# naming.navigation.retained-path-source-inventory

Kind: `implementation-contract`

## Problem statement

Path-variable and namespace-scoped file/package source advice can combine original source words with values from another source image, grammar or lookup scope. Authored path hints need exact retained input and whole original operand positions independently of current runtime values.

## Question

How do path-variable, namespace-scoped file and package source-advice consumers retain the same complete analysis, source image, availability, configuration and original whole-word positions?

## Conclusion

constant_path_assignments_from_analysis requires the actual retained input, whole Document source image and exact body lexer policy. OriginalRegistryWords and selected Registry source-navigation/assignment layouts retain effective whole-word ordinals under current availability; iterative source scopes preserve the authored naming purpose and independent barriers. Path folding uses the shared path algebra and selected braced-variable grammar. Variable scalar/closed-element geometry remains distinct from namespace naming, including empty scalar names and parenthesized namespace literals. Core typed source link projection uses this inventory and actual source navigation, refusing stale/missing input, known shadows and captured-only anchors. These are conditional source hints, not observed values, executed namespace/body, native cell/frame or an edit permission. SourcePathOperation selects Join, Dirname, Normalize or ScriptPath from the actual selected schema and effective argument ordinals. capture_source_path_expression retains a flat original-source plan; OriginalSourcePathExpression::evaluate uses an explicitly supplied document filename and selected variable resolver. PathConstantValue::Original retains this plan without reparsing its evaluated value as source. Selected list renamed as file supplies no path operation, while authentic bound values remain one value even with dollar, Unicode or semicolon bytes.
