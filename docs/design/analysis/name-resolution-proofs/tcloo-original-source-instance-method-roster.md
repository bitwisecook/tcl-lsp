# naming.tcloo.original-source-instance-method-roster

Kind: `implementation-contract`

## Problem statement

An editor proposing an instance-method name must account for builtin inherited names such as destroy even when no source method card exists. Absence from a source declaration ledger alone does not establish a free method name, and class-object or observed provider state cannot substitute for a closed instance-side roster.

## Question

Can a complete source world issue a counted instance-method collision roster for one exact current ordinary stock class, including its selected builtin names, without borrowing a native table or class-object inventory?

## Conclusion

The roster joins the independent source class definition to one surviving original publication and its exact current class token and implementation allocation. It requires the ordinary selected stock factory, closed own instance-name inventory, unchanged provider dependencies and no ancestors, dispatcher or observers. Selected builtin names and opaque source names share counted method identity. Surviving source names retain their exact current declaration entry, and proposed default visibility delegates to the selected grammar. Missing or unsupported premises decline; the roster supplies collision and source declaration advice only.

## Scope

Read-only Rust source-model inventory under C8.6, C9.0 and C9.1 naming purposes, selected from an independently complete Normal root world. ClassObject, supplied Native entries, configurable support mixins, source ancestors, own-object configuration tables, observed or tainted dispatch, unavailable inventory and foreign source ownership are excluded. Proposed default visibility is source grammar advice. No actual method invocation, native installation, completion or edit authority is issued.
