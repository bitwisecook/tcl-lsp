# naming.variable.trace-source-receiver-purpose

Kind: `implementation-contract`

## Problem statement

Trace variable names use a trace-specific ingress before root/index parsing. A nominal VarWrite effect role can otherwise turn trace registration into a source declaration, and requiring every argument to have a Unicode value loses opaque original subject references.

## Question

Can one Registry-selected trace subject descriptor preserve modern and legacy variable-reference grammar, exact original byte geometry and authoring parity without granting registration, successful access or ordinary combined lookup?

## Conclusion

Registry variable trace forms select TraceSubject at the exact modern or legacy subject ordinal. The structured role selector requires the type word and complete argument count; an original native byte selector uses the independently selected index-input extent and the shared trace type table, while command and execution traces remain command references. TraceSubject consumes the shared native trace-query ingress before combined root/index parsing. Source namespace, local, alias and rename geometry use that same purpose; ignored original suffix bytes remain retained, and trace effects never become variable declaration cards. Trace subject naming roles are excluded from value-read and contents-write projections; ordinary selected reads retain their observers. SpecTcl and Studio preserve the receiver form, inheritance and explicit withdrawal; malformed draft forms, positions and duplicates cannot silently default to Combined or argument zero. Missing context, unknown applicability and unavailable Jim trace purpose remain terminal. This descriptor supplies no trace installation, entered alias, observer closure, live cell, successful access, normal completion or edit authority.

## Scope

Rust Registry, Syntax, Compiler, SpecTcl and Studio source naming contract. Fixed tests cover C Tcl 8.4–9.1 modern forms, supported C8 legacy forms, exact worker offsets, unknown selectors/expansion counts, opaque subjects, raw-zero versus encoded-zero address geometry, arrays, authentic alias context, unknown bare namespace targets and complete source currency, and the separation of trace subject naming from observed value reads and contents writes. Jim trace naming remains unavailable under the selected protocol. The separately retained native trace-subject observation motivates the address projection; it does not execute the Rust consumers.
