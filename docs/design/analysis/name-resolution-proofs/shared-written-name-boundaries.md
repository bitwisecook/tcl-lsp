# naming.grammar.shared-written-name-boundaries

Kind: `implementation-contract`

## Problem statement

Core, Registry, syntax and lexer consumers can repeat colon-boundary scans while selecting different counted, CString, Jim and bare-variable inputs. A shared byte span must preserve complete written separator runs without substituting a generic QName projection for the selected input, result or runtime identity owner.

## Question

How do actual counted qualifier/tail and nested ASCII variable consumers share the canonical boundary workers while retaining independent original C/Jim input/result contracts and selected Registry stock-function identity?

## Conclusion

written_separator_extent derives the complete final written separator from qualifier_component_extents, and written_command_tail reuses that span. Core neutral and Registry counted qualifier/tail adapters share these queries. Native C qualifier reporting keeps its original CString selection before the query; Jim keeps its separate last-colon branch and original-object result roles. The array-index scanner delegates its existing ASCII bare-variable door to the core-types worker without changing selected braced/array styles. VM math dispatch uses the Registry direct-global function descriptor after actual stock identity selection and refuses an unavailable descriptor through the typed Host boundary. Three fixed software control definitions exercise counted spans/Core adapters/actual nested array scanning. The nested array scanner and a separate core-types leaf scanner passed the two named, scoped current-owned software controls in the retained receipt. Two further fixed software controls passed for braced-variable style and array-index syntax in a separate follow-up receipt. Four named fixed syntax software controls also passed in a separate current-owned receipt. No other software assertion or provider execution outcome is attached. Studio extension probes retain exact supplied command reports. ExtensionImport::merge_probe compares full strings, merges only an identical report and preserves distinct :p, ::p and :::::p rows without stripping root markers. C-source registration expressions remain separate unresolved authoring inputs. Reporting rows and provenance establish no native registration slot, namespace context or callable identity.

## Scope

Current pure counted written span/tail API, its actual syntax/Core/Registry consumers and exact supplied extension-report merging. Linked fixed software controls remain independent of execution acceptance. Complete separator runs, lone colons, empty/trailing forms, Unicode and embedded NUL are source/counting examples only. Original C CString extent and Jim primitive/result-object behavior keep their separate owners; no Native language/name-key/namespace/source-edit/dispatch/reference or callback chronology is inferred. Existing Native proofs remain independently scoped and unchanged.
