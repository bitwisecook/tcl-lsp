# naming.core.original-expression-source-selection

Kind: `implementation-contract`

## Problem statement

An expression-shaped data or comment selection can receive an operator edit when a consumer reparses selected text. Nominal Registry roles also risk offering builtin math completion after the actual original head is shadowed, missing or stale.

## Question

Which current original operand and independently selected expression role permit readonly expression completion, and which additional permission is needed before operator rewriting?

## Conclusion

The primary expression selector retains a genuine original NativeWord under the complete current source/channel/configuration and actual Registry generation. Native and explicit lexical paths consume unanimous selected effective roles and written origins through the shared invocation owner. Hosted source keeps its independent guarded conditional Registry shape and full original vector/context without C/Jim policy conversion. Completion consumes that same expression operand and distinguishes an inner command substitution. Operator actions require selection wholly inside the genuine operand content. Native and hosted De Morgan/comparison proposals retain missing-expression-operator-rewrite-permission with no edits; readonly source geometry supplies no evaluation or transformation equivalence. Explicit lexical advice retains its separate bounded authoring branch. Known shadowed heads, comments, data, stale whole source and unavailable original roles cannot borrow nominal expression metadata.

## Scope

Current Core primary expression completion and selected-text operator action adapters, with original Native, hosted and independently selected lexical source purposes. Fixed assertions cover reporting-map/dialect-label counterfactuals, actual shadowing, data/comment positions, stale full source, hosted nested source geometry and disabled Native edits. No passing Rust or native-provider receipt is attached.
