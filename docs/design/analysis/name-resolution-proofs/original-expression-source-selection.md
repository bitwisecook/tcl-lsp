# naming.core.original-expression-source-selection

Kind: `implementation-contract`

## Problem statement

An expression-shaped data or comment selection can receive an operator edit when a consumer reparses selected text. Nominal Registry roles also risk offering builtin math completion after the actual original head is shadowed, missing or stale.

## Question

Which current original operand and independently selected expression role permit readonly expression completion, and which additional permission is needed before operator rewriting?

## Conclusion

The primary expression selector retains a genuine original NativeWord under the complete current source/channel/configuration and actual Registry generation. Native and explicit lexical paths consume unanimous selected effective roles and written origins through the shared invocation owner. Hosted source keeps its independent guarded conditional Registry shape and full original vector/context without C/Jim policy conversion. Completion consumes that same expression operand and distinguishes an inner command substitution. Operator actions require selection wholly inside the genuine operand content. Native and hosted De Morgan/comparison proposals retain missing-expression-operator-rewrite-permission with no edits unless a separate bounded original operator issuer closes the requested transformation. Readonly source geometry supplies no evaluation or transformation equivalence. Explicit lexical advice retains its separate bounded authoring branch.

The independent Native operator issuer admits only a whole braced operand of one actual selected expression handler or a simple conditional with exactly one Expr role. Every body of that command must be reflection-free: each nested command is a registry command under a selected or obligation-free conditional lookup, with complete roles, no command substitution, none of the command-name reflection, current-frame introspection or user-procedure traits, and reflection-free bodies of its own; such a body cannot observe the written text of its enclosing command. The command is the only root source command. Original dispatch, compiler name effects, Registry/input/configuration correspondence, command observers and variable-trace inventories remain independently closed. Leaves are literals, fixed strings and plain variable reads whose index holds no command substitution; with traces proved absent a read observes nothing and both trees read the same variables in the same order. De Morgan rewrites preserve truth and left-to-right short-circuit evaluation. The explicitly requested comparison inversion complements equality, membership and string ordering (`eq`/`ne`, `in`/`ni`, `lt`/`ge`, `le`/`gt`) while retaining original leaves in order; it does not claim unchanged predicate truth. Numeric ordered comparisons are not complements when an operand is NaN (`set a NaN; list [expr {$a < 1}] [expr {$a >= 1}]` is `0 0` on tclsh 8.6 and 9.0), so a tree holding one keeps the literal-only, finite-normal-evaluation bound. A rewrite of a failing evaluation changes the command text `errorInfo` reports, as any source refactor does; that is accepted (user decision, November 2026). Lexer-issued leaf extents authenticate both trees, and the replacement is separately checked as an authored braced word. Functions, command substitutions, additional conditions, source-observing bodies and retained procedure source remain unavailable. Known shadowed heads, comments, data, stale whole source and unavailable original roles cannot borrow nominal expression metadata.

Logical math hover consumes a distinct source-only expression occurrence. The
existing configured expression lexer and SourceTopology parser retain the complete
untrimmed expression, every actual caller lexer knob and immutable function-call
ordinal. The Registry source-name receipt derives its relative naming intention
from that exact AST identifier, never from an analyser report or qualified label.

The Compiler expression catalogue holds the original Expr NativeWord, complete
effective argv and selected parent schema. Only the existing whole-source root
traversal's Document receipt or an authentic Logical declared body/frame parent
can supply its namespace recipe. Ordered source coordinates reuse the shared
authored command candidate/path/import owner at that parent horizon. Genuine
original header cards supply candidate allocations, including superseded
headers; none is selected as a runtime winner. Known terminal source cells
exclude header suggestions, while missing path/header inventory remains
unavailable. Current source/input/Realm/configuration/Registry correspondence is
checked again whenever retained advice is used. Earlier unknown operations,
opaque/substitution operands and independent function/observer obligations stay
explicit.

Core's actual Logical hover renders conditional source declarations and separate
builtin expression-grammar documentation. Native fixed-table and command-table
selectors remain earlier terminal branches, with their existing engine/name
policies and allocation guards. The new receipt supplies no Native syntax,
lookup, evaluation, read, normal result, function registration, folding or edit
permission. An unrepresented body/frame, cooked or folded source, non-Written
expression operand, malformed expression or unavailable role cannot borrow a
root context or a reporting-name inverse.

## Scope

Current Core primary expression completion and selected-text operator action adapters, with original Native, hosted and independently selected lexical source purposes. Fixed assertions cover reporting-map/dialect-label counterfactuals, actual shadowing, data/comment positions, stale full source, hosted nested source geometry and disabled Native edits outside the independent literal operator envelope. No passing Rust or native-provider receipt is attached.

## Configured partial expression cursor and parameter extents

The actual completion adapter retains strict current Document UTF-16 position, full source/input/configuration/Registry and its independently selected original Expr NativeWord. OriginalExpressionCursor uses the existing configured Expr lexer over precisely that word content through the real cursor. ExpressionCursorGrammar retains complete LexerConfig independently of expression comments/numerals/operator release and host grammar. The existing variable, bracket, quote and brace scanners keep their real failure coordinates; no closer, completed expression, replacement word or Native diagnostic is manufactured. Only a lexically unfailed expression-space prefix enables the existing source completion context. Inert quoted/braced text, expression comments and unfinished inner scripts cannot do so. Unknown bytes or malformed variable geometry withhold a cursor receipt. Whole-image/configuration/grammar changes cannot reborrow it. This supplies source geometry only, with no AST, mathematical target, result, evaluated read, compiler/Native/Normal or edit permission.

The legacy public expr_arg_context_at remains a distinct nominal authoring compatibility entry with no retained source/handler proof; it has no in-repository production caller. Its old fixed tests remain unchanged. Actual production source_expr_arg_context_at and parameter-list word extents no longer consume that compatibility scanner. Missing original outer Expr word/role representation remains unavailable: prefix geometry cannot manufacture it, including a source document whose enclosing word cannot yet be retained.

parameter_list_position_at authenticates the current whole analysis source/configuration, reborrows the actual name delimiter extent through word_span_at and reads the parameter word from the existing configured token grouper. NativeWord::written_span_from_group supplies the original complete parameter word extent; the shared param_word_is_literal predicate distinguishes one literal token from computed or expanded forms. No local brace/quote/bareword closing or decoded-value inverse remains in this actual adapter. Computed defaults/arguments stay navigable; this is a source cursor classification, not a formal binding/activation or declaration/edit grant. The current ProcDef/MethodDef inventory still supplies which original header is queried; this patch does not broaden its owner or claim an Installed inventory.
