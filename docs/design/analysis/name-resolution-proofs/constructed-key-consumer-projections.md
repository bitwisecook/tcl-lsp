# naming.analysis.constructed-key-consumer-projections

Kind: `implementation-contract`

## Problem statement

Analytical command/class/procedure inventories and diagnostic groups use different name presentations. Local delimiter splits can collapse a constructed lone-colon segment or mistake literal reporting geometry for an original namespace/procedure owner.

## Question

Which shared projection governs literal diagnostic QName grouping versus constructed class/procedure/inventory holders and tails, and what independent producer/source/metadata guards remain necessary before actual lookup, factory or creation reasoning?

## Conclusion

Literal W214 grouping delegates reported_qname_namespace with LiteralPrefix and keeps its existing String/default semantics. Constructed graph and inventory consumers delegate key_holder_and_tail or key_tail, preserving lone-colon segments, root/bare holders and qualified nonempty recovery selection. The query does not recover an arbitrary native component path. Existing original source class lookup, positioned procedure/invocation, original module/source/availability correspondence, hierarchy and manufacturer/layout requirements remain independent; displayed labels cannot replace absent receipts. Marked fixed software controls exercise reporting, graph, recovery and placeholder surfaces. No assertion outcome, external provider execution or general source/factory/type-soundness closure is attached. The LSP Itcl member projection uses an explicitly supplied Registry for standalone constructed rows. Contextual callers obtain the descriptor family only from complete retained input matching the analysis-owned command realm/store; missing or foreign input and absent grammar withhold family metadata. The standalone projection control preserves its expected holder/tail and refusal assertions without establishing contextual source currency. Implementation navigation uses exact shared class-hierarchy keys in its explicitly admitted lexical branch. Its original-source branch authenticates complete source/configuration and class/method declaration identities; method_implementations_in_inventory requires a unique declaring owner, retained original instance ancestry and exact method-name policy/bytes. Class-object methods select only their declaring class. Report equality or root stripping cannot identify an original method, live class, MRO or dispatch target. The opaque namespace-import trust roster receives a constructed command-key label, not an import pattern or original Native word. Shared written_command_parts and ByteNamespacePath preserve a qualified empty command tail before the shared checked key formatter; no normaliser may erase that tail first. Authored rebound-name invalidation delegates shared bareword_resolution_candidates, including namespace-relative qualified names. Both projections only withdraw MAY trust and mint no command slot, body ID or Native callable receipt. The former optimiser namespace wrappers exist only as private geometry fixtures.

## Scope

Linked fixed controls supply source definitions; current assertion acceptance remains independent. Colon/Unicode/NUL reporting inputs are metadata examples, not native namespace semantics or addressability observations. Constructed key geometry does not replace original command/namespace/class/procedure receipts or independent logical compatibility admission. C Tcl/Jim/BIG-IP processes are not applicable and not tested; no Native getter, callback chronology, dispatch, class/factory or creation effect is inferred. The linked LSP constructed-member control supplies its Registry explicitly and covers descriptive partition, family and member-row selection. Contextual retained-input family selection and current-source guards are separate source obligations described by naming.core.original-dispatch-region-context. This clarification adds no assertion execution or provider outcome.
