# naming.core.original-comment-source-context

Kind: `implementation-contract`

## Problem statement

Comment diagnostics and corrections can lose the actual source grammar, declared Body syntax or physical line boundary when they rebuild nominal context or borrow cooked interior coordinates.

## Question

How do comment diagnostics and next-line consumers retain the actual original image, full grammar and Registry generation without turning syntax inventory into evaluation authority?

## Conclusion

original_script_comment_facts projects physical comment facts from the complete original image and genuine explicitly supplied source script spans. Boundary, encoding, lexer and physical-line checks decline unmapped text. Core validates the full actual Analysis/source/configuration/context correspondence and uses the common Syntax body inventory, including genuine declared Body syntax. Unspecified declaration timing and ReferenceOnly provide syntax only, not PotentialEvaluation. Dynamic, cooked, compound, shadowed or stale body ownership supplies no interior coordinates. W115 correction uses complete original physical lines and refuses an inline command prefix beside a body comment. Server, CLI and sweep consumers pass the actual analysis. Independent style checks retain their own applicability. This supplies no runtime body/frame, compaction or execution-equivalence claim. script_comment_facts_from_analysis and parse_noqa_line_suppressions_from_analysis share the Compiler actual-input owner. Next-line suppressions initialise after retaining actual input, declared contracts and original realm but before diagnostics in whole-file, chunked, command-snapshot and per-item ingress. Definition-member regions retain one genuine parent lexical plan and accept only complete original argv through the shared Registry byte-valued layout kernel. Only explicitly selected wrapper blocks retain parent definition vocabulary; method/lifecycle/accessor/lambda scripts do not inherit it. Unknown selectors/expansions, foreign words, trimmed argv and cooked/compound bodies decline. Original source_expression_script_bodies shares one whole original expression operand, actual full expression grammar and exact command-region byte rebasing with Core structure/traversal/comment inventory. Multiple fragments and unavailable ownership decline. ReferenceOnly and declared Body without timing remain Syntax only. These source regions supply no entered frame, current binding, Native compiler admission, completion or rewrite equivalence. OriginalSourceScriptBody::definition_parent_for is the shared source-vocabulary parent owner. An authored definition-body schema selects its own genuine body. Ordinary nested source bodies inherit a retained containing parent only under actual Plain body kind, Current interpreter and SameInvocation timing for every selected Body position. Full image/configuration/context and containment are mandatory; structural, deferred, ReferenceOnly, foreign, unrelated or unavailable bodies supply no inherited vocabulary. OriginalSourceDefinitionMemberRegion retains the complete genuine region argv; member_keyword applies actual member availability independently of script_bodies layout. A genuine complete keyword may survive an unknown formal/optional selector while its body layout declines. Wrapper blocks retain vocabulary; ordinary method/procedure/lambda bodies clear it. Physical comments and next-line suppressions share this owner with executable/semantic/readonly-structure consumers, without Native entry/frame/effects authority. Core definition cursor inertness and namespace source fallback use offset_in_physical_comment_in_analysis, which delegates retained script_comment_facts_from_analysis under the full current original image/configuration/input. A physical line beginning # inside a multiline quoted word retains live substitution applicability; a genuine later physical comment is inert. Stale image/configuration or missing retained input declines. Absence from the physical comment inventory does not classify every other inert/live source form: data-purpose advice remains independent. The public current-line compatibility scanner is explicitly approximate and supplies no original analysis ownership.
