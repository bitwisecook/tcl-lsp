# naming.completion.return-evaluated-argument-worker-grammar

Kind: `native-observation`

## Problem statement

An alias targeting original return with no bound operands exposes evaluated-argument public behavior separately from direct original return source. A changed code operand or failed family-branch setup cannot answer parity for the original operand vector.

## Question

What public completion fields does a newly created original-return alias produce for the76 fixed evaluated-argument cases, and which C8.5 nested-option results differ from the direct source observations?

## Conclusion

Six fresh CLI processes execute corrected383 and return 76 complete public rows each, exit 0 and empty stderr. Each case preserves the corresponding379/380 operand spelling; only its return command position uses original_return_worker. C aliases are created by interp alias and the Jim alias by its actual alias API, with no bound operands. C8.5 options_nested_before_outer_code reports -code 1 through the alias while source380 reports -code 0. C8.5 options_repeated_nested_invalid_then_good returns catch 2/-code 0 through the alias while source380 returns catch 1/-code 1. The complete counted result/error/options fields are retained independently. Prior382 remains a separate actual control: three -code return values were changed to original_return_worker, so those rows do not establish the original operand comparison. Prior381 retains its Jim missing-global setup failure and all five C outputs. No software implementation pass or generic compiler/instruction equivalence is inferred.
