# naming.source.original-class-publications

Kind: `implementation-contract`

## Problem statement

Canonical class declarations can remain available after their conditional source factory slot moves, is deleted or is replaced. Appending original declaration labels to package inventories can revive withdrawn suggestions; unrepresented declaration cards also need a purpose separate from surviving root source cells.

## Question

Which genuine original class factories survive as conditional source publication candidates, and how do current slots, canonical declarations, known terminals and unrepresented source cards retain their independent purposes?

## Conclusion

OriginalSourceClassPublications retains final surviving direct SourceClass cells from the authentic root source graph and separately retains original factory ancestry. Each publication keeps the canonical complete factory declaration and original name input independently of its conditional current source slot, selected authored naming policy and actual written move lineage. Factory applicability, unavailable actual lookup, written transition applicability and unknown earlier mutation remain explicit obligations. Whole genuine operations with unresolved effects remain attached; an unknown method call supplies no known class transition. Represented known moves select the moved slot, while deletes, procedure replacement and alias replacement withdraw that class suggestion without recovering the original declaration label. Genuine declarations outside the represented root graph remain separate canonical cards with publication=None, not final publication facts. The source_structure facade requires retained complete input, exact source image/configuration, current Registry context and authentic realm. The returned inventory seals that exact input; held candidates refuse missing input, changed image/configuration, foreign store or changed availability. Candidate source_name preserves the canonical SourceCommandPublication purpose while selecting its current source slot. Native authored factory naming policy remains a source-purpose selection; explicit Logical class metadata has its own owner. Server package/autoload command inventories consume this shared candidate projection. No conditional receipt establishes an allocated class, installed command, actual factory success, current token, completed Native world, entered dispatch/frame, navigation identity or edit authority. Indexed consumers use candidates_from_retained_records with the exact retained ResolvedAnalysisInput and canonical original records, without reconstructing a profile or QName. WorkspaceIndex stores the sealed source inventory and input separately from its immutable original declaration/navigation inventory and any independently supplied completed world. Current readonly candidate/assistance selection uses the surviving conditional source slot while mapping to the canonical original declaration, so a moved New candidate does not revive Old or Removed. Settlement dependency records retain current slot, original factory geometry, lineage, unknown-operation premises and obligations; reindex/removal/slot reuse changes or withdraws that advice. Missing/foreign/configuration-drifted retained input withholds candidates even when original declarations remain available, and actual unavailable factory vocabulary creates no declaration. Canonical original source navigation and current conditional candidate advice remain distinct from runtime object allocation, installed/current Native tables, entered lookup/frame, execution and edit authority. Core class-command and method candidate consumers retain authentic source_constructor_call_at at each original call horizon rather than replace earlier applicability with the final inventory. A boxed genuine source call keeps its own obligations and captured effective selector; a captured selector does not create a cursor operand. Workspace unresolved class-name advice selects current publication slots while canonical original MRO/declaration records remain independent. SourceClass::matches_source_declaration is only the canonical original occurrence join used by source_class and publication candidates. A positive Native name-input domain is required before these consumers intercept a call; Logical and hosted factory source receipts cannot become Native method queries or block separately admitted Logical advice.
