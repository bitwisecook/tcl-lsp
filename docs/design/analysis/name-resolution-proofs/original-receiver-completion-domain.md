# naming.consumer.original-receiver-completion-domain

Kind: `implementation-contract`

## Problem statement

Fuzzy method completion requires an authentic positioned class or instance candidate universe and complete retained document context. A missing source receiver cannot be filled from String-keyed class/instance reporting maps or a caller profile.

## Question

Can fuzzy completion preserve authentic class/object declaration candidates while treating a missing Native receiver as terminal and keeping nominal Registry receiver advice inside independently Logical inputs?

## Conclusion

The fuzzy receiver universe uses genuine positioned original class candidates or instance_method_completion_record over InstanceCompletionSource. That shared source owner retains complete conditional original construction/receiver ancestry or an independently positioned current receiver, canonical original class metadata and authentic effective argv. Candidate position keeps captured selectors separate from later written arguments. Native/hosted misses never fall through dispatch_receiver_of or nominal receiver/class reports. String receiver inference remains inside the independently selected Logical advice domain, with its class and method bucket selected together. Registry instance metadata there uses the actual retained ResolvedContext and DocumentFloor package availability instead of a fresh profile query. Authentic primary and fuzzy source candidates share filter_candidates and decorate_fuzzy_items; typo ranking follows candidate selection. Clearing nominal maps cannot remove genuine source candidates, and unrelated injected reports cannot supply a Native method candidate. Source candidate names grant no current receiver, installed method, navigation or rename identity.

## Scope

Readonly candidate selection for source class/object records and explicitly Logical nominal Registry receivers. Complete source/configuration/context checks, conditional construction ancestry and independent current object ownership stay with their original OO owners. Authored C8.6/C9.0/C9.1 positives and stale/context/report-map negatives do not observe native execution or attest installed objects, dispatch, complete runtime class inventory, Normal, writable references or rename safety. Source method geometry and spelling replacement have the separate naming.core.original-source-instance-completion contract. No nominal Native receiver receipt is fabricated when the original candidate owner is unavailable.
