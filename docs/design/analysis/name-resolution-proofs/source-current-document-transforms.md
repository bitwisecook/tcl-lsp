# Original whole-document transform currency

Implementation contract: `naming.lsp.original-document-transform-currency`.

The owner is the existing Server source/input/provider publication kernel,
extended by `document_transform.rs` for original whole-document result handles.
Node and Browser share `documentTransform.ts` and the existing
`replaceDocumentFromSnapshot` host owner. The baseline callers are
`lsp-server-source-transform-command-results` (713),
`lsp-node-transform-response-source-currency` (664), and
`lsp-browser-transform-response-source-currency` (658). Count reconciliation
belongs to Root; private helpers are not separate migration units.

## Admission and retained objects

An explicit source request must match the actual live raw bytes and LSP version.
The actual document revision/language/dialect, source-file allocation, whole
selected input/Registry and configuration/policy, existing factory/input/overlay
and evaluator generations, and original provider publication/path remain held.
Each worker pass retains its genuine current whole source and original input
and Registry. Document workers must match the complete captured SourceFile
input and full original normalised source, so an independently current analysis
with equal bytes under a different input refuses. Safe-fix instead uses a typed
bundle as its actual existing configured-analyser producer. Every pass retains
that same bundle and its own actual input; final admission rejoins exact mode,
extra commands, resource inputs, actual PackSet allocation, policy, dialect and
decode values. It does not equate that distinct purpose to document analysis.
The private bounded ledger can recover only the original returned replacement.
Its original `EditorWireSession` is independently allocated once through the
shared actual OS/WASI/Web Crypto owner and retained as a lossless 16-byte array.
Validation requires that same issuer before local numeric handle lookup. Missing
or malformed issuers, another Backend's same-counter receipt and unavailable
entropy cannot borrow a fresh row. Legacy URI results remain unaffected. This
transport discriminator is not semantic identity or a borrowed CALL registry.
No kind/name/URI label, user confirmation, later current buffer or newly
assembled input can issue or refresh that receipt.

Final response issuance and validation run under the current source-file and
provider path publication guards. The metadata reborrow does not require or
assert a completed diagnostic report. Changed source, reopen, Registry/input,
configuration, policy, provider or generation refuses. Legacy URI responses
keep their existing unbound JSON shape and cannot authorise a new checked edit.

The actual host document allocation/source/version/language, pinned client
session/analysis context and full resource settings are captured before any
mode/request UI. Each async boundary rejoins that snapshot. The final Server
validation is inside the existing replacement helper after editor focus and
before `editor.edit`; the host snapshot is checked again after validation and
before the actual edit. A no-op response takes the optional admission path too,
before reporting accepted success; legacy callers without that option keep the
old no-op behaviour. Real configuration change events invalidate the actual
analysis context, even if values later revert. A stale or malformed response
is unavailable, never a successful empty report.

## Independent limits

Currency is not semantic equivalence, Native admission, command-world closure,
physical source execution, a diagnostic completion or a distributed provider
lock. Minifier refusal/edit/collision barriers and mode flags, optimiser
policy/profile/group rules and pass budgets, diagnostic FixSafety and
DiagnosticEditSource per-pass checks, and safe-fix raw terminators remain with
the original workers. Symbol maps are shown only after the checked write.
Screenshot and other legacy URI clients retain their existing separate host
snapshot purpose; this packet does not silently migrate their Server binding.

## Validation obligations

Preserve all old functions/assertions/source fixtures. Fixed new Server controls
exercise actual minify/optimise/safe-fix command results, legacy result shape,
changed replacement/source, configuration without an input-epoch change, and
reopen with the same original text/version, an actual foreign complete worker
input with identical source, and distinct configured safe-fix parameter changes.
Actual extension controls exercise
a text edit during confirmation, fresh checked success, and a resource settings
change, plus a genuine no-op response whose unissued handle the actual Server
refuses. A fresh-two-Backend control retains identical URI/version/source/result
and first numeric ID: each own issuer passes and both crossed receipts refuse.
Root alone runs ordinary Rust and host/browser checks; source review,
formatting and patch/hash verification claim no build, gate or efficacy result.
