# naming.mcp.original-datagroup-suggestion-eligibility

Kind: `implementation-contract`

## Problem statement

A heuristic pattern report can advertise static extraction even though its selected hosted or Native analysis supplies no independent source-edit permission. A reconstructed profile grammar can also differ from the actual whole-source owner.

## Question

Does static extraction eligibility remain separate from heuristic data-group suggestions and require the actual current source analysis, full configuration and command store?

## Conclusion

MCP captures analysis through its actual dialect and pack-overlay ingress. suggest_for_analysis requires complete current source/configuration correspondence and the actual retained Registry before walking source patterns. Heuristic pattern type, inferred value type and confidence remain report advice. has_static_extraction is true only when this independently selected analysis allows lexical declaration advice and the deterministic extractor accepts the actual cursor, Registry and full configuration. Hosted and Native source policies cannot borrow that compatibility permission. Missing or stale source/configuration/Registry yields no report candidates. Explicit independently supplied lexical authoring remains supported. These report fields establish neither behavioral equivalence nor runtime attachment, cell, availability or edit authority beyond the extractor’s separately selected lexical surface.

## Scope

Current MCP data-group suggestion report and actual analysis ingress. Fixed assertions retain hosted/Native heuristic candidates with static extraction false, preserve a genuine explicit lexical positive, and refuse changed whole source or parser configuration. All seven native providers are not tested; no Rust execution receipt is attached.
