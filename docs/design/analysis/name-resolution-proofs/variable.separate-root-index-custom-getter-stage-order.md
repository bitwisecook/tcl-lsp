# naming.variable.separate-root-index-custom-getter-stage-order

Kind: `native-observation`

## Problem statement

Custom root/index updateString callbacks make ordering observable before any selected receiver exists. A runtime must not reorder those callbacks, render a cached root through another object, or equate pure value bytes with conversion/receiver authority.

## Question

Separate root/index custom string-getter order and lookup failure What exact stages and results occur in the retained native probe?

## Conclusion

The fifty captured native records retain exact custom getter visit order and resulting original headers alongside selected/null lookup and error/quiet presentation for the five root shapes. These observations establish ordering for these probe callbacks only; they do not close arbitrary getter/free hooks, normal stores or compiler frame capabilities.

## Scope

C84-91 custom originalRootGetterProbe/originalIndexGetterProbe, fresh and cached combined root controls, separate Tcl_ObjSetVar2 quiet/error modes; exact all stages, no Jim/BIG-IP.
