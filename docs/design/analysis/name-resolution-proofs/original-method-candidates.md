# naming.editor.original-method-candidates

Kind: `implementation-contract`

## Problem statement

A class/member display spelling can conflate opaque siblings, and two documents can contain identical declaration bytes without sharing ownership. An editor can also mistake a later metadata route for an authentic method selected at an earlier call.

## Question

How does one readonly Core/Workspace selector preserve genuine class/selector inputs, receiver side, canonical declarations and URI ownership while refusing incomplete receiver or relation evidence?

## Conclusion

The sealed query retains the original selector and complete consumer image/configuration. A temporal receiver selection identifies its canonical local member independently of the queried route. Pure external class lookup checks earlier occupied proc and class headers before selecting a source own-table candidate. Explicit instance declaration advice uses the shared exact-record MRO and validates relation occupation. Local Core and Workspace candidates share the same declaration/lookup kernel; local definition, references and hover preserve the complete nested declaration image. A lexical variable root or retained variable conflict keeps its separate variable editor purpose even when the produced value is an OO selector. Missing original method lookup or selector owners are terminal. Missing receiver entries, reporting-only class guesses, incomplete ledgers or relations, duplicate independent owners and stale source are terminal. Identical complete views within one URI are deduplicated; equal documents under different URIs remain independent. Declaration advice supplies no live object, native dispatch, callback execution or source edit.

## Scope

Readonly local Core and Workspace method source candidates and selector occurrence rows. Fixed C8.6 source assertions distinguish surrogate D800/D801 class/member names, same-URI append views versus independent URI duplicates, missing/duplicate superclass providers, instance-versus-class-object side and earlier procedure occupation. Local definition, reference and hover queries use genuine analysis inventories without constructing a WorkspaceIndex; nested method declarations retain the complete parent source image, and changing an unrelated enclosing namespace withdraws all three providers. Reporting-only receiver/class guesses cannot replace an original receiver. Unresolved command and external class selector controls preserve actual lexical variable reads; retained variable conflicts stay with that provider. Removed or foreign original method lookup owners decline before reporting assistance. Class-object advice covers the selected source own table only; makers, object mixins, registered delegates and native-owned slots require separate temporal ownership.
