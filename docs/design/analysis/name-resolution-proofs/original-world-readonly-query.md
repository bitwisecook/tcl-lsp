# naming.command.original-world-readonly-query

Kind: `implementation-contract`

## Problem statement

Readonly source-name geometry may use a retained borrowed ledger only when selecting the actual policy and retained root changes no ledger field. Skipping preparation through a display/configuration shortcut could revive a withdrawn world or select another naming recipe; an owned prepared copy must leave the supplied original state unchanged.

## Question

Which exact original ledger and entry facts permit readonly borrowing while preserving policy preparation, refusal and subsequent source-world mutations?

## Conclusion

Readonly queries borrow only the exact original world when the actual baseline supplies the same positive native naming recipe, that world is not withdrawn, and the actual source root is already retained. Every other case owns a private clone and applies the existing policy preparation. Consumers retain all independent table, source, availability, compiler, frame and Native currency checks. No persistent cache or semantic equality/hash change is involved. Three direct software definitions retain exact borrowing, owned preparation without supplied-state mutation, and current policy/COW withdrawal refusal. Seven readonly consumers share the selected view.

## Scope

Rust software owner contract for readonly original source command-world geometry. It establishes no Native object/current-provider freshness, successful worker, entered body/frame, result/value/store or edit permission. The three test definitions and their real module parents are inspected as current source only; no successful producer, executable listing, passed assertion, speed improvement or timing dominance is supplied. Their fixed C/Jim baselines select Rust recipes and are not external-provider comparisons. An earlier retained view stays valid only for its original immutable world and supplies no currency for a subsequently withdrawn world. Clone measurement fields are outside semantic world identity; no persistent cache is involved.
