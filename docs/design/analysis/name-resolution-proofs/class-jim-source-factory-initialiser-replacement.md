Kind: `native-observation`

## Problem statement

A current Jim class factory can change a previously authored two-word procedure slot. A conditional source member ledger needs independent public evidence of the exact stock slots and the conditional baseclass case; later authored overrides need their own chronological control.

## Question

Which pre-existing two-word procedure slots are replaced by the current Jim class factory, is baseclass replacement conditional on nonempty BASES, and can a later raw procedure replace a stock member?

## Conclusion

In recorded Jim 0.84-9-g5bac7c9, all twelve listed factory initialisers have factory catch code zero and no retained equality with the earlier STALE procedure body. Eleven have info-body catch code zero and a different body; constructor has info-body catch code one, so this probe does not expose its new body. The baseclass slot retains the earlier body when BASES is empty and changes when BASES contains ActualBase; the later baseclass call returns ActualBase. A raw Later get procedure written after the factory returns CUSTOM through the subsequent object call. The five stock C processes catch package require oo rejection, expose no class command and mark all initialiser controls not applicable; this does not assert TclOO absence. Six process exits are zero with empty stderr because finite guest errors are caught. BIG-IP is not tested. Public body equality and return values neither prove a native procedure/alias/header implementation nor donate execution or member identity to a Compiler source carrier.
