# naming.compiler.file-worker-attachment-roster

Kind: `native-observation`

## Problem statement

A public file ensemble member can exist while its private worker has no compiler hook, or the worker can be absent in an older release. An existence-only inventory cannot select a compiler recipe.

## Question

Which original file/private-worker commands exist and carry compileProc in each captured C interpreter?

## Conclusion

The native roster reads each original command token and compiler attachment. A -1 row means that named worker was absent; zero means present without an attachment. These are bootstrap token observations, not entered filesystem behavior or a source availability proof.

## Scope

Only the original retained programs, capture windows and provider labels in the attached artifacts are covered. Version labels are original receipt metadata, not a fresh patchlevel query. Missing command/API doors and aborted processes stay distinct from successful guest completion. Source files/probes explain the observer protocol; no pinned engine implementation excerpt or executed Rust assertion is claimed. Different attempts and sources are retained separately, never treated as byte-identical duplicates.
