# naming.tcloo.bootstrap-private-and-definition-namespace-owners

Kind: `native-observation`

## Problem statement

An object label or source namespace cannot establish the actual object-private or definition namespace.

## Question

Which private namespace and ordered path, definition namespace pointers and support-worker paths belong to these actual bootstrap objects?

## Conclusion

All observed C8.6/C9 object-private namespaces retain ordered [::oo::Helpers, ::oo] paths. C9 classRoot stores class-definition namespace ::oo::define; objectRoot stores object-definition namespace ::oo::objdefine. Configurable and support class facets store the measured configurable class/object definition namespaces; the corresponding worker namespaces retain paths to define/objdefine. Support rename preserves its private and definition namespace relationships.

## Scope

Configured original C private/public object APIs on fresh bootstrap and explicitly printed rename/lifecycle/dispatch controls. ASCII Tcl_EvalEx source controls and actual selected header fields; no compiler admission, cache, variable, method-body, observer, Registry-role or Rust parity capability. C8.4/C8.5/Jim expose no oo::class in the measured initialized interpreter. BIG-IP not tested.
