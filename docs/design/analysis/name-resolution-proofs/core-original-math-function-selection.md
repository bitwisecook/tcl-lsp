# naming.core.original-math-function-selection

Kind: `implementation-contract`

## Problem statement

An expression function identifier is not an original script command head. C 8.4 and Jim select fixed function tables, while later Tcl can select a command-table implementation. Looking up a same-named procedure or constructing a qualified wrapper from the displayed identifier confuses these purposes and loses current source allocation identity.

## Question

Does readonly Core math-function selection preserve the original expression producer and its independently selected function-table or command-table target?

## Conclusion

The current-image facade consumes the authentic complete source, full lexer configuration, retained Registry and expression-function inventory. It retains each original identifier and selected dispatch purpose. Procedure metadata is joined only through the independently retained actual implementation allocation; cleared reporting maps and command invocation rows do not erase the original inventory. Missing target remains terminal, and no script-head input, wrapper command, execution or edit authority is issued. Command-function navigation, incoming call edges and reference spans share that canonical procedure allocation under an independently owned current document inventory. Equal-source duplicate provider owners remain ambiguous.

## Scope

Core readonly expression-function selection, including local overrides, independent same-named procedures, missing targets, stale source and fixed-table metadata. Command-table reference and function syntax ownership remain separate from any writable identifier contract.
