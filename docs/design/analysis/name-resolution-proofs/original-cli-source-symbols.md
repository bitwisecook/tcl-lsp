# naming.consumer.original-cli-source-symbols

Kind: `implementation-contract`

## Problem statement

CLI symbols extracted from reporting Scope maps can collapse repeated declarations and opaque byte siblings. A rendered function label cannot select its parameter row or restore declaration ownership.

## Question

Does CLI source-symbol reporting consume current original source cards and preserve independent declarations when reporting maps are cleared?

## Conclusion

Native and hosted CLI symbols use the shared current source outline. Independent opaque and repeated declaration rows retain their source extents. Procedure parameters join only by an unambiguous exact source span from the original procedure inventory; labels supply no join. Nested local variables remain outside the global-variable report. Explicit lexical declaration advice retains its separate Scope view. Symbol names and event spelling are presentation, with no command binding, runtime normalization, edit or native execution grant.

## Scope

Current CLI symbols for selected Native, hosted and explicit lexical advice. Fixed assertions distinguish repeated opaque names, changed reporting maps, hosted event cards and stale whole source. No native or Rust execution receipt is attached.
