## Problem statement

Nominal command spelling and a source argument count can choose an unrelated completion member when aliases insert operands, expansion changes argv or an inner command is shadowed. A rendered profile does not supply the current full availability context.

## Question

How does command-context completion retain current original effective ordinals and its independent hosted source schema?

## Conclusion

The primary context completion selector requires actual whole source/channel/configuration and the retained Registry/ResolvedContext. It consumes the shared original invocation traversal and unanimous effective command/argument origins, preserving captured prefix and expansion ordinals. Hosted completion uses its genuine guarded conditional Registry vector and authored source units independently of C/Jim argv recipes. Member, option and argument suggestions use the selected context query only after that source selection. Known shadowing and stale or unavailable owners remain terminal, and an inner command cannot borrow the outer schema. The output supplies contextual source suggestions only, without handler implementation, effects, Normal, native lookup or runtime/edit authority. Current source completion uses the common complete source receipt and clones the authentic selected per-point descriptor, retaining its effective arguments and original captured/written origins. Actual available package/subcommand/option surfaces govern proposals; an equal command store or stale source cannot donate current options. Option values consume only the selected available option table after the shared original outer and nested selector path gate. Missing, dynamic or unknown nested selectors cannot borrow sibling-form option unions. Hosted and ordinary source projections retain their existing full input/configuration/context owners; withheld option vocabulary does not suppress unrelated event or subcommand advice.
