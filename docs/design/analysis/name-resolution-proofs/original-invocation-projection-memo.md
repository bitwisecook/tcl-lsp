# naming.source.original-invocation-projection-memo

Kind: `implementation-contract`

## Problem statement

Original stamping repeats complete lookup and observation attachment for identical descendant source points under one immutable realm, across different enclosing token vectors.

## Question

How can original token stamping share complete derived point projections without substituting another source interpretation?

## Conclusion

One immutable realm owns a bounded cache of the shared original invocation query at exact offsets. The factory ignores presentation head text and selects genuine points under the complete root/config/Registry/entry/input/namespace/frame/variable inventories already sealed by that realm. The full derived result is retained, including all residuals and unknown outcomes.

## Scope

An immutable realm retains at most 256 exact-offset point results. A completed read-only RetainedSourceBodyInventory first uses its retained Logical realm when that realm is available; otherwise its own invocation memo retains at most 4096 results over its complete inventory. Clones share their owner's caches. Each newly constructed selected child owns a separate invocation memo; a replacement realm or independently rebuilt inventory also starts fresh. At either capacity, an uncached point still runs the ordinary query and returns its complete result. Capacity does not prove absence or completeness. Realm equality excludes derived memo state. Mutable SourceBindings builders retain ordinary querying without these immutable-owner caches. Original token correspondence and current Input/lookup/CPP/Normal/frame obligations remain unchanged. These limits and branches are an inspected Rust implementation contract, not an executed body-memo or performance result. The existing 80-level/default-stack selector is unchanged; timing/pass claims require actual execution.
