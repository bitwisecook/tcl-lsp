# naming.variable.original-readonly-formal-topology

Kind: `implementation-contract`

## Problem statement

A refactor binding arguments through ProcDef.params can collapse opaque formal names or lose default/rest/link roles. Exposing a full activation owner for source assistance would give topology an unrelated runtime authority.

## Question

Can a readonly procedure signature expose exact native formal bytes and binding ordinals while keeping activation entry private?

## Conclusion

SignatureSourceFormalParameters retains the original ParamList Key, exact ordered ByteFormalParameter values and the independently selected required/default/rest/link grammar. AnalysisResult issues it only for an exact retained declaration and unanimous Registry-selected declaration recipe. The facade preserves producer image/channel and full parser configuration; it neither installs formals nor proves command liveness, caller identity, cell contents, physical frame, native objects or Normal completion. Readonly worker parameter syntax may parse a genuine complete original operand with an independently selected dialect; the caller retains the separate ParamList role obligation. Name and optional second fields retain actual native list-child inputs and only independently mapped original source extents. Escape-produced parent values or mismatched clipped fields do not manufacture lexical child geometry. Readonly parameter-list values may retain actual lambda/list-child inputs without becoming complete lexical keys. Intermediate static list ancestry supplies source extents only when every traversed child preserves its literal bytes; evaluated or decoded intermediate values abstain. The complete-word and readonly-value facades share one field projection and the existing native formal parser. Lowering name-only headers use the independently selected WordValueRules and ParameterGrammar through parse_formal_parameters_in for both procedures and members. Missing grammar declines. Jim qualified/array-shaped and link-spelled source names retain their own name syntax; they do not issue ordinary C local storage, a caller-link frame or positional/default/rest activation. parse_param_list_strict_in takes independently selected word-value rules and parameter grammar for native-valid syntax only; parse_param_list_strict remains authored C compatibility. E006 formal/lambda diagnostics, original procedure replay and bounded factory syntax use the selected grammar and decline unknown axes. Inlining and ordinary bounded lambda activation additionally require the C parameter axis; Jim naming/reference headers do not supply a C frame. Structural prefix counts remain governed by the central arity representation.

## Scope

Rust readonly original formal metadata for explicit C Tcl and Jim source recipes. A fixed all-six model test covers opaque native names, default and rest binding counts and source/configuration mismatch. Native installation and formal storage observations remain separate. Procedure/member lowering source-name headers keep syntax acceptance separate from installation and activation; duplicate final-rest syntax follows the actually selected C or Jim grammar.
