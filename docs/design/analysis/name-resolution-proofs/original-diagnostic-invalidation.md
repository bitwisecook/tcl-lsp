# naming.editor.original-diagnostic-invalidation

Kind: `implementation-contract`

## Problem statement

Opaque provider names, unchanged display maps and changed complete source/configuration can leave dependent workspace diagnostics stale when invalidation compares only Unicode command labels and arity sets.

## Question

Does diagnostic invalidation retain actual original provider source/header facts and match genuine caller dependencies while refusing to lose unknown relevant Tcl consumers?

## Conclusion

The workspace retains the actual complete source image, full scanner configuration and independently selected original/logical advice mode as readonly invalidation context. Diagnostic provider facts compare that context plus every original procedure/class declaration and surviving source publication. Changed native slots/policies and allocation sites are matched against genuine original caller inputs, lookup paths and selected implementation sites. Missing, stale or conflicting relevant caller dependency inventories conservatively invalidate all relevant open Tcl source participants. JavaScript, BIG-IP configuration and other foreign surfaces contribute no Tcl dependency. These dependencies schedule diagnostics only; they grant no binding, runtime world, command existence or editable reference.

## Scope

Rust workspace diagnostic scheduling contract. Fixed tests preserve exact source/configuration through clone, replacement, removal and reused slots; change an opaque provider while both display projections remain empty; retain a genuine byte-key caller despite counterfactual reporting labels; discriminate its opaque sibling; preserve unknown/stale caller conservatism and exclude foreign buffers. Native outcomes and Rust test execution are not asserted.
