# naming.compiler.original-dispatch-ledger-subjects

Kind: `implementation-contract`

## Problem statement

A dispatch-contents ledger can normalise a selected Registry descriptor label as though it were the original called slot, or let raw Logical eligibility stand in for a supplied Native entry. Written transition geometry, actual alias/import/moved slots and byte-exact descriptor data then become interchangeable and an authored pristine baseline can be overclaimed.

## Question

How do production GVN and native lowering use the same contents fixpoint while admitting only an original complete Logical/Standalone direct unmoved builtin slot, without borrowing Native or AuthoredSimulation purpose or parsing a descriptor into lookup authority?

## Conclusion

The checked consumer reuses the existing contents fixpoint and asks for a subject only when replay reaches the actual invocation site. Its original binding reborrows the production original_recorded_command vector, matches all GenericInvoke.original_words, joins the current actual metadata and central purpose, and checks complete selected Registry facts. Only Logical/Standalone direct builtin references at the same original invocation site whose called slot equals their retained origin supply the ledger subject. That rooted constructed slot loses exactly one root through Syntax; the selected descriptor label stays data. Alias/import/moved, missing/foreign/changed owners, Execution and AuthoredSimulation supply no site proof. Written transition keys use shared canonical_written_command and preserve a trailing separator under the explicit authored model. Three FunctionUnit GVN entry adapters and the one native Lowerer use this checked sibling; the public low-level explicit-assumption analysis retains its authored compatibility purpose. Native trace absence and Native domain contents remain independent owners. Five fixed source controls have no attached assertion or provider execution.

## Scope

Finite dispatch_proof contents/site capture, three production GVN callers and one native_lowering caller. The fixpoint/edge commit/cleanup algorithms are shared. This question certifies source interfaces and unexecuted control definitions only, not full Native dispatch-state capture, world/session sealing, invoked command identity, successful lowering, receiver/class hierarchy, imported pack selection or external provider semantics. Authored pristine assumptions remain explicit and are not runtime facts. Other method relation and source-world producers are independent.
