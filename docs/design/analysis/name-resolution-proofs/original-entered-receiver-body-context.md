# naming.variable.original-entered-receiver-body-context

Kind: `implementation-contract`

## Problem statement

A class-wide String union can donate later or inherited instance variables to a method. Filling a cleared original execution domain from a compatibility overlay can also merge cells across worker/event lifetimes.

## Question

How do method IR facts retain the genuine entered provider, receiver axis, original formals and independent variable/execution context?

## Conclusion

OriginalReceiverBodyContext is issued only at the genuine entered body boundary with the selected declaring provider, explicit Instance/ClassObject/OwnObject axis, exact formal topology, source/configuration and activation context. Lowering selects only unanimous entered observations. Original method facts retain counted formal inputs separately from compatibility parameter labels and never seed current variables from a class-wide String union. Missing entry remains unknown. Replacing an original point context cannot restore cleared instance, interpreter or execution fields from a compatibility overlay.

## Scope

Rust Compiler original method/context transport and source-only unresolved method facts. This supplies no native CPP/table layout, object header, ordinary contents, successful store or broadcast publication. Independent compiled/runtime TclOO matcher and per-TMM execution-domain proofs keep their own scope.
