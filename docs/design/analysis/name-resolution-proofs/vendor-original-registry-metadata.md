# naming.vendor.original-registry-metadata

Kind: `implementation-contract`

## Problem statement

Hosted F5 source names retain vendor context rather than a C/Jim naming recipe. Requiring a native command key loses legitimate source metadata; decoding unsupported vendor operands through a C dialect would substitute another producer.

## Question

How can readonly Registry roles retain original hosted source provenance without granting native lookup or execution?

## Conclusion

Vendor source metadata requires an exact hosted-context match between the retained head policy and the actual analysis ContextRegistry. The shared structured selection retains that supplied context and its command store, including keyed versions and overlays. Unknown units retain their ordinals without acquiring C/Jim recipes or executable facts. Authored source roles are projected separately from native procedure-definition acceptance, so a missing C/Jim recipe cannot erase hosted source grammar or grant executable definition facts. Possible variable receiver forms use the same selected descriptor kernel under complete authored roles and accepted source arity, independently of executable native-definition acceptance. Alias declarations, role-only descriptors, unknown expansion and rejected arity cannot supply a receiver form. A complete non-expanded original word with an unavailable value remains a single readonly source operand; unavailable source shape and expansion retain unknown cardinality. VendorSourceNameInput::root_command_coordinate retains an authentic complete original authored root coordinate before selecting source Registry metadata. Plain, rooted, repeated-root and braced-rooted heads retain the same source descriptor; dynamic heads and escaped whitespace decline. This coordinate supplies no measured TMM dispatch or Native name key.

## Scope

Authored Registry metadata shape only. The complete retained ResolvedContext and command-store content key support this selection; static profile contexts cannot replace the actual analysis generation. Explicit iCall with no matching registered context declines. Runtime presence, shadow closure, Native authority, Normal and compiler admission remain independent. Complete readonly receipt equality compares all retained context fields, original inputs and command-store content; a digest or environment label alone is not an identity.
