# naming.source.original-point-operand-projection

Kind: `implementation-contract`

## Problem statement

Readonly operand queries can repeatedly traverse enclosing source inventories instead of the retained actual invocation.

## Question

How does a readonly namespace operand reuse its actual immutable point binding without replacing its original source or value owner?

## Conclusion

The immutable realm reuses its complete exact-offset invocation projection only after the caller's full source image, channel and configuration match. The binding matches a unique original word or first-token extent in its retained complete vector, then uses the unchanged original input factory and current frozen-value checks. Namespace recording and namespace scope geometry supply the actual dispatch offset; their existing independent static-input fallback and policy checks remain separate. Immutable original lexical projections reuse complete source/channel/config/offset/vector derivations while reverse namespace indexes reuse only their actual retained table Arc and exact implementation/holder alternatives. Cache warmth remains outside semantic identity.

## Scope

Readonly original operand correspondence only. Existing bounded point retention, replacement-realm freshness and unknown results remain unchanged. No argument role, namespace existence, lookup, Native compiler admission, entered frame or Normal follows. Mutable SourceBindings builders retain their ordinary scanner. These deterministic software geometry/reuse controls measure neither timing nor Native admission. Changed geometry refuses, independent equal origins/tables retain independent cache ownership, and original Native execution or source-point outcomes require their separate receipts.

## Immutable identity and derived memo lifetime

`SourceOriginId` retains its unchanged semantic kind, fingerprint and activation key. `OriginalSourceAnalysisOwner` retains its actual allocation identity and immutable original source, complete metadata and configuration. Their Eq/Hash policies do not depend on cache warmth. Mutable lexical projections and the analysis owner's existing weak registered-instance/operand-cache links and conditional-declaration memo are kept outside these key types in private derived sidecars.

A sidecar belongs to the actual Arc allocation: an address is only a bucket, and lookup must upgrade the retained Weak owner and compare the complete actual Arc pointer. Equal-valued independent allocations do not share a memo. The sidecar retains no strong owner, removes dead-owner entries on access, and releases its registry lock before lexical parsing or source interpretation. The existing weak baseline and weak independently owned source-cache checks remain unchanged. A derived result never becomes source identity, metadata admission, Native lookup, entered frame or semantic permission.

`OriginalSourceProjectionMemo` also owns one `NestedBodyCutMemo` for the same origin's whole image. It records a command-substitution body only after the unchanged recursive parse-cut walk of that body finished clean, keyed by whole-image body extent, full lexer configuration and channel. Bodies that cut or whose lexical stream or geometry is unavailable are never recorded and are walked again, so every projection keeps the unmemoised first cut and refusal. `SourceOriginId::original_script_words_in` shares the same memo for checked script-word plans of regions of that image — the source transition advice root plan and its body walk — whose plans equal the unshared capture. The sidecar is derived warmth: its Debug output names no bytes or keys, and it is not origin identity.

Fixed source/analysis-owner lifetime controls retain products through the real lexical and conditional-declaration routes, drop the owner, and verify weak expiry plus retirement on the next sidecar access. Existing lexical projection controls use the accessor in place of the removed mutable field; their capture-count predicates, values and original source fixtures remain unchanged. These source controls are not claimed executed by this packet.
