# naming.source.original-point-operand-projection

Kind: `implementation-contract`

## Problem statement

Readonly operand queries can repeatedly traverse enclosing source inventories instead of the retained actual invocation.

## Question

How does a readonly namespace operand reuse its actual immutable point binding without replacing its original source or value owner?

## Conclusion

The immutable realm reuses its complete exact-offset invocation projection only after the caller's full source image, channel and configuration match. The binding matches a unique original word or first-token extent in its retained complete vector, then uses the unchanged original input factory and current frozen-value checks. Namespace recording and namespace scope geometry supply the actual dispatch offset; their existing independent static-input fallback and policy checks remain separate.

Immutable original lexical projections reuse complete source/channel/config/offset/vector derivations while reverse namespace indexes reuse only their actual retained table Arc and exact implementation/holder alternatives. Cache warmth remains outside semantic identity.

## Scope

Readonly original operand correspondence only. Existing bounded point retention, replacement-realm freshness and unknown results remain unchanged. No argument role, namespace existence, lookup, Native compiler admission, entered frame or Normal follows. Mutable SourceBindings builders retain their ordinary scanner.

These deterministic software geometry/reuse controls measure neither timing nor Native admission. Changed geometry refuses, independent equal origins/tables retain independent cache ownership, and original Native execution or source-point outcomes require their separate receipts.
