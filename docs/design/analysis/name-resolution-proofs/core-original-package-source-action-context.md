# naming.core.original-package-source-action-context

Kind: `implementation-contract`

## Problem statement

Package insertion and suggestions can reparse reporting requirement labels, treat nested/data words or a provide query as an installed root header, or select candidates from a context unrelated to the source. Native and Logical missing-head advice require their independently authenticated source domains.

## Question

How do package actions retain the actual complete source context, genuine selected package grammar and root insertion geometry without inferring package installation or falling back between source domains?

## Conclusion

original_package_require_insert_offset owns the current full image, actual input and complete grammar, including BOM policy, and selects only genuine root package-require commands. Split-line, shebang and EOF geometry remain original. W120 and Core actions share that insertion owner. original_source_package_already_named uses selected requirement or version-supplying provision syntax; a provide-name query, nested requirement or literal data cannot create a root package header. package_catalogue selects metadata under the actual ContextRegistry. Native actions require the genuine original unresolved-command subject and lookup; positively sealed Logical actions require their complete vector and shared positioned absence under the actual source input. Reporting names cannot replace those owners, and unsupported Native or hosted inputs do not fall back to Logical advice. Package names and proposals remain source metadata and reviewed insertion geometry, with no installed package, loader success, dispatch, file execution or runtime completion grant.

## Scope

Three marked Rust controls retain root split-line/shebang/EOF offsets and changed-image refusal; genuine provision/query/escaped requirement distinctions survive mutated requirement/provision reporting labels. The Logical action fixture uses a sealed no-Native-policy Jim0.79 source profile with an independently supplied C8.6 authoring ContextRegistry. It retains its original unresolved head despite changed reporting names and refuses changed BOM configuration and a Native source domain. That fixture is source advice only and supplies no current Jim or C execution observation. Candidate ranking, package installation and successful edit semantics remain independent.
