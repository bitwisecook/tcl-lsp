# naming.index.original-table-string-regeneration

Kind: `native-observation`

## Problem statement

An Index primary retains a live table entry rather than a frozen displayed word. A duplicate can share that table association while later entry changes alter its regenerated bytes.

## Question

What bytes are regenerated from the original Index and its duplicate after the retained first table entry changes?

## Conclusion

Every C capture regenerates changed from the original and again from its duplicate after the shared first entry is changed again. Both retain Index primary and resident bytes. The probe owns persistent static table/string storage throughout; this does not authorize caches from arbitrary pointers, unloaded extensions or a stale table lifetime.

## Scope

Exact public Tcl_GetIndexFromObj on original String a, distinct static tables first/other, TCL_EXACT and conditional C9 flag64. Tcl_InvalidateStringRep/GetString regenerates from retained mutable static table entries; Tcl_DuplicateObj preserves cache association. Five original output files have complete source/archive/output hashes and successful process status, but no compiler status, header/executable digest or launched runtime version query is recorded. Probe input is C object API, not document source or a guest command selector.
