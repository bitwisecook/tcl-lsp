## Problem statement

Public class-package chronology can distinguish sequential external methods, genuine two-word procedures before or after a factory, and BASES references to current, moved, command-aliased, deleted or replaced dispatchers. Conditional Compiler class-reference syntax cannot answer these native execution questions.

## Question

What public Jim class-package results follow sequential external method declarations, two-word procedures before/after a class factory, and BASES references to current, moved, command-aliased, deleted or nonclass command names?

## Conclusion

The recorded Jim 0.84-9-g5bac7c9 process provides oo package 1.0 and class/alias commands. Sequential external methods return FIRST SECOND 1; genuine two-word procedures written before and after the factory return BEFORE AFTER. Moving the earlier two-word procedure produces a caught unknown-method error. Current BASES imports return BASE 11 22. Moving only the base dispatcher produces invalid command name "HeldBase inherited"; an ordinary command alias base produces invalid command name "AliasName inherited". A deleted base produces invalid command name "DeletedBase"; a nonclass replacement produces missing value to go with key. Every exact caught row is retained. All five recorded stock C installations reject package require oo, expose no class command and print jim_class_controls not_applicable no_class_command; none of the eight class controls executes there. These observations do not establish TclOO absence. Every process exits zero with empty stderr because the finite public guest errors are caught. BIG-IP is not tested. The public outputs remain independent of readonly conditional Compiler class/reference/metadata carriers and do not attest Native class-object identity, native argv/header/object/cache/frame ownership, current installation, arbitrary inheritance or runtime equivalence.
