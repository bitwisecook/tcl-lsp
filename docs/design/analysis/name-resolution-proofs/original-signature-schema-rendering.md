# naming.consumer.original-signature-schema-rendering

Kind: `implementation-contract`

## Problem statement

Signature help discarded the authentic effective source vector after context detection, retaining a canonical String command and one selector. Re-querying a profile catalogue could replace the original conditional availability, captured alias prefix and actual package/context generation.

## Question

Does signature help render the same complete original source schema under its retained availability context while preserving effective argument origins and keeping conditional documentation independent of Native dispatch?

## Conclusion

The context retains OriginalRegistryWords and its full effective arguments, original producers and source classification. Both an independently validated Logical source input and Native source advice use the same full source-schema owner under the retained Analysis ContextRegistry; no reporting command/selector or profile catalogue is reselected. Rendering uses the schema-selected metadata/subcommand and retained package floor, maps the cursor through original written/expanded origins, and states unresolved conditional/source-transition availability. Original procedure advice remains separate. Missing or foreign source/configuration/context/schema withdraws Registry documentation.

## Scope

Readonly signature metadata over genuine complete original Document input, full lexer configuration and retained Registry/context. Positively validated Logical source input and conditional Native source advice share the same source-schema owner while keeping their applicability separate. C and selected Jim source fixtures are authored controls, not interpreter observations. This creates no callable head, runtime lookup, loaded package, handler, observer, Native compilation, Normal or edit receipt.
