# naming.refactor.original-extraction-motion-boundary

Kind: `implementation-contract`

## Problem statement

An extraction can turn local reads/writes into formal arguments or caller links, relocate command lookup and introduce a procedure publication. Exact names and cell identities classify captures but do not authorise these effects. A compatibility String path would silently grant missing movement, observer or insertion permission.

## Question

Does Native procedure extraction classify exact captures and stop before missing relocation or insertion authority?

## Conclusion

Native capture classification consumes original Registry roles, exact lexical roots/operand inputs and unanimous source-owned variable symbols with full cell/frame identity. Alias, unowned and incomplete regions decline. Captured and capture-free plans remain disabled with no edits until their separate motion, observer, caller-link and procedure insertion contracts exist. Native refusal never enters the String compatibility path.

## Scope

Current Core Native procedure extraction interface and capture classification. No general movement or publication insertion contract is present; lexical-only authoring extraction is a distinct branch.
