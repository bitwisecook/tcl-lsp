# naming.optimisation.original-source-purpose

Kind: `implementation-contract`

## Problem statement

A raw analysis-input Logical naming flag can be true for a held Native Jim entry. Choosing Logical optimisation policy from that flag can bypass the actual retained source purpose, and the same shortcut can appear in an alternate has_logical_source_name_context predicate.

## Question

How do actual inline-frame, substitution/procedure purity, chain layout/constant/rewrite, raise-assistance and method-reachability consumers distinguish the retained original Execution, Logical, Standalone and AuthoredSimulation purposes while preserving separately checked source advice?

## Conclusion

The shared binding query joins the complete original vector, source input, Registry, source instance and frame before projecting purpose; the Module sibling owns implicit entry selection. Inline-frame eligibility reads the actual Module Logical purpose. Procedure-purity fallback, chain selected-layout branch and source lattice constant substitution use the original call purpose. Chain executable advice requires Logical; checked Native and AuthoredSimulation source layouts remain hints. Raise assistance requires same actual function metadata plus the retained Module Logical purpose, while its independent folded and normal-completion proofs remain separate. Method classification uses the actual binding purpose before selecting its source versus checked invocation; unknown purpose widens reachability. Its unprofiled Standalone route remains explicit and refuses supplied Native or unknown entries. Genuine fixed software controls capture and retain a real Jim Vm entry, establish its raw Logical eligibility and actual Execution purpose, and independently build a Logical source driver from the same input. They define checks at each actual consumer. A separate explicit AuthoredSimulation entry defines a checked layout remaining hint-only. No assertions or external provider executions are attached.

## Scope

Finite original-purpose policy ports in inlining/frame, elimination/source_purity, elimination RaiseProof, chain_fold and method_barrier. Source geometry, retained purpose and selected descriptors do not grant Native handler/admission, frame/cell/value, trace absence, splice/erasure, completion or general optimisation soundness. Existing independent value, RHS, source, cell, observer, method-target and rewrite guards remain required. Hierarchy relation resolution and dispatch-world contents/name ledgers are separate owners, not certified by this question.
