# naming.tcloo.original-native-factory-role-selection

Kind: `implementation-contract`

## Problem statement

A native command token can identify a stock object command without proving its current class role, constructor, manufacturer method, support allocation or definition namespace. Native factory consumers need the independently captured OO state before accepting source declaration metadata.

## Question

Does native factory selection join the actual same-entry OO allocation, selected intrinsic method, current visibility, topology and retained namespaces without granting successful manufacture or body entry?

## Conclusion

The shared factory consumer joins the selected command token and implementation generation to backend-stamped class roles, constructor and manufacturer method allocations, ordered foundation topology, closed filter and mixin inventories, and retained definition namespaces. Configurable support is selected through the canonical occupied command cell and its independently stamped allocation. Missing or conflicting capabilities, altered handlers, private or unexported dispatch, unknown topology and stale currency decline. Source factory Normal completion and native body admission remain independent.

## Scope

Rust selection of original ordinary class factories under C8.6, C9.0 and C9.1 and configurable factories under C9.0 and C9.1. Positive controls retain an actual backend-captured entry and interpreter owner; negative controls remove or alter individual retained premises. These checks supply stock role and dispatch selection only. They do not establish successful factory execution, created-object identity, callback closure, native body entry, physical property lookup or editable source geometry.
