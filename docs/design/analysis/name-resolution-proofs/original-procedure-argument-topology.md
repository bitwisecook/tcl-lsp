## Problem statement

## Question

How do readonly procedure hints and formal-role colours share an authentic declaration, original formal topology and exact effective argv source anchors?

## Conclusion

Complete source/channel/configuration and retained Registry currency remain mandatory. Original formal topology supplies required/default/rest argument bindings independently of execution. Effective argv retains captured prefixes and genuine expansion-child ancestry; source anchors exist only for the corresponding written operand or exact original list child. Missing original correspondence on a present analysis projection is terminal. Inlay hints and formal-role colours consume this same carrier without reporting-map joins. Captured operands, default arguments and frozen list values without current written children cannot borrow another span. An authentic original procedure formal receipt exposes its already-decoded byte-name/default topology and retained parameter grammar through the same shared count owner as strict binding, before argc binding succeeds. The existing descriptor test distinguishes required-after-default C/Jim shape without inferring call or binding success.

## Scope

No formal installation, entered frame, runtime binding, value-read certainty, native admission, Normal, cross-document allocation or edit grant is supplied. A distinct authentic original procedure source descriptor retains current reference/declaration/formal grammar, full resolved input and complete effective argv before argc binding. Invalid argument count can retain descriptive formal syntax without gaining argument bindings, callee entry or Normal completion. The rich argument receipt continues to require successful shared native formal binding. The source formal-receipt count projection and its retained parameter grammar remain independently bounded metadata before argument binding. Native acceptance results still apply only to the exact Formal185 definition/call source and argc0..5 range.
