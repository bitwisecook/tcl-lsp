# naming.diagnostic.original-math-function-subject

Kind: `implementation-contract`

## Problem statement

A checked original expression function can emit W123 while the command-only diagnostic subject rejects is_mathfunc_call. Protocol consumers then lose the warning's genuine name even though the expression occurrence is retained. Manufacturing a script command-head word or parsing the warning message would replace expression syntax with another naming purpose.

## Question

Does W123 retain a separate genuine expression-function diagnostic subject and structured reporting payload while preserving original source/context correspondence and keeping workspace source candidates independent of dispatch?

## Conclusion

The issuer consumes an authentic OriginalMathFunctionOccurrence and checks the exact original function span, identifier, argument count, complete source image/channel, full lexer configuration, retained Registry and diagnostic-purpose Absent classification. It retains the original conditional expression frame/namespace/parser context, naming policy and selected fixed-table or command-table purpose. A distinct unresolvedMathFunction reporting kind preserves the original bytes/span/ordinal/arity/policy and classification without parsing presentation. Plain command/package getters stay separate, and workspace declaration labels cannot suppress this Native dispatch warning. Reporting decoding creates no original source, command head, function registration, lookup, execution, Normal or edit capability.

## Scope

Rust implementation contract for admitted ASCII identifiers in the checked original expression inventory and the Compiler-to-Core-to-Server reporting route. C8.4 and selected Jim0.84 fixed-table purposes remain distinct from C8.5-C9.1 command-table purposes. Missing occurrence ownership, foreign source/channel/full configuration/Registry, mismatched name/span/arity, command-word or existence-probe roles and unknown/present diagnostic classification cannot issue a subject. This record claims neither native guest execution nor successful execution of the linked Rust tests.
