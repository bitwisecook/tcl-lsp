# naming.consumer.typed-spec-pack-notice-actions

Kind: `implementation-contract`

## Problem statement

Extracting a DSL property or flag from diagnostic prose can choose a different word, reuse a stale notice or turn a forged message into an edit. Producer parsing configuration and current consumer configuration are independent owners.

## Question

Which retained loader subject and independently current source/configuration/Registry must agree before a SpecTcl property or flag notice supplies a source quick fix?

## Conclusion

The production loader retains the actual complete original source, selected parser configuration and complete CST row/word vector. Its actual unknown-property/flag detector privately selects the rejected original word, ordinal and braced-container path; line/name text is not used to recover that identity. The public Core subject carries source geometry and kind metadata only: it does not certify loader causality or grant an edit. The source span comes from the shared configured CST parser and original NativeWord geometry, without message parsing or a recursive all-braces search. Detached evaluated values, cooked bodies and ambiguous evaluated-row correspondences retain notice reporting without a source subject. Disk cache format/version remain unchanged; cached values receive new geometry only after whole current parsed-row/word correspondence, never from serialised offsets. An opaque bounded local handle transports that subject after retaining the actual consumer configuration and Registry semantic key. Core reborrows only the retained selected source path under its independently current full configuration and validates complete source/channel, both parsing configurations, current Registry, typed notice kind and exact line/word geometry before a property or flag action. Missing, forged, evicted, stale or ambiguous subjects decline. Diagnostic presentation can change without selecting another subject. These interfaces provide bounded DSL source advice; they supply no Native name, runtime lookup, evaluation, Normal, insertion or transformation-equivalence capability. Nested document vocabulary comes from the actual selected document grammar, an admitted member of the same family and its Registry-authored child grammar. This readonly projection does not require execution resolution and cannot substitute for command or handler authority.

## Scope

Current SpecTcl loader notices, Core diagnostic transport/source actions and Server publication/request lifting. Fixed controls use actual loader evaluation, typed property and flag subjects, changed or empty message text, absent/forged handles, ambiguous same-line words, stale complete source and changed full configuration. All seven native providers are not-tested for this Rust source-action contract; no executed Rust receipt is attached. Selected SpecTcl document-to-pack-to-command grammar controls separately reject wrong parents, ordinary command words, foreign document families and Native contexts lacking that document grammar.

### Evaluated parent continuity (V2)

An existing verbatim reader preference is not a source-parent receipt. Each evaluated header must match its actual complete captured argv against the retained literal original statement vector, and the actual captured body value must equal that original body word before only its geometry is retained.
