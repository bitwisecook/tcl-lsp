# naming.consumer.typed-spec-pack-notice-actions

Kind: `implementation-contract`

## Problem statement

Extracting a DSL property or flag from diagnostic prose can choose a different word, reuse a stale notice or turn a forged message into an edit. Producer parsing configuration and current consumer configuration are independent owners.

## Question

Which retained loader subject and independently current source/configuration/Registry must agree before a SpecTcl property or flag notice supplies a source quick fix?

## Conclusion

The loader retains the actual complete original source, its selected parser configuration, the typed Property or Flag subject, and one uniquely identified literal word at the notice line. The source span comes from shared original word geometry, without message parsing or text search. An opaque bounded local handle transports that subject after retaining the actual consumer configuration and Registry semantic key. Core reselects the existing subject and validates complete source/channel, both parsing configurations, current Registry, typed notice kind and exact line/word geometry before a property or flag action. Missing, forged, evicted, stale or ambiguous subjects decline. Diagnostic presentation can change without selecting another subject. These interfaces provide bounded DSL source advice; they supply no Native name, runtime lookup, evaluation, Normal, insertion or transformation-equivalence capability. Nested document vocabulary comes from the actual selected document grammar, an admitted member of the same family and its Registry-authored child grammar. This readonly projection does not require execution resolution and cannot substitute for command or handler authority.

## Scope

Current SpecTcl loader notices, Core diagnostic transport/source actions and Server publication/request lifting. Fixed controls use actual loader evaluation, typed property and flag subjects, changed or empty message text, absent/forged handles, ambiguous same-line words, stale complete source and changed full configuration. All seven native providers are not-tested for this Rust source-action contract; no executed Rust receipt is attached. Selected SpecTcl document-to-pack-to-command grammar controls separately reject wrong parents, ordinary command words, foreign document families and Native contexts lacking that document grammar.
