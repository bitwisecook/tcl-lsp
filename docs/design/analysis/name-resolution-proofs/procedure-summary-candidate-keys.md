# naming.analysis.procedure-summary-candidate-keys

Kind: `implementation-contract`

## Problem statement

Procedure summary maps can overwrite a same-named namespace candidate or select an arbitrary first parameter summary. This can lose possible caller reads and report one conflicting caller alias/default/signature as definite. Trimming constructed leading colon segments also changes metadata identity.

## Question

How do constructed procedure summary keys share one pure geometry owner, retain all original same-source candidates, refuse conflicting complete signatures/frame aliases, and union protective by-name reads without turning a label or missing candidate into Native lookup or effect-absence authority?

## Conclusion

key_suffixes delegates the existing constructed key_segments split and retains complete keys, lone-colon segments and nonempty unique suffix labels. CFG frame and parameter indexes preserve all members under the original retained Module/header/body owner; one unavailable, changed or redefined member leaves the shared key unavailable. Parameter publication requires equal ordered names and raw declarations, preserving defaults and variadic position. Frame composition/publication also requires unanimous own or composed frame summaries; conflicts and unknown callees widen to opaque caller reads/writes without definite alias maps. ProcIndex retains every parameter-summary candidate and unions possible literal by-name arguments/defaults. A missing/dynamic key protects literal passed names; it grants no effect-free callee. The sole production elimination consumer uses this as extra MAY protection and independently retains binding/opaque CFG, positioned source-read and RHS/raise/store proof owners. Six genuine fixed source-defined controls cover constructed colon/Unicode/NUL geometry, conflicting caller aliases, default/order/variadic disagreement, changed member/foreign source refusal, every colliding read/default and missing-key literal protection. All255 previous true test bodies remain exact. No assertion/provider execution is attached.

## Scope

Finite Syntax constructed-key query and Compiler frame/parameter/protective-index consumers. The global-write and deferred-write index adapters share the same query through qualified_lookup_keys without changing their existing independent effect/source guards. Possible keys and ProcIndex candidates are MAY metadata, never selected Native command, namespace incarnation, frame, alias/cell contents, observer history, successful completion or store-removal authority. Empty neutral indexes preserve their compatibility short circuit; unknown hidden frame effects remain the existing binding/CFG owner. This is not a claim of all Compiler naming, whole optimisation soundness or external Tcl/Jim/BIG-IP behavior.
