# naming.source.original-declaration-layout-visits

Kind: `implementation-contract`

## Problem statement

Repeated nested declaration layout inquiries can revisit the same lexical body under identical immutable parent lookup worlds. Reuse needs the complete original source and owner/context, while genuine child operands must replace parent command words before semantic selection.

## Question

When can an original nested declaration layout inquiry share a completed visit while preserving complete source/lookup/issuer/entry/realm/namespace/configuration correspondence and all retained semantic observations?

## Conclusion

The per-collector worklist uses structural equality of NestedDeclarationLayoutKey: complete original source bytes/channel/origin/mapping and immutable parent observations, including issuer/entry/snapshot state, realm, namespace and lexer configuration. The Registry is fixed for that collector. Parent command words are excluded only because genuine child words replace them before every body semantic query. Identical complete keys share one visit; any changed retained source or owner/context facet is a separate inquiry. The fixed nested fixture compares seven shared-worklist lexical body visits with twenty-eight unshared visits and requires equal complete retained bindings. No wall-clock improvement, global allocation law, runtime body entry, Native frame, Normal result, new Registry selection or depth-budget grant follows. OriginalDeclarationLayout::select retains one exact original layout advice and DeclarationInvocationFlow for each parent observation; parent_declaration_layouts shares that guarded result between child source projection and the successor-retention decision. The complete original source/frame/dialect/Registry guards and whole visit key remain authoritative. This local derivation reuse issues no cross-world cache, elapsed-time, installed implementation, entered body or Native frame grant.

## Scope

Two deterministic marked source/API controls check exact visit counts, complete semantic equality and changed source/lookup/owner facets. They do not execute native providers or establish elapsed-time results. Existing source lexical declaration and native execution/admission questions remain independent; every provider is not tested for this implementation contract. Two marked fixed source/API controls compare shared exact-parent child/successor projections with independently rederived original worlds and explicitly remove source origin, selected frame or invocation dialect. Refusal remains visible in both child collection and successor selection; no runtime or timing outcome is asserted.
