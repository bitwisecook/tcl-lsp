# naming.source.original-procedure-publications

Kind: `implementation-contract`

## Problem statement

Canonical procedure metadata can survive after its conditional source slot moves, is deleted or is replaced. Reusing the declaration name can resurrect a withdrawn suggestion; treating deferred declaration cards as final publications can invent source effects.

## Question

Which genuine original procedure declarations survive as conditional source publication candidates, and how do current slots, known terminals and unrepresented declaration cards remain distinct?

## Conclusion

OriginalSourceProcedurePublications retains authentic root source graph headers and surviving direct SourceProcedure cells. Each publication keeps canonical whole declaration/body and original naming operand separately from conditional current slot, selected policy and move lineage. Exact original operations with unknown mutation effects remain attached with explicit obligations. Represented known deletion, alias/nonprocedure replacement and superseded procedure headers withdraw old candidates rather than falling back to canonical names. Genuine namespace or deferred declaration cards outside the represented graph remain separate candidates with publication=None. The source_structure facade checks actual input, complete image, configuration, Registry context and retained realm; candidates additionally check original declaration correspondence. Core local completion, workspace indexing/completion and Server package inventories share these candidates. Independently supplied completed-world publication remains a separate owner. No source receipt supplies installed absence/presence, completed runtime world, reached dispatch, frame, successful effects, navigation identity or edit authority.

## Scope

Current conditional source inventory and readonly consumer projection. Fixed controls cover moves/deletes/replacements, canonical headers after report clearing, unknown-operation vectors, full input/image/configuration refusal, deferred cards, workspace reindex/slot reuse and package suggestions. All seven providers are not tested for this source API contract; native holder observations and Rust validation receipts retain their independent scope.
