# naming.source.original-registry-header-advice

Kind: `implementation-contract`

## Problem statement

An uncalled original procedure body can retain an exact declaration layout while its runtime handler and value-read completion remain unknown. Execution-only metadata queries would lose readonly signatures, but using reporting command text would invent lookup ownership.

## Question

Which genuine source owner may supply conditional Registry command words for readonly header advice?

## Conclusion

The complete original word vector authenticates the query. A unanimous retained execution envelope is preferred; otherwise the existing closed original declaration-layout issuer supplies only conditional metadata. Execution, Normal, stores and compiler admission are unchanged. Three additional marked signature-scanner definitions retain actual clause availability and keyword values, direct moved/replaced installer horizons and written-operand geometry. Captured or expanded operands do not supply a written body token. Explicit header-only metadata describes source shape without issuing current installer ownership.

## Scope

Readonly Registry metadata under a matching complete original word vector/configuration and an independently closed declaration point. Changed original syntax, missing ownership and source-defined handler shadowing cannot inherit the stock Registry shape. These are readonly source-definition bindings without an attached assertion result. They supply no executed declaration, Native handler/body/frame, current table or Normal/compiler admission. A supplied inventory refusal remains terminal, independently of catalogue compatibility and presentation labels.
