# naming.source.ordered-compiler-local-inventory

Kind: `implementation-contract`

## Problem statement

An embedded-zero C compiler-local name can select an earlier same-length counted primary. A lexical variable-write list omits formal, anonymous, recursive and rejected-hook allocations and cannot identify the winning source primary.

## Question

When can the existing authentic source compiler traversal retain a complete ordered local inventory for the independently selected compiler-name purpose?

## Conclusion

The original formal prefix and complete represented compiler preparation events retain counted primaries and anonymous slot positions in order. Complete ownership is rechecked before selecting the first matching small-index primary; any unsupported or missing attempted event withdraws the whole inventory.

## Scope

Conditional source procedure topology under the independently selected compiler-local protocol, exact original source/configuration/frame and bounded complete traversal. Unrepresented expression-variable compilation, generic worker attempts without a preparation receipt, failed compilation, oversized inventories and unselected large-index fallbacks remain unavailable. No physical native table, activation, object header, cache or Normal grant.
