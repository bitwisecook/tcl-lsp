# naming.diagnostic.original-materialized-write-footprint

Kind: `implementation-contract`

## Problem statement

Possible-output advice can scan concatenated script values or detached expressions under a stock profile and lose authentic alias targets, replacements, availability and source lookup horizons. W210 suppression and CFG possible writes need one original installer-bound source footprint.

## Question

How can diagnostic suppression and CFG possible output names retain the original installer lookup and complete actual metadata while treating materialized script text and expression branches as possible source writes only?

## Conclusion

SourceInvocationBinding::original_materialized_footprint seals the genuine original installer words, complete source image/input/config/store and closed original lookup/namespace. Script values are scanned as possible text under that retained world, preserving literal resolved roots, authentic aliases and known replacements without acquiring an original child word/span. Original expression suppression selects a unique original Expr operand base and uses each genuine child lookup horizon. Actual Registry argument roles and same-frame script purposes govern possible output names; missing/foreign/stale ownership withdraws suppression or keeps effects opaque. These API definitions supply neither a completed write nor a Native invocation.

## Scope

Seven marked source/API controls cover literal dollars, unmatched scalar parentheses and Unicode names; moved/captured alias targets and known replacement; same command store with independently older availability; missing/foreign input and stale source/config; original child ordering and multiple expression-role refusal; and prepared CFG Module-profile/body-configuration checks. Materialized child text remains May advice without an authored NativeWord, original child span, entered frame, current cell/store, normal handler result or execution grant. Expression branches contribute possible names only. All seven external providers are not tested for this implementation contract. Immediate materialized bodies retain the original source-entry InvocationRealm from the sealed command world. The actual f5-irules context independently withholds a loader-only unavailable descriptor and permits its runtime-source metadata under an explicit source realm. The control retains native_entry: None and tests conditional possible names plus an opaque refusal only; it establishes neither an appliance process nor an entered runtime frame or successful store. The separate with_source_schema ingress retains its RuleLoader purpose.
