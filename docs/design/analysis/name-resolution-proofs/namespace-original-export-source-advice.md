# naming.namespace.original-export-source-advice

Kind: `implementation-contract`

## Problem statement

Reporting namespace export and import strings lose counted opaque names and can misclassify a leading control word. A later clear must be ordered against each import, and an intermediate imported command need not have a local source declaration.

## Question

Do source export/import consumers retain the genuine operand, caller geometry, selected byte purpose and ordered clear events without rebuilding native names from reporting labels?

## Conclusion

The source inventory retains genuine whole operand Inputs, invocation sites and caller scopes. The selected C namespace pattern purpose records only the first leading clear and commits patterns only before the first qualified-pattern refusal. Core document and workspace queries share the same ordered event fold and canonical native glob purposes over exact counted command slots. Unknown operands remain explicit May barriers; policy and namespace disagreement refuse advice. Intermediate import query geometry uses independently retained command tails and never manufactures a declaration or imported token. A static source declaration can separately retain conditional namespace geometry after current invocation scope becomes unavailable; its distinct lineage supplies neither actual handler completion nor runtime lookup.

## Scope

Readonly source naming advice under selected C Tcl 8.4, 8.5, 8.6, 9.0 and 9.1 policies. Whole authentic static words and independently retained readonly values remain separate Inputs; grouped words retain their original complete vector and configuration. Export and import geometry, original declaration-body source ordering and UI association supply neither current command existence, import authority, native namespace or command tokens, entered bodies, compiler preparation, Normal completion nor edit grants. Jim export inventory and unsupported or conflicting operand producers remain unavailable. Native provider measurements are independent from this Rust implementation contract. Conditional declaration fallback is bounded to authentic static original operands and a chain of explicit static namespace-eval source scopes under the same source image, complete configuration and name policy. Computed namespace scopes, unknown scopes and unentered callable scopes cannot borrow an enclosing namespace through this fallback.
