# naming.tcloo.original-named-manufacture-cell-transfer

Kind: `implementation-contract`

## Problem statement

A named source constructor can install a reporting String cell while subsequent original command lookup selects a byte slot. The mismatch loses the genuine receiver and complete source-world continuation; opaque full-name results also cannot survive through a Unicode result projection.

## Question

Does named source manufacture retain the actual installed byte cell and allocation, and issue held full-name data only after independently complete constructor outcomes?

## Conclusion

The constructor consumes the canonical original effective argument inputs, selects the Registry manufacturer and a fresh current byte cell, installs that cell through the existing command allocator, and joins the actual command token allocation to the source receiver allocation. Current presence and deletion use the surviving exact cell rather than reporting text. A separate retained full-name value retains the requested producer, actual allocation, selected policy and exact surviving slot only after complete constructor outcomes; it supplies no written word or current receiver authority.

## Scope

Rust source-only named TclOO instance construction under C8.6, C9.0 and C9.1 with independently selected original factory, lifecycle, arguments, namespace and callback premises. Controls include direct ordinary and opaque command/member names, a held opaque command-name result, occupied or unknown destinations, constructor errors and unresolved filters. This contract does not establish physical native allocation, native factory completion, generated private namespace spelling, destructor callback closure, editable value geometry or successful dynamic-name construction without its own producer. Positive source-mode coverage independently selects Direct or ScriptCode; Unknown setter mode cannot close held input, receiver or completed-world premises.
