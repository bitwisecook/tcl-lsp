## Problem statement

Public regexp/scan output retention must distinguish no-match, successful match, incoming absent/OLD values, authentic captured/moved builtin calls and replaced/custom providers. A source-selected output descriptor alone cannot establish current public values.

## Question

What exact caught completion/result, info-exists and stored output values do the original matcher and capability-selected alias/move/replacement controls report, including the limited Jim alias setup?

## Conclusion

The independent originals agree on the first sixteen public rows for all six providers: literal regexp and scan no-match keep absent outputs absent or retain OLD; expanded regexp space and scan match controls report ab and42. The capability-selected alias original reports alias_capability0 on C and1 on Jim, then captured_alias, moved_alias and moved_builtin no-match retain ABSENT or OLD; replaced_stock and custom_same_tail report CUSTOM and TAIL. All six capability-selected processes exit0 with empty stderr and27 rows. The other original completes26 rows on all five C providers; Jim emits the same first16 rows then host exit1 with its whole line20 interp alias wrong-arity stderr, so it gives no subsequent captured/moved/replaced alias answer. Both whole sources and all outputs remain independent exact evidence. The raw requests identify the related source diagnostics question; this record measures public values only. No current physical output cell, native argv/header/frame, generic provider completion or diagnostic admission is inferred.
