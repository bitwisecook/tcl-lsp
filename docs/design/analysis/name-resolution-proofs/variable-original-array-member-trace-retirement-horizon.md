# naming.variable.original-array-member-trace-retirement-horizon

Kind: `native-observation`

## Problem statement

Array teardown callbacks can change member trace registrations through retained aliases or a same-spelled root. Public callback logs are needed to distinguish those original programs without assuming a universal snapshot rule or private member identity.

## Question

What whole public callback logs do the three original array teardown programs return when a root or member callback changes registrations through retained aliases or the original root spelling?

## Conclusion

Each pinned C8.4–C9.1 provider completes the three exact originals with code0 and public results NEW, OLD NEW OLD and oldx oldy root respectively. The first original removes the old member unset trace and adds fresh through a retained element alias during the root callback; the second adds fresh registrations through retained aliases during a member callback; the third removes and adds a same-spelled member registration from the root callback and sorts its public log. These are observations of those complete programs and their original registration operations, not a general trace snapshot or callback-list algorithm. Jim completes the same driver processes with guest code1 and invalid command name "trace" for all three originals; no Jim member teardown answer is supplied. All eighteen original processes have host exit0 and empty stderr, with independent VERSION and ORIGINAL counted-hex channels. The public logs establish no private member/cell/header identity, registration generation, entered frame, Native argv or corresponding software assertion pass.

## Scope

Three original ASCII LF programs, each in a fresh fully initialised provider interpreter, use the unchanged counted-source CAPI driver without a source catch/eval/puts envelope. Six compile receipts and eighteen whole process receipts/streams preserve exact source, executable, archive, header, build and required-source pins. Original source names and request statements are retained, including anticipated outcomes separately from measured answers. No opaque/Unicode/NUL trace-name input, private member identity, BIG-IP or executed Rust comparison is measured. The linked Runtime comparison consumes all eighteen whole untouched original public completions/results, including Jim unsupported trace. Separate software VarTraceScope ownership uses the selected root and original element binding identity; retained aliases use that selected generation, the original member stays live during root and earlier-member callbacks; at its own retirement horizon the then-current registration group is captured and detached by immutable registration IDs before its unset callbacks. Changes before that horizon can affect the group, while same-spelled replacement-member registrations cannot. Cleanup removes only the captured original IDs. The Rust member-correspondence control does not turn public logs into provider member/cell/header identities, and linked status claims no executed software pass. NativeElementAliasEntry::permits_trace_registration admits only the exact actively retiring original entry for trace-list registration. Ordinary is_live value access remains refused at that point, and registration permission ends with the active retirement receipt. Trace resolver/ensure consumers retain this purpose-specific entry rather than revive retired alias reads or writes. The linked software allocation control proves only this implementation capability boundary; public original343 callback logs do not identify private entries or registration IDs.
