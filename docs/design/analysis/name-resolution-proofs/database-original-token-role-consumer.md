# naming.database.original-token-role-consumer

Kind: `implementation-contract`

## Problem statement

A light database token-fact tier must retain distinct original byte declarations and their inferred argument roles. Clearing reporting names or passing a stale caller analysis must not merge declarations or donate a role to another procedure.

## Question

Does the database token-fact and project role projection preserve original opaque declarations while the semantic-token consumer requires the complete current caller source, full configuration and genuine original head input?

## Conclusion

FileTokenFacts derives procedure roles from the original declaration inventory. Project role projection preserves independently retained original declarations. Semantic-token role application selects the caller original input and positioned lookup under the complete current image and full configuration; cleared reporting maps cannot erase the original writer, and an unrelated opaque procedure cannot borrow its role. Stale source, changed full configuration and missing original caller input refuse the projection.

## Scope

Rust database and readonly semantic-token integration for a Tcl8.6 authored document. The positive writer and ordinary procedure have distinct surrogate-unit byte names. Inferred argument role metadata supplies no runtime variable cell, successful upvar effect, native object header, compiler admission, Normal completion or edit permission. Other provider behavior is not measured by this question.
