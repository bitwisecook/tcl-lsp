# naming.jim.original-command-table-key-publication

Kind: `native-observation`

## Problem statement

A publicly reported Jim command key can preserve a particular spelling through same-slot replacement while deletion/fresh publication reports another spelling. Namespace forwarding can also prevent the original inventory query from reaching a key observation.

## Question

Which exact public Jim command-name/value reports follow original root procedure/alias replacement, rename/delete/fresh publication and namespace-relative replacement, and which namespace query remains limited by its caught arity failure?

## Conclusion

Jim root-replacement reports ::r2286_key with FIRST, SECOND, ALIAS and LAST. The rename original reports :::r2286_key_moved with FIRST and SECOND, then r2286_key_moved with FRESH after delete and fresh publication. The independent namespace original whose inventory query runs at actual root reports r2286_key_holder::local with FIRST and SECOND. The other namespace original returns ORIGINAL1 wrong # args: should be "namespace info cmd ?pattern?" and supplies no key report. All five C releases return original NOT_APPLICABLE for all four source controls. All24 fresh source processes and twelve compiler commands exit0 with empty stderr, preserving counted VERSION and ORIGINAL completions as separate channels. Public report/comparison bytes do not prove key header/pointer identity, hash-table slot identity, object lifetime, private replacement mechanism, Native frame or generic namespace inventory law.
