Per-object definition-abort candidates retain reporting receiver/member names. Those String tables do not establish a selected Native operation or closed current own-method table; donating candidates, construction reports or a Native-looking label cannot justify guaranteed-abort advice.

## Question

When may per-object reporting candidates produce W315 source compatibility advice, and how do actual Native/hosted or missing input remain outside that admission even when report labels, construction maps and member tables are donated?

## Conclusion

AnalysisResult::allows_retained_logical_declaration_advice positively requires actual retained Logical input together with the existing lexical advice mode and source/vendor exclusions. flush_objdefine_abort_diagnostics drains per-object candidates and uses this shared class/object admission before consulting bounded Logical construction/member reports. Native, hosted and absent-input source profiles decline even when reporting class/instance/method rows, dialect labels or advice flags are copied. Existing per-object receiver, conditional-state and same-name source-model premises remain mandatory within genuine Logical compatibility. These String reports establish no actual object, current own-method absence, table completeness, selected definition worker, guaranteed Native abort, frame or edit authority.

## Scope

Existing Logical object-table source controls retain their independent model. All seven providers are not tested; no runtime worker, object or physical method table is observed. A Server integration control withholds Native per-object W315 while retaining its authored source retraction. The separate class declaration-abort contract binds the companion emitter; sharing the admission owner does not collapse class and per-object reporting premises.
