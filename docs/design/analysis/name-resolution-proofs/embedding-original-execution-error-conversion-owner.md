# naming.embedding.original-execution-error-conversion-owner

Kind: `implementation-contract`

## Problem statement

Implicit question-mark or Into conversion can project a complete operational refusal down to message bytes and lose its original typed first cause. Matching diagnostic fields alone cannot restore the stopped owner or manufacture a Guest completion.

## Question

Do the shared NativeExecutionError-to-CmdError conversion routes preserve the complete original first-cause record through question-mark and Into, keep Host metadata separate from Guest fields, and refuse text/detail projection without treating authored diagnostic profiles, interpreter, frame or namespace tokens as execution authority?

## Conclusion

The current conversion delegates to CmdError::from_execution_refusal and retains the complete typed NativeExecutionError metadata with empty message bytes. One finite linked source control covers authored HostCommandRefusal and ValueAccessRefusal records through question-mark, Into and fallible message/error-code/detail access. It has no attached matching owned assertion outcome. All seven external execution statuses are not tested. Preserved fields grant no real interpreter/context identity, live frame, Guest completion, replay, Native entry or all-variant runtime outcome.

## Scope

Pure shared Rust typed-error conversion and readonly diagnostic projections. The finite control uses authored records with independent source/native profile keys and explicit interpreter/frame/namespace fields; these are model data rather than captured provider state. Other NativeExecutionError variants remain declarations only for this control. Actual first-cause issuance, entered operation currency, owning Guest completion and physical runtime transport retain independent requirements.
