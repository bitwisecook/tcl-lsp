## Problem statement

Inlining through a QName or display formal can select another opaque declaration, erase an observable argument read, or substitute into braced literal data. Correct applicability depends on the actual implementation allocation, exact original ParamList, complete effective arguments and source body geometry, separately from a displayed signature.

## Question

Does Native procedure inlining use the exact original allocation, byte formal binding and genuine body operands?

## Conclusion

Inlining selects canonical original declaration metadata and authentic body words, uses the retained byte formal binder with exact effective prefix/expansion origins, and rewrites only original executable variable parts. Erased variable reads, free cells, arrays, rest-list reads, caller links, unknown or multiple body owners and unavailable arguments decline. Literal braced data is retained. Conditional structure and declaration metadata do not supply new Native execution or Normal grants.

## Scope
