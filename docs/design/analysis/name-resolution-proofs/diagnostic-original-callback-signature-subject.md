# naming.diagnostic.original-callback-signature-subject

Kind: `implementation-contract`

## Problem statement

A callback report can expose mutable display names, scalar counts, spans and future lookup guesses. Reinterpreting those fields or message text can join a different source declaration or imply an unproved callback frame.

## Question

Can callback diagnostics retain the genuine original prefix name, count and lookup scope with exact current source-header advice without report-field reparsing or future dispatch promotion?

## Conclusion

OriginalCallbackPrefix retains its genuine readonly name child, baked count, selected appended-arity descriptor and independently available lookup scope. SourceCallbackAritySubject selects only matching original procedure headers with original formal-count provenance and known parameter grammar. Finite suffix alternatives and lower-bound counts include baked words with checked arithmetic. Only a proved incompatibility supplies a typed TooFew, TooMany or NoCompatibleSignature issue. Missing lookup, uncheckable counts, unknown formals, non-procedure candidates and unowned geometry decline. The diagnostic span is the exact decoded head extent or the complete genuine parent operand when no child substring exists; it is readonly. The database body-free query keeps original ordered slot/policy alternatives and current headers, with namespace tails separate. Core serializes the retained purpose, counts, issue, scope and declarations independently of presentation. No registration, future command occupancy, actual callback argv, activation, frame, completion or edit authority is supplied. A selected C absolute TriggerFrame name retains its source target slot without a caller naming scope; relative future frame coordinates remain unavailable. Qualified source geometry supplies no actual future callable or entered trigger frame. CallbackSourceArity is a separate diagnostic subject: required-package, unresolved-command, unresolved-math-function and conditional-interpreter accessors return None for it. Core requires the diagnostic code to agree with the typed callback issue before transport; changing report text cannot select another issue. Retained SourceCallbackSignatureLookup additionally selects genuine local canonical procedure headers or held external alias target slots under explicit source horizon/refusal. Alias-captured counts remain separate from baked prefix and appended suffix counts; mutable report counts do not substitute. Known source barriers cannot be reopened by project headers. Exact disjoint retained source headers preserve the typed NoCompatibleSignature issue, independently of a reporting tail.

## Scope

Rust Compiler/database/Core source-signature contract. Original prefix and declaration headers retain their own source/context/policy and parameter grammar. Linked tests inspect source metadata and mutable presentation independence; native callback processes were not invoked.
