# naming.tcloo.original-member-body-source-roles

Kind: `implementation-contract`

## Problem statement

Reporting parameter/body spans do not establish authentic whole ParamList or Body operands. Readonly generated names and moved source routes require independent retained worker words and a matching source grammar before syntax roles can be offered.

## Question

Does the selected declaration grammar retain the genuine whole formal-list and body words independently of the method name, current route and execution entry?

## Conclusion

The genuine source member producer selects ParamList and Body ordinals from the Registry MemberSpec and retains their complete NativeWords in canonical method metadata. The words keep their original image and lexer configuration through readonly generated names and source route moves. A forward retains no body role, and a foreign image, configuration or expanded whole operand cannot supply those fields. The source driver retains its independently selected InvocationDialect alongside these roles; an explicit unknown entry or incompatible lexical grammar supplies no dialect. Literal generated names use the existing authenticated conditional Registry source-candidate owner, retaining its unknown applicability separately from the complete formal/body syntax words. A selected optional flag uses its Registry-declared ordinal and authentic input; the readonly method name supplies no option word.

## Scope

Readonly source declaration roles for Registry-selected definition-body member grammars, with TclOO fixtures under the Tcl 8.6, 9.0 and 9.1 naming policies. Existing independently selected constructor/destructor words retain their separate nameless lifecycle owner. These whole ParamList/Body words supply syntax roles only: no evaluated parameter value, formal binding, activation, body script projection, entered execution, selected method implementation, native compiler/header, installation, Normal completion or edit grant follows from retention. Names remain distinct static or readonly producers, and reporting spans do not recover source words. The retained source dialect comes from the actual SourceAnalysisEntry, or the documented authoring driver when no entry was supplied; name bytes and name policy do not select a parameter grammar. Missing dialect retains syntax words without formal-field grammar. A literal single-var/list installer retains the shared conditional Registry source schema and its explicit lookup/applicability obligations. Original words and native list-child lineage supply readonly declaration candidates only; known shadow/tombstone barriers, computed lists and multi-variable shapes refuse the fold. Conditional source schemas grant no loop execution or method installation.
