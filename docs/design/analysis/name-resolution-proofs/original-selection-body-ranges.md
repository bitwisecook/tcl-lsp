# naming.editor.original-selection-body-ranges

Kind: `implementation-contract`

## Problem statement

Selection ranges can lose an earlier procedure declaration or byte-distinct class/member body when enclosing spans come from display-name maps. Stale analysis can also attach body geometry from a different source or configuration.

## Question

Do enclosing selection-body links retain each genuine original declaration site and reject missing, stale or conflicting source ownership?

## Conclusion

The consumer validates the complete current document image and retained scanner configuration before reading original procedure, class, named member and nameless lifecycle inventories. It retains independent declaration sites regardless of display names or redefinitions. Independently selected configuration-worker rows supply their own body geometry without selecting a class, object allocation or native entry. Equal extents collapse only as selection links; non-nested containing spans and foreign or stale records decline semantic body links. Command segmentation uses the current retained profile and full configuration. Explicitly selected logical declaration advice remains a separate compatibility branch; unavailable Native records cannot enable it.

## Scope

Readonly Rust selection geometry for current document source. Fixed coverage includes all-six opaque/repeated procedure declarations after report maps are cleared; C86/C90/C91 named method, constructor and destructor bodies inside an opaque class; stale source/full configuration, foreign header and default-assistance refusal. Syntax-only word, command, line and document ranges remain independent. No runtime dispatch, installed member table, body execution, editable name, namespace existence or native interpreter result is granted.
