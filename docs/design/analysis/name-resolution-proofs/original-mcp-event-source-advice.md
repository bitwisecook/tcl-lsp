# naming.consumer.original-mcp-event-source-advice

Kind: `implementation-contract`

## Problem statement

MCP event reporting can ignore the requested dialect when it reparses text under a fixed iRules profile. Reporting text may then manufacture event advice for Native Tcl, iApps or a shadowed declaration.

## Question

Do MCP event reports and ordering consume the actual requested Analysis and current hosted source declarations rather than a fixed profile or reporting map?

## Conclusion

MCP event detection consumes shared current Event source cards from the requested analysis. Catalogue ordering additionally requires supported ASCII Event-role units from the actual hosted declaration at the same authentic extent. Unknown units remain readable source cards without catalogue identity. Native Tcl, iApps and shadowed source heads do not acquire iRules events by text spelling. Whole-source currency and independent source policy remain mandatory. This is readonly source advice, with no reached event, runtime normalization, worker frame or handler capability.

## Scope

Current MCP analyze/event_order source reports. Fixed controls use real hosted analysis, erased reporting maps, stale source, independently selected Native Tcl/iApps and a procedure named when. No native or Rust execution receipt is attached.
