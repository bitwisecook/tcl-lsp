# naming.compiler.original-named-operand-projection

Kind: `implementation-contract`

## Problem statement

A private handler consumes ensemble selector operands before ordinary operand consumers run; rebuilding an original word at the shortened vector can lose its genuine full-source owner or select the wrong ordinal.

## Question

Does a selected private handler retain one exact original-word projection before consuming its selectors, and can later operand consumers use only that authenticated correspondence?

## Conclusion

ProjectedNamedArguments captures the complete genuine NativeWord vector before the compiler-selected private handler consumes ensemble selectors. OriginalNamedWords retains the same ordinal projection with the exact corresponding IR words and full original image/channel/configuration. Later consumers request words_for with the actual projected IR vector and current full source/configuration; mismatch refuses. The original_variable_invocation consumer receives the authentic original operand Input instead of attempting to capture a shortened script as a complete command.

## Scope

Private original-source correspondence only. Opaque namespace export operands, exact consumed ordinals, foreign image/channel/configuration and mismatched projected IR vectors are linked Rust coverage. No handler selection, NamePolicy, physical table, variable cell, native execution, compiler admission or Normal grant follows from this geometry. Native observations and immutable direct source controls remain independent.
