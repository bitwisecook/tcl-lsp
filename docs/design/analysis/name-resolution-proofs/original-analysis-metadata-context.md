Kind: `implementation-contract`

## Problem statement

An analysis can retain keyed versions, package availability, authoring scope and a command overlay that differ from its display profile. Reconstructing default metadata context can select different argument roles, bodies, symbols or variable-name descriptors.

## Question

How do analyser metadata queries retain the exact original availability context and command generation without turning source advice into execution authority?

## Scope

Controls compare authentic source tokens under selected C8.6 and C8.4 availability and refuse a foreign store; they are not runtime executions. A fixed retained-invocation control additionally compares authentic dict create under C8.6/C8.4 availability on the same Registry store, known source replacement and removed binding. It checks source metadata/representation admission only, not native handler entry or runtime completion. The retained invocation control also checks actual-context candidate/residual assistance. Genuine original Statement and diagnostic constant-harvest ingress retain the same availability and operand grammar; these are source metadata projections without runtime store contents or argv materialisation. A retained-array constant control independently selects C8.4 versus C9 original operand grammar on a shared C9 Registry store; its U-escape syntax results are source literal advice, not runtime Unicode storage. A fixed qualified/unqualified original alias-tail control shares one C8.6 command store while comparing actual C8.6 availability against an identity-only f5-bigip no-Tcl context, and refuses genuine source replacement. No native process or variable alias creation is measured. Eight fixed Unit/factory source controls link actual supplied availability, same-store older availability, missing/foreign owners, complete effective alias words, operand offsets and caller uncertainty. They describe conditional metadata, trait inventory, symbolic variable facts and May candidates; source loader/entry, formal binding, SSA construction-result and physical Native purposes remain independent. No source/API test result or native-provider execution is inferred. Marked FunctionUnit generation/config, method-dispatch, recursive-folding, whole-child token-purity and variable-footprint controls distinguish the same catalogue under different actual availability and terminal missing/foreign owners. Their assertion definitions are source/API contracts; no executed Rust result or new provider process is supplied. Explicit standalone metadata ingress remains independent from a FunctionUnit or Module that lacks an actual supplied owner.
