# naming.consumer.original-profile-source-advice

Kind: `implementation-contract`

## Problem statement

Recommendations for profile headers can change when a reporting command label is modified or when a static iRules profile is substituted for the current source owner. Such labels and reconstructed profiles do not identify a selected command or event.

## Question

Does the profile source action use the current source/configuration/Registry and retained selected command/event metadata independently of reporting names?

## Conclusion

The profile source action validates the current whole image and full configuration against Analysis and requires the supplied Registry to equal its retained command store. It obtains possible command profile requirements through shared SourceStructure and the Compiler source-schema owner with exact whole written origins, actual ContextRegistry and selected/guarded conditional metadata. Known custom handlers and tombstones block nominal catalogue advice. Event implications come from actual selected top-level handler metadata. Reporting invocation names and procedure maps are not used to choose requirements. The profile catalogue supplies ordering and infrastructure filtering only after current source metadata selection. This is an authored profile-header recommendation; it supplies no appliance availability, runtime command binding, execution or edit-equivalence grant.

## Scope

Current Core profile-header source advice for independently selected authored iRules context. The fixed control preserves its HTTP recommendation after all invocation display names change and refuses stale source or a different Registry. Native C/Jim and BIG-IP execution are not tested by this Rust contract. Complete unexpanded Written origins are required; unsupported expansion or foreign source/configuration cannot supply a diagnostic source vector.
