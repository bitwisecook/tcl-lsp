# naming.core.original-scoped-body-completion

Kind: `implementation-contract`

## Problem statement

Reparsing a reporting region or nominal command can offer a scoped vocabulary inside a different body, after shadowing/deletion, or under stale source and availability context.

## Question

Which genuine original body word, current context and independent conditional schema select scoped body completion?

## Conclusion

The Compiler retains OriginalSourceScopedBody from the actual original command vector and selected script/body roles. It keeps the whole NativeWord, exact content span, complete source/channel/configuration, actual ResolvedContext and Registry key, together with selected or conditional applicability metadata. Native source candidates reuse shared conditional Registry metadata and their original namespace; hosted candidates retain the separate guarded vendor vector/context without C/Jim conversion. Core scoped_env_at consumes the retained current descriptor, rather than reporting regions, while the analyser and per-item paths preserve its exact owning image. Known shadowing/deletion, missing original roles, stale complete source/context and unavailable body geometry withdraw the schema. The vocabulary is source-only candidate advice, without an entered frame, live command table, body execution, Normal or edit grant.

## Scope

Current Compiler body-schema retention and Core scoped completion. Fixed assertions use genuine source body descriptors, cleared reporting regions, known shadow/deletion and stale whole-source/context negatives. Seven native providers are not tested by this Rust carrier contract; no passing Rust receipt is attached.
