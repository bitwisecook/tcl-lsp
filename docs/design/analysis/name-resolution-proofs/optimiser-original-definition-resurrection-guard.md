# naming.optimiser.original-definition-resurrection-guard

Kind: `implementation-contract`

## Problem statement

A final rewrite can expose a variable reference after a proposed defining statement removal. The removal guard needs selected genuine source operands and canonical place owners; whitespace-split reporting text loses quoted/qualified/captured names or invents absence when original ownership is missing.

## Question

How does optimiser finalisation retain authentic original definition operands and cell projections when checking whether another surviving replacement resurrects a reference?

## Conclusion

elim_target_vars selects an actual original CFG statement and retained source binding under matching module source, lexer configuration and command store. normal_definition_reference_names consumes the selected normal definition/output arguments and canonical variable place owners, keeping quoted names, qualified heads, captured alias operands, literal dollar bytes and scalar-parenthesis values as selected values rather than reparsing reporting argv. Missing/foreign source, Registry/configuration, binding or required literal/output geometry declines definition-removal advice. drop_def_elims_resurrected_by_replacements excludes same atomic-group replacements from resurrection; a declined or resurrected deletion withdraws its complete atomic group. This guard protects final source removal proposals only; lexical source advice grants no Native rewrite, variable cell, executed frame, compiler instruction entry or end-to-end optimiser emission result.

## Scope

Two marked fixed source/API controls exercise quoted/qualified/captured operands, genuine unknown/rebound target refusal, unrelated replacement, and missing/foreign source/configuration/Registry/carrier refusal. Atomic group handling is part of the current owner contract. The manufactured proposals test this final safety gate independently of complete optimiser production. All seven providers are not tested; actual Rust receipts remain separate.
