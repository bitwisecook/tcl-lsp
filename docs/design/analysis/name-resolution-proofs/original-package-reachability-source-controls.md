## Problem statement

Nominal if, return and package spellings can prune or publish package-index paths even when those commands select custom handlers. Running interpreter release is also distinct from the current Tcl package provision.

## Question

How can package-index source reachability use authentic selected control schemas while retaining unknown paths and current-loader uncertainty?

## Conclusion

Original package entries analyse the actual complete loader source under its full configuration, retained context and Registry. The scanner consumes common original source schemas, exact written origins and selected package-registration hooks. Literal boolean branches and completion routes prune only under independently closed selected source lookup and operand-effect premises. Custom handlers cannot borrow builtin body or termination roles. Conditional applicability, unknown commands, unsupported body geometry and version-dependent guards remain Undecidable. Version guards do not infer current package provision from the interpreter release. Filenames remain separate advisory candidates and no package loading, registration or Normal grant is supplied.

## Scope
