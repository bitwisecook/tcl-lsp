# naming.variable.registry-event-frame-identity

Kind: `implementation-contract`

## Problem statement

An internal procedure label resembling an event can manufacture an iRules frame when a consumer reconstructs policy from its spelling. A memo without the selected event body can also reuse an unrelated procedure entry.

## Question

Which source producer selects an iRules event frame, and can a function label or Registry profile supply that producer?

## Conclusion

Only the actual Registry-selected lowering of an event declaration retains the conditional event body. The descriptor owns the original body, full source/configuration and Registry content; procedure mapping checks all of those before applying its frame policy. The lattice key retains that complete original descriptor independently of normalized body geometry, and a cache miss checks the actual body/configuration and Registry before applying conditional entry. Ordinary function labels cannot select event or hosted storage policy. Cross-event summaries read the retained event identity, and variable diagnostics consume the actual point contexts. The descriptor supplies no reached event, worker, initialization epoch, Normal completion, current value or RULE_INIT broadcast agreement.

## Scope

Rust implementation contract for conditional source event frames, exact current lowering ownership, function-unit transport and cross-event source analysis. This does not replace independently supplied WorkerExecution, physical variable bindings, observer/lifetime closure or measured appliance publication questions.
