# naming.proof-records.exact-evidence-and-coverage

Kind: `implementation-contract`

## Problem statement

A retained native result can be silently detached from changed source bytes, a missing JSON row, another test function or an incomplete capture inventory. Treating a structurally valid subset as complete would conceal unreviewed native questions. The proof consumer needs to distinguish exact retained evidence from an output assertion or coverage claim borrowed from another owner.

## Question

Does the proof gate reject changed evidence, missing row selectors, escaping paths, adjacent-function comment donation, unindexed pages/test annotations, suppressed JSON candidate flags, source inspection borrowing execution or another provider, and pending capture coverage while keeping structural audit distinct from complete certification?

## Conclusion

The gate checks complete file digests and selected rows, repository-contained paths, exact question/document/provider bindings and the current corpus census. Every proof page and explicitly marked Rust question requires an indexed record. A retained JSON capture cannot escape review by clearing its candidate flag. Source inspections require an inspected answer with that provider's pinned excerpt and cannot issue a guest execution answer. Pending capture review and unlinked tests fail complete certification. Structural audit neither executes a native probe nor certifies completed coverage. Pinned source line ranges count LF separators only and preserve embedded form-feed and carriage-return bytes, including CRLF. A final unterminated line remains addressable without adding an empty line after a terminal LF.

## Scope

Python proof-consumer implementation contract. The fixed synthetic controls exercise validator rejection paths; they do not constitute C Tcl, Jim or BIG-IP language observations.
