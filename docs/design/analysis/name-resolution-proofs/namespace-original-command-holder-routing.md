# naming.namespace.original-command-holder-routing

Kind: `native-observation`

## Problem statement

Equal displayed namespace paths do not establish current command routing or survival after namespace deletion/recreation. Procedure definitions, synchronous delete callbacks, TclOO calls and C alias publication have distinct original entry purposes; a combined eval/catch envelope can change the source channel.

## Question

What exact public completion and separate query results do the five original namespace deletion/recreation, callback-created/replaced procedure, TclOO replacement and relative/rooted C alias controls produce under independent external API evaluations?

## Conclusion

Thirty external API case processes exit zero with empty stderr, and six independent C driver compilations exit zero. Each fresh control preserves its exact independent prelude, original source and optional query; guest completion codes are distinct from process exit. C8.4.20/C8.5.19 deferred-original return code one with invalid command name r; C8.6.18/C9.0.4/C9.1.0 return code zero and the exact nested result {R {} ::N::r 1 {can't create procedure "::N::s": unknown namespace} {} 0} {} 0. C8.4/C8.5 TclOO original calls return code one with invalid command name oo::class; C8.6+/C9 return code zero with OLD {} NEW. All five C releases complete the independent synchronous-create and synchronous-replace sources and later queries with code zero. Their exact log orders differ: C8.4/C8.5 creation ends one ten with zz earlier, while C8.6+/C9 creation ends one ten zz; replacement likewise reports its last two earlier on C8.4/C8.5 and last on C8.6+/C9. These are the exact finite callback observations, not a universal traversal law. All five C alias controls return code zero with {0 q::relative 0 ::AliasHolder::q::rooted 0 RELATIVE 0 ROOTED 1} 1 ::AliasHolder::q::rooted: both measured inner calls succeed and the final command query reports only the rooted name. Jim 0.84-9-g5bac7c9 reports code one for both deferred controls at unavailable namespace exists, code one for the TclOO spelling oo::class, and code one for both synchronous originals at trace; its independent preludes return rec and final log queries return the empty value. No Jim C alias branch result or teardown parity is inferred from the terminal error. Original version/completion/query hex rows remain authoritative. BIG-IP is not tested. Display names, returned values and source requests supply no private namespace token, allocation/lifetime generation, command-table/dispatcher identity, bytecode engine uniformity, Native compiler admission, arbitrary callback law, successful Rust result or edit authority.

Two marked default Runtime fixtures bind the exact callback log and OLD/empty-query/NEW public tuple to the shared namespace deletion owner.
