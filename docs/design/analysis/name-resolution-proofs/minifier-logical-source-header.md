# naming.minifier.logical-source-header

Kind: `implementation-contract`

## Problem statement

A heterogeneous Registry cannot select a default Native engine for an independently retained Logical editing input; execution lookup without a Native name issuer also cannot replace original pre-operand authored metadata.

## Question

Can Logical minifier role selection retain the actual complete editing input and independently select source metadata without manufacturing Native lookup?

## Conclusion

The Logical Realm ingress uses the actual retained profile and full configuration with the document driver file protocol, without the heterogeneous catalogue default Native engine. Source-header advice meets genuine original pre-operand observations of the complete static ASCII argv against the unchanged authored table. All matching original occurrences must select the same Registry target without a prefix, uncertainty or absence. The retained full ContextRegistry then selects its canonical source schema. The runtime lookup remains independently unknown; no Native input, name recipe, dispatch or completion is filled.

## Scope

Explicit Logical authoring advice only. The immutable Realm must retain the exact full editing input and current source image/configuration. Native, hosted and explicit execution-entry paths remain separate. Dynamic or opaque argv, unknown entry or earlier mutation, known shadows, deletion, alias prefixes and inconsistent observations abstain. This supplies authored metadata, not Native lookup, installed command identity, body entry, compiler admission, effects, Normal, storage or runtime rewrite equivalence.
