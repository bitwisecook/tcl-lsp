## Problem statement

A generated test can turn command labels and hypothetical source paths into outcome assertions, infer appliance worker behavior from static variable text, or create source setup objects from a guessed runtime value.

## Question

Does the iRule scaffold keep authentic event/source candidates separate from independently observed outcomes and worker/evaluation premises?

## Conclusion

The generator captures one OriginalIrulesSourceContext under the explicitly selected source ingress and supplied immutable store. Actual SourceIrulesEventBody descriptors supply event labels; the same guarded source closure supplies source command cards and supported literal object-reference candidates. Original variable-token labels and possible multi-TMM source patterns remain setup/review suggestions, without current cell or appliance execution authority. Generated action and template assertions remain comments requiring independently observed expectations; original user source is retained as one authored Tcl list element and is not rewritten by assertion annotation. The wire output states conditional-source analysis, unverified outcomes and separate handler, event and observed-outcome obligations. Configuration setup words use the common inert list-element renderer. The tool supplies a source scaffold and review questions, without functional equivalence, traffic effects, per-worker state, runtime binding, Normal or a behavioral test oracle.

## Scope

Fixed controls distinguish actual source candidates from custom event-handler barriers, retain source object cards, prevent predicted outcome assertions and keep multiline action labels inert.
