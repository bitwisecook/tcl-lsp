# naming.variable.original-eval-container-storage-columns

Kind: `native-observation`

## Problem statement

The retained storage expectations describe ten exact public array/scalar, alias and dictionary-mapping specimens. Complete isolated native process receipts are required to distinguish these fixed output columns from an independently failing Runtime implementation or a different source envelope.

## Question

What do the six pinned providers return for all ten original variable-container specimens in their exact isolated puts-[eval]-source-file envelope, and do these captured rows match the existing expectation columns byte for byte?

## Conclusion

All sixty independent provider/case processes exit zero with empty stderr, and every whole stdout equals its corresponding existing expectation row plus LF byte for byte. C8.4/C8.5/C8.6/C9.0/C9.1 refuse scalar read/write of arrays and element writes to scalar values in the exact caught controls; Jim returns its distinct dictionary-value tuples. All ten indexed rows are retained for every provider. In case 8, C8.4 takes the guarded UNAVAILABLE branch; C8.5+ returns 1 NEW 0 1 {can't read "blocked": variable is array}, with the first mapped target advanced and the body unentered. Jim returns 0 NEW 1 0 OTHER with a normal update, entered body and scalar-readable second destination. These actual captures reconfirm the unchanged existing C and Jim columns. Source187 and paired188 remain separate exact-input observations. BIG-IP is not tested. A public tuple establishes neither private array/scalar representation nor a native bytecode/input-object/cache/header/frame-storage mechanism, Runtime parity, successful Compiler admission or edits.

## Scope

Ten original fixed ASCII LF programs use puts [eval {<exact script>}] and run in sixty separate fresh provider processes. The request identifies each exact case index/source SHA and the original variable_container_scripts source-owner digest. An immutable exact matching owner snapshot and unchanged expectation columns are retained alongside every original input, receipt, whole stdout/stderr and aggregate capture-summary log. Versions are associated through the independently captured source187 version receipts and the same exact executable/artifact/environment associations; no case process prints its own version. No raw/counting NUL, non-ASCII, continuation or control escape is exercised. Source/library/header/build pins are associations, not independently established compiled-source explanations. Dictionary absence is scoped to captured stock C8.4 and that guarded branch. Actual Rust compilation and assertion outcomes remain separate; no frame/object/header/argv identity, broad semantic equivalence, generic storage algorithm or edit authority follows.
