# naming.source.original-command-name-publications

Kind: `implementation-contract`

## Problem statement

Source consumers can confuse an authored future command naming layout with successful creation, publish a permanent display-name set, or select a factory class by splitting substitution text and looking up its printed head. Captured prefixes, option widths, renames and shadows make those reconstructions drift.

## Question

Which shared source interfaces preserve the exact original command/variable naming operands and selected factory schema without claiming creation or life?

## Conclusion

Registry authored_source_command_publication owns exact effective naming positions, selected member offsets, declared option widths and terminators. Unknown controls, expansion cardinality and optional factory naming/control layouts decline. Mandatory factory names can describe a class label even when the descriptor has no modelled methods. Compiler seals the selected original argv, full context/source applicability, genuine whole naming word, optional Native input and exact source-produced units. Source handle-class advice joins a genuine setter layout to its exact single constructor substitution through that same source owner. Generic defined-command naming metadata never writes a permanent successful-creation set. Actual command publication and lifetime remain with the shared command binding state. Compatibility class labels are source presentations and do not grant entered dispatch, allocation, variable contents, Native admission, completion, lifetime or rename authority.

## Scope

Compiler source naming and source class presentation. Mandatory factory naming layouts only; optional constructor names and control grammars need an explicit Registry recipe and do not receive a nominal fallback. This is a Rust contract.
