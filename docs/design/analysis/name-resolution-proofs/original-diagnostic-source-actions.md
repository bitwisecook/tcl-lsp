# naming.consumer.original-diagnostic-source-actions

Kind: `implementation-contract`

## Problem statement

Diagnostic prose is presentation. Extracting a variable, sink or helper occupancy from its text can edit a different source read, treat a comment as a declaration, overwrite an occupied helper or reuse a warning after its source/configuration/Registry changes.

## Question

Which original producer subject, current source geometry and selected metadata must agree before a diagnostic-driven taint or collection-bootstrap source action is offered?

## Conclusion

Compiler warnings retain optional complete SourceImage, full LexerConfig and immutable RegistrySnapshot together with original taint variable/sink fields. A bounded process-local handle reselects the actual warning; message text cannot construct the subject. Core independently checks code, exact diagnostic range, whole image/channel/configuration and both current Registry readers before selecting the original sink and source read. Shared source command metadata retains actual whole words, complete written origins, arity and catalogue barriers. A source hardening action validates its separately issued typed sink/read; complete roles for unrelated operands are not this action purpose. Generated helper names are checked against retained declarations, including braced names, while comments carry no occupancy. Collection bootstrap uses actual selected handler/payload metadata and an authentic top-level parsed handler boundary. The selected subst option hardening uses current written head and declared option geometry; other Native rewrites decline absent independent evaluation/insertion permission. Authored vendor and explicit Logical source hardening retain their separate source-advice purpose. No current runtime cell, Normal, handler effect, transformed-program equivalence or native allocation is issued. Shared vendor source selection authenticates the complete original NativeWord vector and site; preceding-comment and other reporting trivia cannot become word identity. Removing a genuine word still withdraws the source candidate. source_action_spec requires actual input, matching command-store semantic key and availability_context.resolve_spec for event/bootstrap/taint/helper metadata. Reporting dialect/catalogue profile cannot donate availability. SourceIrulesEventBody retains the genuine complete event operand from selected rule declaration/Registry event position; IRULE1005 anchors that operand rather than the first body statement. Missing image/configuration/Registry/event geometry refuses, without Native event activation or TMM lifecycle. Current Logical source command/helper projection requires positive actual input and resolves metadata through its retained availability. Required-profile metadata uses source_action_spec under that same actual context; no copied advice flag or catalogue profile repairs missing ingress. Positive retained Logical current_commands traversal uses the actual analysis source/body owner and actual ContextRegistry availability. Under the same custom catalogue, C8.4 availability withholds the gated nested body while C9 admits its genuine complete source commands; selected ReferenceOnly scripts stay outside this traversal. Missing input and changed full source decline. These are source-command extents, without sink fabrication, reached effects, Native Normal completion or edit admission.

## Scope

Current Compiler warning transport, Core context source actions and Server diagnostic publication/request lifting. Fixed controls use actual source-produced warnings, altered presentation, missing/forged handles, moved ranges, stale full source, changed configuration/Registry, comment versus braced helper declarations, nested-handler boundaries and unsupported Native wrapper authority. Authored F5 context controls are Rust model assertions, not appliance observations. No passing Rust receipt is attached. Explicit lexical helper authoring checks the emitted root procedure/class publication rather than unrelated reporting tails; it supplies no Native cell, availability or edit-equivalence receipt.
