# naming.tcloo.original-configuration-allocation-join-contract

Kind: `implementation-contract`

## Problem statement

Two original class names can share a reporting label, and renaming a class changes its public slot while preserving its implementation allocation. An OO extension joined by a display QName can therefore update the wrong class, lose a moved class, or promote an alias or ordinary object into a class. The configuration target and its own member delta need independent provenance.

## Question

Does original OO configuration metadata retain its actual target operand and point, join local class metadata by the full implementation allocation site, and keep receiver sides and unresolved targets separate?

## Conclusion

The shared target issuer requires the original full command vector, Registry-selected configuration operand and axis, unanimous reaching rows, and independent operand-effect closure. A local member/relation delta joins original creation metadata only by its full allocation site. Proven local absence remains an external obligation. Aliases and unowned computed targets cannot supply a class join; unowned targets withdraw effective own views while birth declarations survive. These records supply source metadata, not entered worker behavior, manufacture, native compiler permission or call-point temporal MRO.

## Scope

Current Compiler implementation contract for static original OO configuration operands and unchanged literal bodies or inline members. The named regressions distinguish opaque surrogate-unit class names, moved source allocations, external target obligations, aliases/computed targets and instance versus class-object tables. No native execution or Rust test outcome is claimed. Computed body mapping and later dispatch currency remain independent obligations.
