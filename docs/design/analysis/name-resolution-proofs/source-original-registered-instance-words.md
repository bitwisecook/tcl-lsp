# naming.source.original-registered-instance-words

Kind: `implementation-contract`

## Problem statement

Instance diagnostics can inverse-resolve a reporting class label into a nominal method table, losing the actual factory, original naming operand, setter RHS and source-order aliases or moves. Those report facts cannot establish a current runtime instance or original written method argv.

## Question

Can readonly instance diagnostics retain the actual original Registry factory, setter and method source ownership without inverse reporting-name lookup or runtime grants?

## Conclusion

OriginalSourceRegisteredInstance retains a genuinely selected mandatory named Registry factory, complete original factory vector, unchanged naming input and source slot. OriginalSourceRegisteredHandleBinding additionally owns a complete selected scalar setter and its original single-command written RHS construction; an RHS captured in an alias prefix cannot issue a new setter-time construction. OriginalSourceRegisteredInstanceWords retains the later complete effective method vector, actual alias prefix/lineage, whole source/input/configuration and immutable ContextRegistry/Registry correspondence. Shared descriptor method, abbreviation, lifecycle, arity and option relationship queries use that same owned factory descriptor. Logical deferred source bodies retain their independently selected parent. Known replacements, deletion, alias loops, dynamic names, missing namespaces and stale handles refuse. Unknown source widening retains the genuine original registered factory/name/vector only conditionally with UnknownEarlierMutation and UnavailableActualLookup obligations. It clears private symbolic setter-handle bindings, so an instance name cannot restore the lost stored-handle advice or establish current widget existence. Opaque, NUL-containing and expanded selectors have no source keyword projection. Widget diagnostics and Core transport retain exact factory identity and typed method/count/relationship purpose with explicit applicability obligations. These source receipts supply no factory/setter execution, successful construction, runtime object/cell/value, entered receiver/frame, Native admission, Normal completion or edit authority. argument_input retains each genuine effective argument producer in its independently selected SourceAdviceNameInput domain. A Native-only prefix consumer must obtain native_input from that same producer; Logical or hosted advice does not inherit a Native name channel. AdviceGraph::instance_key uses the selected Registry naming layout for conditional candidates. Jim candidates delegate the shared command_lookup_slot under the retained source root, including counted non-ASCII units and root comparison. C/Logical candidates retain centrally bounded ASCII authored geometry; unsupported units refuse the source receipt. This candidate comparison does not assert a generic factory native publication protocol, successful construction or current instance.

## Scope

Marked C8.6 source controls cover actual Registry descriptor ownership, method prefixes and foreign descriptor refusal; factory/method alias and move lineage with exact original vectors and stale/partial-vector withdrawal; original scalar setter/RHS with independent applicability; replacement, deletion, dynamic factory naming, stale handle and captured RHS refusal, plus conditional unknown-mutation factory retention with stored-handle withdrawal; bare/handle widget method warnings, too-many/too-few method count advice, and message-independent Core transport. Expanded method argv retains no exact count or method keyword. Optional factory-control layouts and native deferred procedure bodies require independent issuers. These controls do not prove package loading, display connection, native constructor dispatch or widget existence.
