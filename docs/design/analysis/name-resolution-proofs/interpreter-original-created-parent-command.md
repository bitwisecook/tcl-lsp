# naming.interpreter.original-created-parent-command

Kind: `native-observation`

## Problem statement

A source model can omit the parent command installed by child interpreter creation, or treat a path and handle spelling as different evaluation capabilities. Native command inventory and caught completion results are needed to bound that source model without inventing runtime token identity.

## Question

Does the exact interp create s install a parent command, do the handle and path evaluation forms propagate the two caught return/value completions, and does deletion remove that command under each retained provider?

## Conclusion

All five C releases create the parent command s, both evaluation forms produce ok for the two fixed controls, and successful deletion leaves no s command. Current Jim rejects the tested create/eval/delete forms and has no s command; its missing-handle results establish no child execution.

The secondary linked source recipe retains original creation and parent-command/body word correspondence under the same complete input/image/config and ordered source transitions. Known delete/move/shadow, unknown table mutation, alias indirection and incomplete/substituted body layouts withhold it.
