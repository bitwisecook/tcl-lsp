# naming.consumer.original-rule-reference-candidates

Kind: `implementation-contract`

## Problem statement

A report that recognises call from a displayed command and splits its first displayed argument can invent a rule reference after handler shadowing, misread -debug as the target, lose authentic source configuration or fabricate a partition owner for a relative spelling.

## Question

Does a readonly cross-rule report candidate require the actual guarded hosted command vector, selected authored user-procedure schema and option ordinal, while retaining rule spelling separately from independent configuration ownership?

## Conclusion

The Registry selects the target ordinal from the actual authored INVOKES_USER_PROC schema, complete non-expanded source cardinality and selected option grammar. Vendor source metadata retains that ordinal with the original vector, complete context and Registry identity. The report requires complete current source/configuration and matching actual ContextRegistry, stamps only authentic source tokens through the retained Realm, and uses the shared conditional vendor metadata issuer; occupied custom handlers and tombstones cannot donate catalogue metadata. It reads only supported original literal source units at the selected ordinal. RuleProcedureTarget owns the rule/procedure spelling split; relative spellings remain relative and no partition or rule owner is manufactured. Equal written rule candidates are deduplicated only as report strings. Missing source owners, unknown target units/cardinality, malformed targets and unsupported Native policy produce no candidate. The returned spelling requires the report caller's independent configuration-object resolution and supplies no native dispatch, entered frame, successful call, complete reference coverage or edit permission.

## Scope

Current Diagram proc_call_refs and proc_call_refs_for_analysis, Registry source operand selection, Compiler vendor schema transport and pure shared RuleProcedureTarget spelling projection. Fixed assertions cover actual optional -debug, dynamic value arguments versus expanded cardinality, supported relative/absolute candidates, malformed/local targets, changed complete source/configuration/context, cleared reporting labels and occupied custom handler refusal. Pool/node/snatpool attachment shape propagation remains a separate purpose and is not established by this contract. No native observation or Rust execution receipt is attached.
