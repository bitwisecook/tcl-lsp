Command Registry — Spec Studio

Browse the tcl-registry command surface, edit every field of a CommandSpec, and export the whole pack as drop-in registry .rs files and a Tcl dialect stub. Import a package's own Tcl and the compiler will infer a starting signature for each proc it finds.

🔒
Everything runs entirely in your browser. The command registry, the Tcl compiler's analyser, both renderers, and the Tcl language server itself are compiled to WebAssembly and served from this page's own directory. Nothing you type or import is uploaded — no server, no API, no telemetry. Once this page has loaded you can go offline and it still works.
One opt-in exception. The Fetch releases from GitHub panel on the Import a package tab — and only that panel — talks to the network: it reads tags from api.github.com and downloads release archives from codeload.github.com, directly from your browser, unauthenticated, and only when you fill it in and press the button. Every other way of getting sources in (drop files, pick a directory, upload .zip archives) is offline. If you would rather the page never reach the network at all, use the .zip upload path instead.
Opening a GitHub issue is the other action that leaves the page, and it is a link you click: the issue form opens pre-filled in a new tab so you can read it before posting.

      Drop a package's .tcl files here, or point at a whole library directory. Each file is compiled with the real analyser — the same one the language server runs — and every proc it finds becomes a draft spec: arity and argument roles from how the body uses each parameter, plus the shape heuristics that read the body itself — option tables from -* dispatch, -- handling, mode words that become subcommands, closed value sets, and callbacks with their appended arity. Every conclusion comes with the evidence behind it.

      Add one .zip per release — GitHub's Download ZIP of a tag, a release asset, or anything else containing the package's sources. Each archive gets a version label (guessed from the file name, and editable: the labels are what every range is derived from). The importer then drafts each release independently and diffs them, so introduced_version and retired_version come from releases that actually witness the change rather than from the newest snapshot's own version number. Nothing is uploaded — the archives are unpacked in this page.
