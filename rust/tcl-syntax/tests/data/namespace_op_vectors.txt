# Namespace-operation conformance vectors — the shared ground truth for the
# operations that *build* the namespace tree, as opposed to resolving against
# it (that is command_resolution_vectors.txt and variable_resolution_vectors.txt).
#
# Format (pipe-separated; `-` = empty column; `#` starts a comment line):
#   current-namespace | setup ops | probe | expected per release
#
# current-namespace  ::-rooted; the probe runs inside `namespace eval <ns>`
#                    (or at script level when it is `::`).
# setup ops          comma-separated mini-ops, run at script level in order:
#                      ns(NS)               namespace eval NS {}
#                      delns(NS)            namespace delete NS
#                      proc(NAME=RESULT)    proc NAME {args} {return {RESULT}}
#                      rename(OLD NEW)      rename OLD NEW
#                      export(NS ARGS)      namespace eval NS {namespace export ARGS}
#                      import(NS ARGS)      namespace eval NS {namespace import ARGS}
#                      forget(NS ARGS)      namespace eval NS {namespace forget ARGS}
#                      path(NS ENTRIES)     namespace eval NS {namespace path [list ENTRIES]}
#                      unknown(NS HANDLER)  namespace eval NS {namespace unknown HANDLER}
#                      var(NAME=VALUE)      set NAME {VALUE}
#                      eval(SCRIPT)         SCRIPT verbatim (escape hatch; commented)
#                    Commas inside parentheses do not split; parentheses nest.
# probe              which NAME | whichvar NAME | origin NAME | current |
#                    parent ?NS? | nsexists NS | children ?NS? ?PATTERN? |
#                    commands PATTERN | vars PATTERN | globals PATTERN |
#                    exports | path | qualifiers TEXT | tail TEXT |
#                    autoqualify CMD NS | read NAME | call TEXT
#                    `children`, `commands`, and `vars` are wrapped in `lsort`
#                    so the row is order-independent; `call` is evaluated as
#                    written.
# expected           the two-element Tcl list `<catch code> <result-or-message>`.
#                    A single value means every modelled release agrees; a
#                    `RANGE=VALUE;RANGE=VALUE` list gives the columns per
#                    release over the ladder 8.4, 8.5, 8.6, 9.0, 9.1 (`9.0+` =
#                    9.0 and later).  The entries must cover the whole ladder.
#
# The whole row — setup included — runs inside one `catch`, so a row that uses
# an 8.5+ subcommand (`namespace path`, `namespace unknown`) states 8.4's real
# `bad option` text as its 8.4 column rather than being excluded.  That text is
# 8.4's own subcommand table (generic/tclNamesp.c, Tcl 8.4.20), pinned by
# tmp/tcl8.4.20/tests/namespace.test lines 857 and 964.
#
# `tcl_syntax::ns_op_conformance::vector_script` renders each row as that
# script; `tests/namespace_op_conformance.rs` runs every row against every real
# tclsh the machine has (TCL_LSP_TCLSH84/85/86/90/91, else PATH probes) and
# asserts that release's own column, skipping loudly for a release with no
# binary.
#
# Pinned live on 8.4.20, 8.5.19, 8.6.14, 9.0.4, and 9.1b0 (2026-08-26): every
# row below was run against all five interpreters and states each release's own
# answer.
#
# C references: generic/tclNamesp.c (Tcl 9.0.4, 8.6.16, 8.4.20).  Rows are
# transcribed from the C suites under tmp/; each group names its source tests.
#
# documented-non-conformance
#   Behaviours deliberately excluded because the C suite itself marks them
#   broken — do not "fix" our model to match them:
#   * namespace-56.4 (knownBug, Tcl bug 16fe1b5807): a namespace literally
#     named `:` with `namespace ensemble create` cannot be dispatched as `: p1`.
#     The colon-run rules that *do* hold are the rows below plus the lone-colon
#     rows of command_resolution_vectors.txt.
#   * info-15.8 (knownBug): `info procs` does not consistently report a global
#     proc shadowed by a namespace proc.  Our `commands` probes only ever ask
#     about fully-qualified patterns, which is the part that does hold.
#   * interp-27.5 .. 27.8 (knownBug): `interp alias` targets carrying `::`.
#     Alias binding belongs to the command_binding domain (P1a) in any case.
#   * namespace-51.13: the 9.0 delta where a namespace being deleted is still
#     visible to its own command-delete trace.  It observes a mid-teardown
#     interpreter state, which is not a resolution rule we intend to model.
