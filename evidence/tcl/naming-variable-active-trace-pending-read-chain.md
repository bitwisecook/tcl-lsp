# Tcl execution evidence

## Question

> A generic variable operand can be an original plain, qualified, indexed or generated byte object. During pending earlier read registration retirement after destruction, native lookup, callbacks or reporting may change which receiver is selected; command success and a later original-name read are separate observations.

> pending earlier read registration retirement after destruction Which exact completion/result and later original-name observation are returned by the retained scripts?

## Assumptions

Assumptions were not separately recorded in the retained capture.

Recorded scope and limits:

> Only the listed fixed scripts and recorded provider builds; ASCII source character input produces the queried native objects. Binary/decomposed names are generated values, not raw document bytes. BIG-IP, physical object headers, compiler opcode selection and arbitrary observer/alias closure are excluded.

## Script

```tcl-visible
set events {}; set v OLD
proc later {n k op} {lappend ::events later-$op}
proc kill {n k op} {lappend ::events kill-$op; if {$op eq "read"} {uplevel 1 {unset v; set v NEW}}}
trace add variable v read later
trace add variable v {read unset} kill
set h lappend
set answer [$h v EXTRA]
set summary [list $answer [set v] $events [trace info variable v]]
puts $summary
set summary
```
